# Spoonfeeder2 仕様

## 目的

AIチャットへ添付する、リポジトリ単位の参照コンテキストを作成する。関数単位のASTスタブコンテキストは作成しない。

## コンテキスト

- 選択されたテキストファイルと、ignored項目を除くリポジトリ構造をXML形式で出力する。
- ファイルパス等のXML属性はエスケープし、日本語・空白・`&`を含むファイル名も構造と本文へ正しく収録する。
- 依頼内容は含めない。利用者は `repository_context.txt` を添付し、チャット本文へ依頼を書く。
- PythonとC#の文字列内にある物理改行は `\n` に変換する。Python docstringの改行は維持する。
- GitリポジトリではGit自身のignore判定を使用する。ignoredディレクトリ内部は走査しない。
- ignored項目表示を有効にした場合も、無視された入口だけを取り消し線で表示する。
- ファイルプレビューはPython/C#などをVS Code風にシンタックスハイライトし、Markdown（`.md`）は見出し・表・リスト・引用・コードブロック等をレンダリングして表示する。プレビューは`Esc`で閉じる。
- プレビュー上部に自動フォーカスされる検索欄を表示し、ファイルを開いた直後から入力できる。検索語をハイライトし、`Enter`/`Shift+Enter`で次・前の一致へ移動し、大文字小文字・単語単位・正規表現を切り替えられる。
- ハンバーガー設定の「無視リストを編集」から、現在のリポジトリ設定（`.spoonfeeder.json` または `.ignore_context`）をモーダルで編集・保存できる。
- ファイル・フォルダの右クリックから無視リストへ追加でき、ignored表示中の項目は右クリックで無視リストから除外できる。Gitの`.gitignore`自体はこの画面から変更しない。
- 通常Pythonモードでは、メインリポジトリで選択中の`.py`／`.cs`から実際に利用される外部ソースモジュールを解析し、読み取り専用の「参照ライブラリ」ツリーへ表示する。
- Pythonはメインリポジトリの`.venv`／`venv`、`VIRTUAL_ENV`、`PYTHONPATH`、実行Pythonの`sys.path`、`.pth`／editable installの順に参照先を解決する。標準ライブラリおよび通常の`site-packages`へ到達した場合は追跡を終了する。
- Pythonの外部ソースリポジトリ内では、使用中モジュールから利用されるモジュールを再帰的に追跡する。未使用のimportは含めない。
- C#は`.csproj`の`ProjectReference`、環境変数を含む参照パス、`.sln`を解析し、選択コードで利用されている型を定義する`.cs`だけを表示する。
- 自動解決できない場合は処理を止めず、ファイルの右クリックメニュー「対象リポジトリを追加」から未解決モジュールと外部リポジトリを対応付ける。手動対応はメインリポジトリ単位で一元設定へ保存する。
- Embedded Pythonモードでは参照リポジトリの自動解析、手動追加、ツリー表示をすべて無効にする。
- 参照リポジトリは常に読み取り専用とし、コード反映、テスト、ターミナルの対象はメインリポジトリだけとする。
- コンテキストでは`main_repository`と`reference_repositories`を分離し、参照側には検出・選択された`.py`／`.cs`の構造と全文だけを収録する。Markdownなどの文書ファイルは参照側へ含めない。

## コード反映

単一の入力欄で次の形式を自動判定し、差分確認後に反映する。

1. 関数・メソッド・クラス全体（Python `class`、C# `class` / `interface` / `struct` / `record`）
2. ファイルパス付きコードブロック
3. `<file_changes>` による複数ファイル変更

AIが出力したコード内の文字列リテラル（シングル/ダブルクォート）に物理改行（`\n`, `\r\n`）が含まれる場合、`\n` へ自動エスケープして構文エラー（`SyntaxError`）を防ぎつつ関数・クラスを抽出する。docstring等のトリプルクォート内の物理改行は維持する。
コードブロックに言語指定（`python` / `csharp`）がない場合や素のテキスト貼り付け時は、Python（関数・クラス）を最優先で自動検出し、該当しない場合にC#を試行する。C#のコード反映時は ````csharp ```` コードブロック指定を推奨する。

ファイル名がなくても、Python関数/クラスまたはC#メソッド/クラスがリポジトリ内で一意なら自動特定する。複数候補がある場合はエラーで終了せず、候補を利用者へ提示する。新規シンボルも既存ファイル構成から推測し、確定できない場合だけ候補を提示する。

複数ファイル反映は事前に全変更を構築し、同時反映を直列化して一時ファイルから原子的に置換する。書き込み途中で失敗した場合は変更前のバイト列へ戻す。既存ファイルのUTF-8 BOM、UTF-16、CP932およびCRLF/LF改行は維持する。

## 画面

- `/`: リポジトリ選択、ファイル選択、コンテキスト作成、コード反映、テスト、ターミナル
- リポジトリ選択: パス入力欄および履歴ドロップダウン（`▼`ボタン）。入力欄にパスが存在する場合でも、`▼`ボタンにより登録されている全リポジトリ履歴を一覧表示して別リポジトリへ素早く切り替え可能。ドロップダウン上部に検索ボックスを備え、入力キーワードでリアルタイムに候補を絞り込み可能。日本語IME変換確定時のEnterによる誤決定を防止し、文字列確定後に`↑`/`↓`で候補選択・`Enter`で決定・自動ロードを実行。各項目右側の削除ボタンから不要な履歴を個別除外可能。
- Git差分コピー: リポジトリバー（REPOSITORY）の「Git差分コピー」ボタンをクリックすると、現在開いているリポジトリで設定されたGitコマンドを実行し、差分をクリップボードにコピーする。差分行数を含むトースト通知を表示する。差分がない場合はクリップボードを空にして差分なしの通知を行う。
- `/map`: Python/C#のファイル、型、関数・メソッド、import/using、呼び出し関係
- ハンバーガー設定: ignored表示、無視リスト編集、Python実行環境、Git差分コマンド（デフォルト: `git diff HEAD -- *.py`）。設定値はブラウザローカルストレージへ自動保存される。
- ファイル選択ツリー: フォーカス後に`↑`／`↓`で表示中の項目を移動し、ファイル上の`Enter`でチェックを切り替える。ファイル上の`Shift+Enter`で中身をプレビュー表示する。フォルダ上の`Enter`、`←`、`→`で開閉する。
- キーボード: `I`で無視リスト編集、`H`でショートカット説明、編集中の`Ctrl/Cmd+S`で保存終了、`Esc`で破棄終了、`Ctrl/Cmd+Z`・`Ctrl/Cmd+Shift+Z`で編集履歴を移動する。

ターミナルはxterm.jsと実PTYを使用する。macOS/Linuxではzshを優先し、プロンプト、ANSIカラー、Tab補完、履歴、矢印キー、対話コマンドを通常の端末と同様に扱う。WindowsではpywinptyによるConPTY/WinPTY（非同期スレッド＋キュー）を優先し、cmdまたはPowerShellへ接続する。Embedded Pythonモードでは、指定ディレクトリや親ディレクトリの `setenv.bat` / `setenv.sh` から環境変数をキャプチャ・マージし、`python_console.bat` が存在する場合は優先して起動する。

`start.sh`／`start.bat`は起動前に指定ポートの既存リスナーを終了する。ビルド済み`frontend/dist`がない場合はNode.jsでビルドし、Node.jsがない、またはビルドに失敗した場合はサーバーを不完全な状態で起動せず終了する。

## テスト実行

テスト実行はUI上のPython実行モード設定と連動する。

- **通常モード**: リポジトリ直下の `.venv` / `venv` / `env` を自動検出し、そのPythonでテストコマンドを実行する。仮想環境がなければシステムPythonにフォールバックする。
- **Embedded Pythonモード**: `embedded_python_dir` 内のPythonバイナリを優先使用する。`setenv.bat` / `setenv.sh` の差分環境変数をプロセスに適用する。
- フロントエンドのPatchPanel（テスト実行ボタン）は `python_mode` と `embedded_python_dir` をAPIに送信し、バックエンドの `resolve_test_command()` が環境に応じたPythonパスを解決する。

## 対応環境

- Python 3.10以上
- Windows、macOS、Linux
- Windows運用時はNode.js不要。`frontend/dist` のビルド済みファイルをFastAPIが配信する。
- Windowsでは`start.bat`がコンソールとPython入出力をUTF-8へ設定する。パス入力は`/`と`\`を受け付け、テスト出力はUTF-8またはCP932を判別する。
- ソースファイルはUTF-8（BOM付き含む）、UTF-16、CP932を読み込める。コード反映では元のBOM・文字コード・改行形式を保持する。
