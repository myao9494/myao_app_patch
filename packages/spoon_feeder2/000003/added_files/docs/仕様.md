# Spoonfeeder2 仕様

## 目的

AIチャットへ添付する、リポジトリ単位の参照コンテキストを作成する。関数単位のASTスタブコンテキストは作成しない。

## コンテキスト

- 選択されたテキストファイルと、ignored項目を除くリポジトリ構造をXML形式で出力する。
- ファイルパス等のXML属性はエスケープし、日本語・空白・`&`を含むファイル名も構造と本文へ正しく収録する。
- 依頼内容は含めない。利用者は `repository_context.txt` を添付し、チャット本文へ依頼を書く。
- PythonとC#の文字列内にある物理改行は `\n` に変換する。Python docstringの改行は維持する。
- GitリポジトリではGit自身のignore判定を使用する。ignoredディレクトリ内部は走査しない。
- ignored項目表示を有効にした場合も、無視された入口だけを取り消し線で表示する。
- ファイルプレビューはPython/C#などをVS Code風にシンタックスハイライトし、Markdown（`.md`）は見出し・表・リスト・引用・コードブロック等をレンダリングして表示する。プレビューは`Esc`で閉じる。
- プレビュー上部に自動フォーカスされる検索欄を表示し、ファイルを開いた直後から入力できる。検索語をハイライトし、`Enter`/`Shift+Enter`で次・前の一致へ移動し、大文字小文字・単語単位・正規表現を切り替えられる。
- ハンバーガー設定の「無視リストを編集」から、現在のリポジトリ設定（`.spoonfeeder.json` または `.ignore_context`）をモーダルで編集・保存できる。
- ファイル・フォルダの右クリックから無視リストへ追加でき、ignored表示中の項目は右クリックで無視リストから除外できる。Gitの`.gitignore`自体はこの画面から変更しない。
- 通常Pythonモードでは、メインリポジトリで選択中の`.py`／`.cs`から実際に利用される外部ソースモジュールを解析し、「参照ライブラリ」ツリーへ表示する。
- Pythonはメインリポジトリの`.venv`／`venv`、`VIRTUAL_ENV`、`PYTHONPATH`、コード内での`sys.path.append()`／`sys.path.insert()`、実行Pythonの`sys.path`、`.pth`／editable installの順に参照先を解決する。標準ライブラリおよび通常の`site-packages`（pipライブラリ）へ到達した場合は追跡を終了する。
- Pythonの外部ソースリポジトリ内では、使用中モジュールから利用されるモジュールを再帰的に追跡する。未使用のimportは含めない。
- C#は`.csproj`の`ProjectReference`、環境変数を含む参照パス、`.sln`を解析し、選択コードで利用されている型を定義する`.cs`だけを表示する。
- 自動解決できない場合は処理を止めず、ファイルの右クリックメニュー「対象リポジトリを追加」から未解決モジュールと外部リポジトリを対応付ける。手動対応はメインリポジトリ単位で一元設定へ保存する。
- Embedded Pythonモードでは参照リポジトリの自動解析、手動追加、ツリー表示をすべて無効にする。
- コンテキスト作成横の「呼び出されているモジュールを含む」がONの場合、検出された外部リポジトリのファイル群をコンテキストへ収録する。Git管理されている外部リポジトリ（`common_lib`等）は編集可能対象としてAI指示文へ収録され、コード反映の対象にも拡張される。OFFの場合はメインリポジトリのみをコンテキストに含める。
- コンテキストでは`main_repository`と`reference_repositories`を分離し、参照側には検出・選択された`.py`／`.cs`の構造と全文だけを収録する。Markdownなどの文書ファイルは参照側へ含めない。

## MkDocsドキュメントリポジトリ対応

- リポジトリ内の `mkdocs.yml` または `mkdocs.yaml` を解析し、`site_name`・`nav`・`docs_dir`・`theme` 等の設定が含まれている場合にMkDocsドキュメントリポジトリとして自動判定する。UI上のモード切替ボタンから手動で「📚 MkDocsモード」と「💻 コードモード」を切り替えることもできる。
- MkDocsモードでは「リンク先MDを自動チェック」ボタンを押すと、選択中の `.md` ファイル内のMarkdownリンク `[...](...)`、Wikiリンク `[[...]]`、および `mkdocs.yml` の `nav` 構成を再帰的に解析し、同一リポジトリ内のリンク先 `.md` ファイルを自動選択する。
- 社内チャットツールの添付上限（最大5ファイル・1ファイルあたり約4.5MB制限・Vision機能あり）に対応するため、選択されたMarkdownから呼び出されている全画像（`![alt](path)` / `![[image.png]]`）を検出し、各図の上部に `【図X】 所属: docs/... | リンク記法: ...` のラベル帯を付加して1枚の縦長結合画像（`*_images.png`、4.5MB超過時は自動で `.jpg` 縮小圧縮）に結合する。
- 統合マークダウン（`*_context.md`）には元の画像リンク記法をそのまま維持して収録し、AIに対して「結合画像の図番号とリンク記法を照合すること」「修正出力時は画像リンク記法を改変・削除せず維持すること」「Spoonfeeder2で自動反映可能な `<file_changes>` または `path:` 付きコードブロック形式で出力すること」を指示する。
- 画面上で統合マークダウンと結合画像の両方をタブ切り替えでプレビューでき、指定した保存先フォルダへワンクリックで2ファイル（`*_context.md` と `*_images.png`/`.jpg`）を保存・フォルダ表示できる。

## コード・ドキュメント反映

単一の入力欄で次の形式を自動判定し、差分確認後に反映する。

1. 関数・メソッド・クラス全体（Python `class`、C# `class` / `interface` / `struct` / `record`）
2. ファイルパス付きコードブロック（Markdown文書内にネストされた ```` ```bash ```` 等のコードブロックを含む場合も内部フェンスを追跡して全文を保持）
3. `<file_changes>` による複数ファイル変更
4. 統合マークダウンのセクション見出し区切り（`# ===== [ファイル X/Y] docs/... =====`）

メインリポジトリに加え、`PYTHONPATH` やコード内 `sys.path` で指定されたGit管理下の外部ライブラリフォルダ（`common_lib`等）配下のファイルも安全な反映先として認識し、差分プレビュー生成とアトミックなパッチ適用を実行できる。

AIが出力したコード内の文字列リテラル（シングル/ダブルクォート）に物理改行（`\n`, `\r\n`）が含まれる場合、`\n` へ自動エスケープして構文エラー（`SyntaxError`）を防ぎつつ関数・クラスを抽出する。docstring等のトリプルクォート内の物理改行は維持する。
コードブロックに言語指定（`python` / `csharp`）がない場合や素のテキスト貼り付け時は、Python（関数・クラス）を最優先で自動検出し、該当しない場合にC#を試行する。C#のコード反映時は ````csharp ```` コードブロック指定を推奨する。

ファイル名がなくても、Python関数/クラスまたはC#メソッド/クラスがリポジトリ内で一意なら自動特定する。複数候補がある場合はエラーで終了せず、候補を利用者へ提示する。新規シンボルも既存ファイル構成から推測し、確定できない場合だけ候補を提示する。

新規シンボル追加時、Pythonファイル内に `if __name__ == "__main__":`（`'__main__'`含む）が存在する場合は、スクリプト実行ブロックを破壊しないようその直前（上）に空行を挟んで挿入する。存在しない場合は従来通りファイル末尾に追加する。
また、クラス内メソッドと同名のトップレベル関数が存在する場合や、過去の編集等で同名関数がファイル内に重複している場合でも、トップレベルの一致や最後の定義を優先して置換し、末尾への同名シンボル多重追加・重複増殖を防止する。

複数ファイル反映は事前に全変更を構築し、同時反映を直列化して一時ファイルから原子的に置換する。書き込み途中で失敗した場合は変更前のバイト列へ戻す。既存ファイルのUTF-8 BOM、UTF-16、CP932およびCRLF/LF改行は維持する。

## 画面

- `/`: リポジトリ選択、ファイル選択、コンテキスト作成（コードモード / MkDocsモード）、コード・ドキュメント反映、テスト、ターミナル
- ライブラリ／リンク先MD自動チェック: 「ファイルを選択」見出し横に配置。コードモード時は選択中ファイルから呼び出されている同一リポジトリ内モジュールをAST解析し、MkDocsモード時はリンク先 `.md` ファイルを再帰的に解析してチェックを自動付与する。
- MkDocs結合出力バー: MkDocsモード時に保存先フォルダ設定欄、「フォルダを開く」ボタン、「2ファイル保存（MD＋結合画像）」ボタン、および「📄 統合マークダウン」「🖼️ 結合画像プレビュー」タブを表示する。
- 呼び出されているモジュールを含む: コードモード時、「コンテキストを作成」ボタン左横にトグルチェックボックスを配置（デフォルト: ON）。外部ライブラリをコンテキストに含めるか切り替える。
- リポジトリ選択: パス入力欄および履歴ドロップダウン（`▼`ボタン）。入力欄にパスが存在する場合でも、`▼`ボタンにより登録されている全リポジトリ履歴を一覧表示して別リポジトリへ素早く切り替え可能。ドロップダウン上部に検索ボックスを備え、入力キーワードでリアルタイムに候補を絞り込み可能。日本語IME変換確定時のEnterによる誤決定を防止し、文字列確定後に`↑`/`↓`で候補選択・`Enter`で決定・自動ロードを実行。各項目右側の削除ボタンから不要な履歴を個別除外可能。
- Git差分コピー: リポジトリバー（REPOSITORY）の「Git差分コピー」ボタンをクリックすると、現在開いているリポジトリで設定されたGitコマンドを実行し、差分をクリップボードにコピーする。差分行数を含むトースト通知を表示する。差分がない場合はクリップボードを空にして差分なしの通知を行う。コマンドはシェルを介さず実行され、読み取り専用のgitサブコマンド（`diff` / `log` / `show` / `status` / `ls-files` / `rev-parse` / `blame` / `describe` / `shortlog`）だけを受け付ける（`--output` などは拒否）。`*.py` のようなパス指定はシェルではなくgitが解釈するため、サブフォルダ内のファイルも対象になる。コピーに失敗した場合（クリップボードの権限なし等）は画面上部のエラー欄に表示する。
- `/map`: Python/C#のファイル、型、関数・メソッド、import/using、呼び出し関係
- ハンバーガー設定: ignored表示、無視リスト編集、Python実行環境、Git差分コマンド（デフォルト: `git diff HEAD -- *.py`）。設定値はブラウザローカルストレージへ自動保存される。
- ファイル選択ツリー: フォーカス後に`↑`／`↓`で表示中の項目を移動し、ファイル上の`Enter`でチェックを切り替える。ファイル上の`Shift+Enter`で中身をプレビュー表示する。フォルダ上の`Enter`、`←`、`→`で開閉する。
- キーボード: `I`で無視リスト編集、`H`でショートカット説明、編集中の`Ctrl/Cmd+S`で保存終了、`Esc`で破棄終了、`Ctrl/Cmd+Z`・`Ctrl/Cmd+Shift+Z`で編集履歴を移動する。

ターミナルはxterm.jsと実PTYを使用する。macOS/Linuxではzshを優先し、プロンプト、ANSIカラー、Tab補完、履歴、矢印キー、対話コマンドを通常の端末と同様に扱う。PTYはシェルの制御端末として設定されるため、`Ctrl+C` で実行中のコマンドを中断でき、ジョブ制御も機能する。ターミナルを閉じる・再起動するときは、シェルとその子プロセス（ターミナルで起動したバックグラウンドジョブを含む）を停止し、プロセスを残さない。WindowsではpywinptyによるConPTY/WinPTY（非同期スレッド＋キュー）を優先し、cmdまたはPowerShellへ接続する。Embedded Pythonモードでは、指定ディレクトリや親ディレクトリの `setenv.bat` / `setenv.sh` から環境変数をキャプチャ・マージし、`python_console.bat` が存在する場合は優先して起動する。

`start.sh`／`start.bat`は起動前に指定ポートの既存リスナーを終了する。ビルド済み`frontend/dist`がない場合はNode.jsでビルドし、Node.jsがない、またはビルドに失敗した場合はサーバーを不完全な状態で起動せず終了する。

## テスト実行

テスト実行はUI上のPython実行モード設定と連動する。

- **通常モード**: リポジトリ直下の `.venv` / `venv` / `env` を自動検出し、そのPythonでテストコマンドを実行する。仮想環境がなければシステムPythonにフォールバックする。
- **Embedded Pythonモード**: `embedded_python_dir` 内のPythonバイナリを優先使用する。`setenv.bat` / `setenv.sh` の差分環境変数をプロセスに適用する。
- フロントエンドのPatchPanel（テスト実行ボタン）は `python_mode` と `embedded_python_dir` をAPIに送信し、バックエンドの `resolve_test_command()` が環境に応じたPythonパスを解決する。書き換え対象は `python` / `python3` / `pytest` で始まるコマンドだけで、それ以外（`npm test` 等）はそのまま実行する。
- タイムアウトは既定300秒（APIの `timeout_sec` で1〜3600秒）。超過時はテストプロセスとその子孫をまとめて終了し、失敗として返す。
- 失敗したテスト出力は「LLMへ戻す文面をコピー」でAIへの修正依頼文に変換できる。コピーに失敗した場合はエラー欄に表示する。

## セキュリティ

ブラウザからシェル実行・ファイル書き換えができるツールのため、既定でローカルのみに閉じる。認証機能はない。

- 待受アドレスの既定は `127.0.0.1`（`SPOONFEEDER_HOST`）。ローカルホスト以外を指定した場合だけLAN公開となり、信頼できるネットワークでのみ使うこと。
- Hostヘッダーを検証し、DNSリバインディング（攻撃者のドメインを `127.0.0.1` へ向けてAPIを呼ぶ手口）を拒否する。ローカルホスト待受では `localhost` / `127.0.0.1` / `[::1]` と `SPOONFEEDER_ALLOWED_HOSTS`（カンマ区切り）のみ許可し、他は403とする。
- ターミナルのWebSocketは、別サイトのページからの接続を拒否する（Originがローカルホスト以外）。LAN公開時は同一Hostからの接続のみ追加で許可し、他は `SPOONFEEDER_ALLOWED_ORIGINS`（カンマ区切り）で明示する。
- コード反映の書き込み先は、メインリポジトリと許可された外部ライブラリルートの内側に限る。AIが出力したパスにリポジトリ名の接頭辞が付いていても、リポジトリ直下に同名のフォルダがある場合は、そのフォルダ内のパスとして扱う。
- テストコマンドとターミナルは任意のコマンドを実行できる。これは意図した機能で、ローカル利用が前提である。

## 設定とデータ

- 利用者の履歴・選択ファイル・手動の参照リポジトリ対応・MkDocs保存先は、プロジェクト直下の `spoonfeeder_configs.json`（`SPOONFEEDER_CONFIGS_FILE` で変更可能、Git管理外）へ保存する。書き込みは一時ファイル経由で置き換える。
- この設定ファイルのJSONが壊れていた場合は、`spoonfeeder_configs.json.corrupt`（以降 `.corrupt.1`…）へ退避してから空の設定で起動する。履歴が上書きで失われない。
- 無視リストはリポジトリ直下の `.spoonfeeder.json`（既存の `.ignore_context` があればそれ）へ保存し、他の設定項目は保持する。
- ブラウザ側の設定（無視ファイル表示、Python実行モード、Embeddedフォルダ、Git差分コマンド、外部モジュールを含めるか、最後に開いたパス）はlocalStorageへ保存する。localStorageが使えない環境ではその回の設定として動作する。

## 対応環境

- Python 3.10以上
- Windows、macOS、Linux
- Windows運用時はNode.js不要。`frontend/dist` のビルド済みファイルをFastAPIが配信する。
- Windowsでは`start.bat`がコンソールとPython入出力をUTF-8へ設定する。パス入力は`/`と`\`を受け付け、テスト出力はUTF-8またはCP932を判別する。
- ソースファイルはUTF-8（BOM付き含む）、UTF-16、CP932を読み込める。コード反映では元のBOM・文字コード・改行形式を保持する。
