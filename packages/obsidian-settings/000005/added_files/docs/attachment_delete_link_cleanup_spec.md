# 仕様書: 添付ファイル削除時のノート内リンク自動クリーンアップ

## 1. 概要
「コピーして同一フォルダーに保存」などでノート内に生成されたObsidianリンク（`[[aaa.md]]`、`[[test.pdf]]`、`![[image.png]]` 等）に対して、「添付ファイルを削除」（または画像の「削除」）を実行した際、ファイル実体をゴミ箱へ移動すると同時に、ノート内の該当リンク（通常Wikilink、埋め込み、Markdownリンク）をすべて自動削除してリンク残存による不具合やフォーマット崩れを防止します。

## 2. 背景と課題
- **従来の挙動**: 
  - 削除ロジックの正規表現が `!\[\[...\]\]` に限定されており、通常リンク `[[test.pdf]]` や `[[aaa.md]]`、Markdownリンク `[doc](test.pdf)` が削除対象外となっていた。
  - ファイルエクスプローラーから添付ファイルを削除した場合、`sourceFile` が `null` のためリンク削除処理自体がスキップされていた。
  - リスト項目（`- [[test.pdf]]`）や単独行のリンクを単純に空文字置換すると、`- ` や不自然な連続空行が残存してMarkdownの構造が崩れていた。
- **課題**:
  - ファイル削除後にリンクが孤立し、クリック時に新規空ノートが作られたり、削除後の動きが不安定になっていた。

## 3. 詳細仕様

### 3.1. リンク削除対象の拡張 (`cleanAttachmentLinksInText`)
- **対応するリンク記法**:
  1. **埋め込みWikilink**: `![[ファイル名]]`、`![[ファイル名|300]]`、`![[ファイル名#見出し]]`
  2. **通常Wikilink**: `[[ファイル名]]`、`[[ファイル名|別名]]`、`[[ファイル名#見出し]]`
  3. **拡張子省略Wikilink**: `[[basename]]`（Markdownファイルの場合）
  4. **標準Markdownリンク**: `[表示名](パス)`、`![代替テキスト](パス)`
- **一致判定ロジック (`isTargetAttachmentLink`)**:
  - リンクパス（クエリ・ハッシュ除去後、URLデコード済）を以下の基準で比較：
    1. `metadataCache.getFirstLinkpathDest(linkpath, sourcePath)` による解決先ファイル
    2. 保管庫ルートからのパス（`attachmentFile.path`）
    3. ノートの親フォルダーからの相対パス（`${sourceFolder}/${linkpath}`）
    4. 完全なファイル名（`attachmentFile.name`）
    5. 拡張子を除いたベースネーム（`attachmentFile.basename`）

### 3.2. フォーマット崩れ防止（行・リスト項目のクリーンアップ）
- **箇条書きリスト項目**:
  - 行がリスト記号（`- `, `* `, `+ `, `1. ` 等）と該当リンクのみで構成される場合、行全体（改行を含む）を削除。
- **単独行リンク**:
  - 前後に空白のみが存在する行に該当リンクがある場合、行全体を削除。
  - 3連続以上の空行（`\n\n\n+`）が発生した場合は、最大2連続改行（段落間1行の空行）に正規化。
- **文章中インラインリンク**:
  - 前後に文章テキストがある場合は、リンク文字列部分のみを削除し、周囲の文章を維持。

### 3.3. 参照元ノートの一括自動削除連携 (`deleteAttachmentFile`)
- **対象ノートの自動検出**:
  - ノート内メニューから実行された場合は、そのノート（`sourceFile`）を対象とする。
  - ファイルエクスプローラー等から `sourceFile` なしで実行された場合：
    1. 現在アクティブなノート（`app.workspace.getActiveFile()`）
    2. バックリンク元ノート（`app.metadataCache.resolvedLinks` から検出した参照元）
    をすべて特定。
- **一括更新・ロールバック**:
  - 特定されたすべてのノートから該当リンクを削除し、`app.vault.modify` で保存。
  - 対象ファイル（`file`）をシステムゴミ箱（`app.vault.trash(file, true)`）へ移動。
  - もしゴミ箱への移動に失敗した場合は、各ノートの内容を自動で元の状態へロールバック。
  - 開かれているノートタブ（葉）があれば、`refreshAttachmentSourceFile` で表示をリフレッシュ。

### 3.4. 通常リンクに対する右クリックメニュー提供
- **閲覧モード / Live Preview (`handleMarkdownAttachmentContextMenu`)**:
  - 埋め込み（`.internal-embed`）だけでなく、通常の内部リンク要素（`a.internal-link`、`.cm-hmd-internal-link` 等）の右クリックメニューにも「添付ファイルを削除」を追加。
- **エディタメニュー (`handleEditorMenu`)**:
  - カーソル位置が `[[...]]` や `![[...]]` 上にある場合、最上部に「添付ファイルを削除」を追加。
