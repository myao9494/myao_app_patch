# 仕様書: PDF埋め込みのドラッグリサイズ

## 1. 概要
Markdown ノートに埋め込んだ PDF（`![[資料.pdf]]`）の右端・下端・右下隅をドラッグして、表示の大きさを変えられるようにする。ドラッグを終えると、画像と同じ記法でノート本文のリンクへ大きさを保存する（画像の右下ドラッグリサイズ [image_drag_resize_spec.md](image_drag_resize_spec.md) と同じ考え方）。大きさを変えても、画面は今の位置のまま動かない。

## 2. Obsidian 標準の PDF 埋め込みの表示（Obsidian 1.14 で確認）
- 埋め込み要素は `.internal-embed.pdf-embed`。既定の大きさは **幅100%・高さ1ページ分**（ページを幅いっぱいに表示したときの1ページの高さ＋ツールバー）。このためノート上では非常に大きく表示される。
- 高さの指定が無い場合、Obsidian は枠の大きさが変わるたびに高さを1ページ分へ合わせ直す。
- リンクの `|600x400` は、埋め込み要素の `width` / `height` 属性になる（編集モード・閲覧モードとも）。ただし PDF の表示には使われない。
- リンクの `#height=400` は Obsidian 標準の高さ指定だが、`#` 以降を変えると Obsidian は埋め込みを作り直して PDF を読み込み直す。別名（`|600x400`）だけの変更なら、埋め込みを作り直さずに属性だけを更新する。
- PDF の表示部品は枠の大きさの変化を監視しており、枠の幅を変えるとページを幅に合わせて描き直す。このとき、ページを表示位置へ合わせる処理が、埋め込みの外側にあるノートのスクロール位置まで動かす。

## 3. 操作
| ハンドル | 変わるもの | 保存されるリンク |
| :--- | :--- | :--- |
| 右端（`mod-right`） | 幅。高さの指定が無い場合、高さは幅に合わせて1ページ分へ自動で追従する | `![[資料.pdf\|600]]` |
| 下端（`mod-bottom`） | 高さ（ツールバーを含む枠全体） | `![[資料.pdf\|600x400]]` |
| 右下隅（`mod-corner`） | 幅と高さ | `![[資料.pdf\|600x400]]` |

- ハンドルは PDF 埋め込みにマウスを乗せると薄く表示される。ドラッグ中は大きさ（例: `幅 600px × 高さ 400px`）をマウスの近くに表示する。
- 最小サイズは幅 200px、高さ 200px。幅は親要素（本文の幅）までに抑え、本文の幅いっぱいまで広げた場合は幅の指定を取り除く（既定の100%表示に戻す）。ただし高さの指定が残る場合は、幅を数値で残す。
- 記法の都合で高さだけは書けないため、下端のドラッグで幅の指定が無い場合は、今の表示幅を書く。
- いずれかのハンドルをダブルクリックすると、幅と高さの指定を取り除いて既定の大きさに戻す。
- ハンドルを動かさずに離した場合（3px 未満）は保存しない。保存すると閲覧モードでは埋め込みが描画し直され、ダブルクリックの2回目が別の要素に当たってリセットできなくなるため。
- 右端のハンドルは、ツールバーのボタンと右下隅のハンドルに重ならないよう、上端から 44px・下端から 16px 空けて配置する。
- ホバープレビュー（`.popover`）と Canvas の PDF は、それぞれの枠の大きさに従うため対象外。

## 4. リンクの書き換えルール（`findPdfEmbedSizeEdit`）
- 幅・高さは、数値で指定、`null` で指定を取り除く、省略で今の値を残す。
- 別名は Obsidian と同じく、最後の `|` 以降がサイズ指定ならサイズ、それより前を表示名として扱い、表示名は残す（`![[資料.pdf|資料|600x400]]`）。
- 以前の版が書いた `#height=` は、高さを指定・リセットするときに取り除く（`page=3` などの他の指定は残す）。幅だけを変えるときは、埋め込みを作り直さないよう `#` 以降に触らない。
- Wikilink（`![[...]]`）を優先し、見つからない場合のみ標準 Markdown 記法（`![資料|600x400](資料.pdf)`。パーセントエンコードされたパスを含む）を対象にする。
- 名前の一部だけが一致する別の PDF（`xa.pdf`）は対象にしない。
- 同じ PDF を複数回埋め込んだノートでは、操作した埋め込みのリンクだけを書き換える。
- 保存先のノートの特定、書き換え範囲（該当リンクだけを置換）、閲覧モードでのファイルの直接書き換えは、画像のリサイズと同じ処理（`rewriteEmbedLinkInNote`）を使う。

## 5. 表示への反映（`applyPdfEmbedSizes`）
- 図の埋め込みの DOM 監視（`applyFigureEmbedDisplayNames`）のたびに、Markdown ビュー内の PDF 埋め込みの `width` / `height` 属性を表示の大きさとして当て、ハンドルを1組だけ付ける。属性が無くなった場合は指定を外す。
- 高さは `height` に加えて `min-height` / `max-height` でも固定する（`setPdfEmbedFixedHeight`）。Obsidian が高さを1ページ分へ戻してしまうため。高さの指定が無い PDF の幅だけを変える場合は、この固定を外して1ページ分の高さへ追従させる。
- 狭いペインでもはみ出さないよう、CSS で `max-width: 100%` を指定する。
- 画像用のリサイズハンドル（`.custom-image-resizer-handle`）は PDF 埋め込みには付けない。PDF のハンドル（`.custom-pdf-resizer-handle`）の追加は、図の再走査のきっかけにしない。

## 6. 表示位置を変えない仕組み
大きさを変えたとき、画面が一番上（カーソルの位置）へ戻ったり、PDF の上端へ飛んだりしないようにする。画像のリサイズも同じ保存処理を使うため、同じ対策が効く。

| 原因 | 対策 |
| :--- | :--- |
| 編集モードで `editor.replaceRange` を使うと、Obsidian がカーソルの見える位置までスクロールする（カーソルがノートの先頭にあると先頭へ戻る） | CodeMirror へ直接、スクロール指定の無い書き換え（`cm.dispatch`）を送る |
| 編集モードで書き換えた行の高さを、CodeMirror が仮の値（Obsidian の埋め込みは一律 100px）に見積もり直す。画面の上へはみ出した大きな PDF は画面外と判断されて描画されず、PDF が消えて下の本文が見える | 書き換えと同時に、書き換えた位置を今と同じ画面位置に保つよう CodeMirror に頼む（`EditorView.scrollIntoView` の `y: "start"` と、今の位置から求めた `yMargin`）。CodeMirror はその位置を描画・計測してからスクロールする |
| 閲覧モードでファイルを書き換えると、Obsidian が該当部分を描き直し、その先頭へスクロールし直す | 書き換え後の再描画のあいだ（3秒）、元のスクロール位置へ戻し続ける（`keepViewScrollPosition`） |
| ドラッグ中に PDF の幅が変わると、PDF の表示部品がページを表示位置へ合わせ、ノートのスクロール位置まで動かす | ドラッグを始めた時点から、元のスクロール位置へ戻し続ける。マウスを離した後は保存処理が引き継ぐ |

- 位置を保っている間に、利用者がホイール・キー・クリックで操作したら、その時点で位置を保つのをやめる。
- 位置はスクロールイベントのたびと毎フレームで確かめる（再描画で本文の高さが変わっても、スクロールイベントが起きない場合があるため）。
