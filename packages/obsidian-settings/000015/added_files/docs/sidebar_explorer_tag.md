# 仕様: Sidebar Explorer Tag

サイドバーエクスプローラータグ（`obsidian-sidebar-explorer-tag`）における機能追加および仕様をまとめます。

## クエリ未指定時におけるタグなしファイルの一覧表示

### 概要
タグ検索窓（`tag_key` セクションのキーワード検索）にキーワードを何も指定していない（空の）状態のときに、タグが一切設定されていないファイルを検索・一覧表示します。

### 動作
- **変更前**: クエリが空のときは「Enter keywords to search...」のプレースホルダーメッセージを表示するのみで、ファイルリストは何も表示されませんでした。
- **変更後**: クエリが空のときは、フロントマターの `tags` や `tag` フィールド、および本文中のインラインタグ（`#tag`）が設定されていないマークダウンファイルをすべて抽出し、更新日時（`mtime`）の降順でソートして一覧表示します。
- **UIの表記**:
  - クエリが空のときの結果リストヘッダーには、`{件数} files with no tags found` と表示されます。
  - クエリが入力されているときは、従来通り `{件数} files found` と表示されます。

### 実装設計
フィルタリングロジックの保守性とテスト可能性を考慮し、ロジックを `utils.ts` に関数として切り出し、Obsidianの実行環境に依存せずに単体テストができるように実装されています。

- **`utils.ts`**:
  - `filterFilesByTagQuery` をエクスポート。ファイルの配列、クエリ文字列、および各ファイルのタグを取得するコールバック関数を引数に取ります。
- **`utils.test.ts`**:
  - `filterFilesByTagQuery` に対する単体テストを定義。空のクエリによるタグなしファイルの抽出、部分一致によるフィルタリング、複数キーワード指定時のAND検索、更新日時による降順ソートが意図通りに動作することを検証します。
- **`view.ts`**:
  - `SidebarExplorerTagView` 内の `refreshFileSearch` メソッドにおいて、`filterFilesByTagQuery` を呼び出してファイルリストの描画処理を行います。

## 除外検索（NOT検索）のサポート

### 概要
タグ検索窓に `-` で始まるキーワード（例: `-開発`）を指定した際、そのタグを持つファイルを除外して検索結果を表示します。
複数キーワードのAND条件をサポートし、例えば `株 -開発` と指定した場合は「株」を含み、かつ「開発」を含まないファイルが抽出されます。

### 仕様・挙動
- キーワードの分類：クエリをスペース区切りで分割し、先頭が `-` で長さが2以上のものを除外キーワード、それ以外を通常キーワードとします。
- マイナス記号単体（`-`）の入力は無視されます。
- 大文字小文字は区別せずに部分一致で除外判定が行われます。

## Option + クリックによる除外タグの追加

### 概要
Markdown本文中のタグ（`.tag`）やプロパティのタグ（`.multi-select-pill`）を `Option + クリック`（または `Alt + クリック`）した際、そのタグ名に `-` を前置して検索窓にアペンドし、即座に除外検索を実行できます。

### 動作
- `Option + クリック` された場合は、既存クエリに対して自動的にスペース区切りで `-タグ名` を追加してビューを更新します。

## 検索結果からのMOC（Map of Content）自動生成

### 概要
`tag_key` セクションの見出し（🔍 tag_key）を右クリックして「MOCを作成」メニューを選択することで、現在の検索結果に合致するファイルをリスト化したMOCファイルを `02_MOC` フォルダ配下に自動生成します。

### 仕様・挙動
- **保存先フォルダ**: `02_MOC` フォルダが存在しない場合は自動作成します。
- **MOCファイル名の決定**: 
  - クエリが空のとき: `タグなしファイル.md`
  - クエリがあるとき: 通常キーワードはアンダースコア（`_`）で連結し、除外キーワードがある場合は `(除外語A・除外語B除く)` のように中黒と括弧で連結して付与します（例: `株 投資 -開発 -海外` ➔ `株_投資(開発・海外除く).md`）。
- **上書き保存**: すでに同名のMOCファイルが存在する場合は、警告を出さずにそのまま上書き（最新のマッチ結果で再生成）します。
- **生成されるMarkdownの形式**:
  - フロントマターに `tags: [MOC]`、`search_query`、`created`（作成日時）を付与。
  - マッチしたファイルへの内部リンクを箇条書き形式（`- [[ファイル名]]`）で出力。
- **作成後の動作**: 作成（または更新）されたMOCファイルをアクティブなタブで開きます。

## MOC作成とサマリー作成の連動

### 概要
見出し右クリックメニューに「MOCを作成してサマリーを作成」項目が追加され、MOCファイルを生成・上書き保存した直後に、既存のサマリー作成処理（`createSummary`）を連動して自動実行します。

### 仕様・挙動
- **グローバルエクスポート**: `00_templates/RegisterCustomCommands.md` の中で `window.createSummary = createSummary` としてグローバル変数に代入することで、プラグインからの呼び出しを可能としています。
- **実行の流れ**: MOC生成およびファイルオープン（`openFile`）が完了した直後に、`window.createSummary(targetFile)` を呼び出します。これにより、通常どおりサマリー作成の深さ指定モーダルが起動し、指定された深さに応じたサマリー（統合マークダウンファイル）が `10_summary` フォルダ配下に作成・更新されます。

- **自動PDFエクスポートとパスコピー**: サマリー生成完了後、作成されたサマリーファイルが開いた直後（1000msの遅延後）に自動的にObsidianの「PDFにエクスポート」ダイアログを起動します。ユーザーが保存先を確定してエクスポートを実行すると、作成されたPDFファイルの絶対パスを自動的にクリップボードにコピーします（既存のPDF保存ダイアログフック機構と連動）。

## ノート一覧の追加

### 概要
`tag_key` セクションの見出しを右クリックして「ノート一覧を追加」を選ぶと、現在の検索クエリに一致するノート一覧を、アクティブなマークダウンノートへ挿入または更新します。

### 仕様・挙動
- 「タグの対象フォルダ」（既定: `01_data`, `02_MOC`）内のノートだけを一覧に入れます（`10_summary` のサマリーなどは入れません）。アクティブノート自身は一覧から除外します。
- `top` タグ付きノートを開いたときの自動更新（`RegisterCustomCommands.md`）とタグの右クリックメニューの「ノート一覧を追加」も、このプラグインが公開する `window._sidebarExplorerTagUpdateNoteList` を使うため、同じ一覧になります（実装: `noteListUpdater.ts`、`noteListSection.ts`）。
- 出力は `# note一覧` 見出しと、`名称` / `タグ` / `冒頭` / `作成日` / `編集日` の表を検索ボックス付きで描画する DataviewJS ブロックです。
- 生成範囲は `<!-- custom-note-list:start -->` と `<!-- custom-note-list:end -->` で囲み、次回以降はこの範囲だけを置換します。
- 過去に作成されたマーカーなしの `# note一覧` については、直下の表または箇条書き部分だけを旧形式として置換し、通常本文を巻き込まないようにします。
- プロパティには `Search Query` として現在の検索クエリを保存します。

## 表示対象ファイルのフォルダ制限

### 概要
サイドバーエクスプローラータグに表示されるファイルを `01_data` と `02_MOC` フォルダ配下のファイルのみに制限します。

### 仕様・挙動
- **対象箇所**:
  - `tag_key` セクション（ファイルのタグ検索結果）
  - `タグ` セクション（タグツリーにリストアップされるタグ情報、およびタグノードを展開した際に表示されるファイル一覧）
- **判定ルール**:
  - Vault内のすべてのマークダウンファイルのうち、ファイルの相対パスが `01_data/` もしくは `02_MOC/` で始まるファイルのみを対象とします。
  - それ以外のフォルダ配下に存在するファイル（例: `00_templates` など）は、タグ情報を含んでいてもサイドバーには表示されず、タグの集計対象からも除外されます。
  - タグツリーに表示するタグおよびその件数は、`01_data/` と `02_MOC/` フォルダ配下のファイルのみを走査して自前で集計・カウントします。これにより、他フォルダに含まれるタグ自体が表示されたり、「No files visible」のような件数の不整合が発生するのを防ぎます。

## 「デフォルトに戻す」ボタンの追加

### 概要
サイドバーエクスプローラータグの最上部に、全てのインプットボックス（入力値）をクリアして初期表示状態に戻す小さな「デフォルトに戻す」ボタンを追加します。

### 仕様・挙動
- **デザイン**: 
  - ビューの最上部に右寄せで配置し、高さを低く抑えた非常にコンパクトなボタンとします（フォントサイズ `0.7em`、枠線は薄い枠線でホバー時に強調されるデザイン）。表示領域をできる限り広く保つための配慮です。
- **動作**: 
  - ボタンがクリックされた際、`setFileSearchQuery("")` が呼び出され、`Keywords...` 入力欄と `Filter tags...` 入力欄の両方の値が空（ブランク）になり、表示内容が初期状態へとリセットされます。

## 「本文のタグを有効にする」設定の追加

### 概要
タグによる検索やノート一覧追加時の対象範囲を、デフォルトではフロントマターの `tags:` または `tag:` に記載されているタグに限定します。本文中のインラインタグ（`#tag`）も含めたい場合は、設定で「本文のタグを有効にする」をオンにします。

### 仕様・挙動
- **設定画面**: `main.ts` 内の `SidebarExplorerTagSettingTab` に「本文のタグを有効にする」トグルスイッチを追加。
- **デフォルト値**: `false` (オフ)
- **動作**:
  - オフのときは、各マークダウンファイルの `CachedMetadata.frontmatter` から抽出されたタグのみを検索・一覧の対象とします。
  - オンのときは、フロントマターのタグに加え、本文内に含まれるタグ（`CachedMetadata.tags`）も対象とします。
- **技術的要件**:
  - `utils.ts` 内の `extractTagsFromMetadata(cache, includeBodyTags)` を利用し、フロントマター及び本文内のタグを動的に抽出してマージする処理を一元化。
  - `view.ts` 内の既存の `getAllTags` によるタグ取得箇所を `extractTagsFromMetadata(cache, enableBodyTags)` に全置換。
