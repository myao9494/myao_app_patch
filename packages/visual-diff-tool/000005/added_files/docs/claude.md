# 開発仕様書

## 概要
画像差分ツール (Visual Diff Tool) のGUI仕様および構成。

## GUIの仕様
- **テーマ**: 全体を通してダークモードを採用。
- **レイアウト**:
  - `header`: タイトルとファイル差分／git差分のモード切替を配置。対応フォーマットの説明は表示せず、差分領域を広く確保する。
  - `toolbar`: 画像選択（A・B）と比較実行ボタン、カテゴリ・表示切り替え、ズームコントロールをまとめて配置。これにより、画像の選択後すぐに比較を実行しやすい設計としている。
  - `viewer`: 左右に並べて画像を表示するエリア。左側に基準画像（A）、右側に比較結果（B）を表示する。
  - `git diff`: 画像と設定対象のテキスト変更を列挙する。テキストは行番号・行内強調付きの左右差分を表示する。
  - `diff memo`: 比較後に `差分メモ` ボタンから別タブで開く。A（旧）と補正済み画像B（新）をスライダーで比較し、画像差分とは独立したテキストメモを配置できる。表示サイズは10〜300%で、画面に合わせるボタンとCtrl+ホイール／ピンチで調整できる。通常の二本指スクロールは画像移動、画像上のドラッグ（マウス中央ボタンを含む）はつかみ移動として扱う。
  - 差分メモはTキーまたは左サイドバーの「メモ追加」で、ポインター位置を中心に作成する。番号は表示せず、固定色で識別する。Lキーで引出線を追加し、矢印（A）、変更雲（C）、矩形（R/2）、楕円（O/4）、細いマーカー（M）を選択中メモへ関連付けられる。矢印は起点・終点、線幅、矢尻サイズを調整できる。描画オブジェクトは選択枠を表示し、Deleteで削除する。Nキーでは独立した黄色の付箋を追加できる。
  - 左サイドバーは境界ドラッグで幅変更、境界マークのクリックで表示切替を行う。一覧本文は3行で省略し、項目をクリックすると対応する図中メモが中央付近に来るよう画像領域を自動スクロールする。HTML・クリップボード出力には色、本文、引出線、描画、付箋を反映する。
  - 差分メモ画面にもメイン画面と同じハンバーガーメニューを表示し、Git対象拡張子・Obsidian設定・表示倍率をlocalStorage／Backend設定から引き継ぐ。
- **メモ付きコピー**:
  - 差分メモ画面の右クリックメニューから、画像A（旧）または画像B（新）にメモを描画したPNGをクリップボードへ保存する。
  - メモはフロントエンド上の注釈であり、Backend APIの差分計算結果には含めない。
  - 別タブ用の比較画像ペイロードは、通常 IndexedDB に保存し、利用できない場合のみ localStorage にフォールバックする。
- **Gitレポート**:
  - ハンバーガーメニューではGit対象拡張子設定を開閉操作なしで直接編集でき、下部にAPIエンドポイント説明へのリンクを表示する。
  - Git画像の注釈とテキストファイル単位のメモを保持し、ファイルごとのチェックで選択した変更を1つの自己完結HTMLへ保存する。
  - HTML出力対象は一覧モーダルでファイルごとにON/OFFを切り替えられ、全件ON/OFFも指定できる。
  - Markdown内のExcalidraw図に画像メモ（注釈・付箋）がある場合は、本文テキストのカードの直後に「<path> / Excalidraw」の画像カードとして出力する。メモは本文テキストのメモと別IDで保存する。
  - 選択後は専用のHTML出力プレビューページでカード順・サイズ、画像位置・倍率・出力領域を調整する。テキスト差分行は現在の行インデックスまで照合したうえで1行ずつHEAD内容へ戻せる。
  - HTMLは画像、CSS、本文倍率変更用の短いスクリプトを内包し、外部スクリプト、Webフォント、ネットワーク接続を必要としない。

## 実装構成
- **Frontend**: React (Vite)
  - `main.jsx`: UIのメインロジック。
  - `styles.css`: ダークモード対応のスタイリング。
  - **ビルド成果物のGit管理**: `frontend/dist` はすべてコミット対象（`.gitignore` 対象外）として管理。会社環境などで `npm run build` や Node.js が使えない場合でも、リポジトリ取得のみで完全オフラインでWebアプリが動作する。
- **Backend**: Python (FastAPI, OpenCV)
  - **ポート**: `8078` (ローカルサーバー)
  - **依存管理**: `requirements.txt` にて3D差分関連（`requirements-3d.txt`）も参照しており、`pip install -r requirements.txt` の1回で全機能の環境構築が可能。
  - `alignment.py`: SIFT / AKAZE / ORB による段階的な特徴量マッチングと ECC 補正。
  - `diffing.py`: YIQベースのピクセル差分、細線を維持するマスク生成、オーバーレイ、矩形抽出。
  - `image_io.py`: PNG/SVG/PDF/TIFF/Excalidraw の解析・ページ単位ラスター化、Obsidian `compressed-json` 展開、Draw.io複数行文字のSVG化、入力上限チェック、Excalidraw変換警告。
  - `raster_cache.py`: アップロード内容・拡張子・DPI・ページ番号をキーにしたラスター化キャッシュ。
  - `result_cache.py`: しきい値再計算用の補正済み画像キャッシュ。

## API仕様メモ
- `POST /api/attachments`: 貼り付け画像を短期保存する。保存先は `attachments/`、保持期間は3日。
- `POST /api/analyze`: ファイル形式、ページ数、ページ寸法、変換警告を返す。PDF/TIFFは全ページ画像を保持せずメタデータ取得を優先する。
- `POST /api/convert`: 指定ページをPNGにラスタライズし、プレビュー画像と基準領域候補を返す。
- `POST /api/diff`: ファイル変換、ページ選択、位置合わせ、初回差分生成を行う。レスポンスには補正済み画像と、キャッシュ可能な場合の `result_id` を含める。
- `POST /api/rediff`: `result_id` と新しいしきい値から差分オーバーレイとマスクだけを再生成する。キャッシュが利用できない場合は `image_a` と `image_b_aligned` を直接送るフォールバックも受け付ける。
- `POST /api/git/images`: Git管理フォルダ配下の変更画像を列挙する。
- `POST /api/git/files`: Git管理フォルダ配下の変更画像・設定対象テキストを列挙する。
- `POST /api/git/markdown` / `GET /api/git/markdown`: Obsidianの現在ノートを受け取り、Markdown起点の変更一覧とDIFF画面用の `diff_url` を返す。
- `GET/PUT /api/settings/obsidian`: Obsidianフォルダーとレポート保存先をBackend設定ファイル（`backend/.visual-diff-settings.json`）へ保存・取得する。Git欄にMarkdownファイルを指定した場合、このフォルダーを起点に関連リンクを解決する。設定ファイルは安全な初期値（空文字列）でGit管理し、会社環境でのファイル不在エラーを防止する。
- `POST /api/reports/save`: 設定済みのObsidianレポート保存先へ50MB以下の自己完結HTMLを保存する。保存先はリクエスト側から上書きできない。
- Frontendの画像差分領域は左右ペインのスクロールを同期し、Ctrl+ホイール／ピンチで画像倍率を変更する。アプリ表示倍率はブラウザー倍率と分離してlocalStorageへ保存する。
- `POST /api/git/item`: 片側画像プレビュー、または構造化されたテキスト左右差分を返す。
- `POST /api/git/revert-line`: プレビュー上のテキスト差分行をHEAD内容へ戻す。現在差分と行種別・内容・インデックスが一致しない場合は409で拒否する。
- `POST /api/git/diff`: 現在の画像とHEAD側画像を比較する。リネーム/コピーでは `head_path` がHEAD側パスになる。
- `POST /api/git/3d/jobs`: Git管理下の3D CADファイル（.step / .stp）について、HEAD側バイナリと作業ツリー側バイナリを抽出し非同期3D差分ジョブを開始して `job_id`（202 Accepted）を返す。片側のみ存在する場合（HEADなし＝新規追加、作業ツリーなし＝削除）も単体プレビュー用ジョブ（`single_mode: "new" / "old"`）を発行する。
- `GET /api/3d/status`: 3D差分関連ライブラリ（OCP, trimesh, scipy, rtree）の導入状況を返す。
- `GET /api/3d/samples`: 動作検証用サンプルSTEPペア（穴位置・寸法・ボス追加・位置ズレ・単位不一致）の一覧を返す。
- `POST /api/3d/samples/load`: 指定サンプルペアの3D差分ジョブを作成し `job_id` を返す。
- `POST /api/3d/jobs`: 新旧STEPファイルをアップロードし、子プロセスで非同期に差分計算を開始して `job_id`（202 Accepted）を返す。
- `GET /api/3d/jobs/{job_id}`: 差分ジョブの進捗率、ステージ名、警告、エラー、統計情報を返す。
- `GET /api/3d/jobs/{job_id}/mesh/{side}`: 完了ジョブの位置合わせ済みメッシュおよび頂点距離データをVDM1バイナリで返す。
- `DELETE /api/3d/jobs/{job_id}`: ジョブ結果および一時ファイルを即時破棄する。

## 3D CAD差分（STEP比較）仕様
- **GUI仕様**:
  - ヘッダーの「3D差分」タブから開く。完全オフライン動作。
  - **比較表示**:
    - **重ね表示 (Overlay)**: 新版（一致箇所: グレー、追加箇所: 緑）に対し、旧版の削除箇所（赤）を重ね合わせ。変更なし部分はフラグメントシェーダーで discard し、Z-fighting を防止。
    - **左右並べ表示 (Side-by-Side)**: 左に旧版（グレー＋赤）、右に新版（グレー＋緑）を並べ、OrbitControls のカメラ操作（回転・ズーム・パン）を左右で完全同期。
    - 単体表示（新版のみ／旧版のみ）、CAD輪郭線（エッジ）表示切替、ワイヤーフレーム表示、視点リセットに対応。
  - **高品質CADレンダリング（STEP-viewer準拠）**:
    - `toCreasedNormals(30°)` によりハードエッジで法線を分離し、平面上の三角形分割に起因する陰影の歪み・モヤモヤ・ガタガタを完全解消。
    - `THREE.EdgesGeometry` により30度以上の鋭角エッジを輪郭線として描画し、CADらしいシャープな形状を実現。
    - マットな質感（roughness 0.65, metalness 0.08）と4灯マルチライティング（環境光＋主光＋補助光＋正面光）により均一で美しい陰影を実現。
    - **差分境界の高精細化・滑らか化**: メッシュ細分化の目標辺長を対角長の1.5%（fineは0.8%）へ高解像度化し、さらにシェーダーで `fwidth` と `smoothstep` によるサブピクセル・アンチエイリアシングを適用。円柱ボスや穴周囲の差分領域のカクカク多角形化を解消し、滑らかな輪郭線を実現。
  - **スマート寸法測定 (Smart Dimension, STEP-viewer準拠)**:
    - ツールバーの「📏 寸法」ボタンで起動。頂点スナップ（Snap to Vertex）により、交差面の最寄り頂点（角・端点）へ自動吸着し、正確な幾何寸法を計測。
    - **スマート自動認識**: 3点円弧指定時は外接円計算（`fitCircleFrom3Points`）により穴径（$\phi$）および半径（$R$）を自動認識。45度傾斜面では面取り（$C$）を自動認識。直線2点では直線距離（$L, dX, dY, dZ$）を自動算出。
    - **手動切替ピル**: 認識が異なる場合や別の表現に切り替えたい場合は、寸法バッジをクリックしてピル（`φ` / `R` / `直線` / `C`）からワンクリックで手動選択可能。
    - **ドラッグ位置調整と引き出し線 (Leader Line)**: 寸法バッジをマウスドラッグで任意の位置へ自由に移動可能。移動時は計測対象の中心点からバッジへ破線の引き出し線（Leader Line）が滑らかに追従描画され、密集箇所でも見やすくレイアウトできる。
  - **3D注記メモ (Annotation, STEP-viewer準拠)**:
    - ツールバーの「📝 注記」ボタンで起動。モデル表面（差分箇所など）をクリックして注記ピンを打設。
    - ピンから引出線（破線・サークル）が伸びるメモカードを表示し、テキスト入力・4色カテゴリ分類（青: 通常メモ、緑: 変更/追加確認、黄: 要確認/課題、赤: 削除/不具合）に対応。
    - **メモカードのドラッグ位置調整**: メモカードヘッダーをドラッグして見やすい位置へ移動可能。ピンとカードを結ぶ引き出し線がリアルタイムに追従。
    - ピンのみの最小化 ↔ 展開切替、個別削除に対応。左右並べ表示（Side-by-Side）時も両画面で完全同期。
  - **CAD中実ハッチング断面表示 (Solid Section Plane)**:
    - ツールバーの「✂ 断面」ボタンで起動。モデルを任意の平面でカット。
    - **擬似中実断面 (Stencil Buffer Cap)**: 単なるクリッピングでは中身が空洞シェルに見える課題に対し、Three.js の Stencil Buffer（裏面インクリメント / 表面デクリメント / NotEqualキャップ描画）により、中身の詰まった閉じた中実ソリッドの切断面を瞬時に生成。
    - **CAD標準45度斜線ハッチング**: 内部Canvasで動的生成された45度斜線ストライプテクスチャ（完全オフライン）を切断面キャップに自動マッピング。
    - **断面操作バー**: 切断軸（X軸 / Y軸 / Z軸）のワンクリック切替、位置調整スライダー（0.5mm刻み）、切断方向の反転（Flip）ボタンを備え、リアルタイムに切断面をインタラクティブに探索可能。左右並べ画面でも完全同期。
  - **リアルタイムしきい値（許容誤差）スライダー**:
    - バックエンドは新旧のメッシュと各頂点の「相手メッシュ表面までの最短距離」を返し、色分けは Three.js のカスタムシェーダー（`MeshStandardMaterial.onBeforeCompile`）で行う。
    - サーバー再計算なしでスライダーに追従し、60fpsで色分けをリアルタイム更新。
    - 追加率（%）および削除率（%）をリアルタイムに集計・バッジ表示。
  - **Git 3D差分連携（コミット済みHEAD vs 作業ツリー）**:
    - 「git差分」タブにおいて、Gitリポジトリ内で変更された `.step` / `.stp` ファイルを自動検出（`kind: "3d"`）。
    - Gitナビゲーション（前後ボタン、ドロップダウン、絞り込み）から選択すると、`ThreeDiffViewer` が自動起動し、`HEAD`（旧版）と作業ツリー（新版）のSTEPバイナリを非同期に解析・差分計算。
    - ツールバーに `Git 3D: HEAD:<head_path> ↔ <path>` バッジを表示。
    - リアルタイムしきい値スライダー、重ね表示／左右並べ表示、スマート寸法（φ/R/直線/C）、注記メモ、中実ハッチング断面表示などの全3D機能がシームレスに動作。
    - **Git新規追加・削除時の単体3Dモデルプレビュー (Single Preview)**:
      - HEAD側に履歴がない新規追加ファイル（Untracked `??` や Added `A`）や、作業ツリーで削除されたファイル（Deleted `D`）が選択された場合も、「比較対象がありません」とエラー停止せず、単体CADモデルとしてプレビュー表示。
      - ツールバーに `Git 3D 新規: 新規追加 (<path>)` バッジを表示し、表示モードを「新版プレビュー」に固定。
      - 単体モデルであっても、マウスによる回転・ズーム・パン、ワイヤーフレーム・エッジ表示切替、スマート寸法測定（φ/R/直線/C、ドラッグ引出線）、注記メモ、CAD中実ハッチング断面表示（X/Y/Z軸・反転・スライダ）などの全CAD機能を完全提供。
  - **検証用サンプル**: 穴位置変更、寸法変更、ボス追加、位置・向きズレ（同一形状の姿勢ズレ検証）、位置ズレ＋形状変更（回転35°/15°補正＋縦壁に穴追加）、単位不一致の6組をUIからワンクリックで読み込み可能。
- **アーキテクチャ・最適化**:
  - **子プロセス分離**: OCPのGIL占有およびクラッシュによるサーバー本体の停止を防止するため、STEP解析・メッシュ化・距離計算を `multiprocessing.Process` で実行。
  - **新旧共通テッセレーション精度**: 新旧のバウンディングボックス対角長の最大値から線形許容差（mm）を決定し、新旧で同一の精度を適用して擬似差分を防止。
  - **自動位置合わせ**: 元座標で一致率が高ければ動かさず、ズレが大きい場合のみ面積重心・慣性主軸（24通りの姿勢候補）・トリム付きICPで補正。
  - **マルチコア並列計算・高速化**:
    - **新旧並行パイプライン**: 新旧STEPファイルの読み込み・テッセレーション（メッシュ化）、および新旧メッシュ細分化（`refine_mesh`）を `ThreadPoolExecutor(max_workers=2)` で並行実行。
    - **チャンク分割並列距離計算 (`parallel_closest_point`)**: 数十万頂点×数十万面の相手メッシュ最短距離計算を CPU コア数に応じてチャンク分割し、全コアマルチスレッドで並列実行。
    - **新旧メッシュ距離計算の同時実行**: 旧メッシュ頂点→新メッシュ、新メッシュ頂点→旧メッシュの距離計算を新旧並行で同時処理。
    - **スレッドセーフ保護**: `libspatialindex`（C++拡張）の空間インデックスのポインタ競合（SIGABRTクラッシュ）を防ぐため、スレッドごとに独立したメッシュ複製を割り当てて安全に並列化。
  - **データ転送高速化 (VDM1)**: JSONヘッダ＋Float32座標＋Uint32面インデックス＋Float32距離をリトルエンディアンでパックした独自バイナリ形式を採用（base64 JSONに比べ容量30%削減・パース高速化）。
  - **セキュリティと容量管理**: アップロードされたSTEPファイルはメッシュ化完了直後に削除。計算結果は保持期間（デフォルト60分、環境変数で変更可）経過後に自動削除。
  - **フロントエンド遅延読み込み**: Three.js 関連コードを `React.lazy` でコード分割し、2D画像・Git差分の初期表示速度を維持。
  - **DOM保護・removeChildエラー防止**: Three.js の Canvas を React 管理下の子ノード（ラベル・SVG計測層）と隔離した専用コンテナ（`.three-canvas-host`）にマウントし、React の仮想DOMツリー破壊による NotFoundError（removeChild）クラッシュを完全防止。
  - **実機STEP検証済み**: 実CADデータ（`CBES (50kg to 2000kg).step`、15,021頂点、単品部品）にて、同一モデル比較で追加・削除0.0%（全面グレー表示・差分なし）となることをWeb画面上で実証。微小面（17面）の安全なスキップ・警告通知も正常動作。


## 入力制限と変換の注意
- アップロード上限は100MB/ファイル。
- PDF/TIFFは60ページまで、ラスタライズ後は90MP/ページまで。
- Gitテキストは5MB、30,000行/片側まで。長大な変更行は行全体を変更として強調し、過大な文字単位計算を避ける。
- ExcalidrawはPython内蔵の軽量レンダラーで基本図形とテキストを描画する。埋め込み画像、要素回転、矢印ヘッド、テキストスタイル、透明度は未対応または近似で、APIは警告を返す。
- Git欄にはリポジトリ・サブフォルダーだけでなくMarkdownファイルも指定できる。リポジトリ全体の変更から、Markdownを起点に `![[画像]]`、`[[ノート]]`、相対Markdownリンク、および3D CADコードブロックを再帰的にたどり、Git変更一覧を関連ファイルだけに絞り込む。
- **Obsidianショートリンク解決とVault自動検出**:
  - `![[図_test_convert.excalidraw]]` や `![[diagram.svg]]` のようにファイル名のみで指定されたショートリンクを、Obsidian VaultルートおよびGit管理下ファイルから自動解決する。
  - **CADコードブロック連携**: ` ```step ` や ` ```cad `、` ```3d ` 等のコードブロック内に記載された `path: ...` や `file: ...` のSTEPファイル（`.step`, `.stp`）、および汎用プロパティ指定のSTEPファイルを自動抽出し、Obsidian Vaultルートまたは相対パスから実体ファイルを高精度に解決。リンク先STEPファイルがGit上で変更されていれば、Markdown起点の差分一覧に `kind: "3d"` として即座に列挙・3D差分比較可能とする。
  - サーバー設定（`obsidian_folder`）が未設定または別フォルダであっても、対象Markdownファイルから親へ遡って `.obsidian` ディレクトリを自動検出し、見つからない場合もGitリポジトリ（`repo`）自身をVaultルートとしてフォールバックする。
  - Git管理下の追跡ファイル（`git ls-files`、`core.quotepath=false` UTF-8対応）を優先走査することで、作業ツリーで削除された画像・モデル（HEADにのみ存在）も含めて高速かつ正確に差分対象として検出する。
  - 拡張子省略リンク（`![[image]]`）の主要画像・3D拡張子自動補完、およびURL形式リンク（`http://.../?filepath=...`）内のローカルファイルパス抽出に対応する。

## パフォーマンスと並列処理・最適化仕様
- **画像Diffパイプラインの並列処理**:
  - 画像Aと画像Bの変換・ラスタライズを `ThreadPoolExecutor` により並列実行する。
  - 特徴量検出（SIFT / AKAZE / ORB）において、画像Aと画像Bの `detectAndCompute` をスレッドセーフな独立インスタンスで並列実行する。
  - 差分生成後のレスポンス画像（原画A/B、補正後A/B、オーバーレイ、マスクの計6枚）のPNGエンコード（zlib圧縮）を並列実行し、レスポンス返却を高速化する。
- **Git一覧取得の軽量化（無駄な繰り返しの排除）**:
  - ファイル一覧（`/api/git/files`）取得時、変更されたテキストファイルに対して不要な `git show`（外部プロセス）を直列実行せず、拡張子およびローカル作業コピーの先頭サンプリングで高速判定する。
- **特定Markdownファイル指定時のピンポイント差分取得**:
  - 単一の Markdown ファイル（または特定パス）が指定されている場合、リポジトリ全体を `git status` 走査するのではなく、対象ファイルとその直接リンク先のみを抽出してパス指定で `git status` を実行し、無駄な全件走査を排除する。
- **Windows向けgitプロセス起動の削減**（Windowsはプロセス起動とファイル走査が桁違いに遅いため）:
  - **リポジトリルート判定**: すべてのGit系APIで毎回 `git rev-parse --show-toplevel` を起動せず、`.git` を親方向に探索して判定する。見つからない場合のみ従来どおりgitで確認する。
  - **HEAD側Blob取得の1プロセス化**: `_git_show` はサイズ確認用の `cat-file -s` を廃止し、`git cat-file blob` を1回だけ起動して上限（+1バイト）まで読んで打ち切る。Markdownのリンクを辿る処理は `git cat-file --batch` の常駐1プロセス（`_GitBlobBatch`）でノート数に依存せずHEADを読む。
  - **リンク解決の索引化**: 解決できないリンクごとのVault全体 `os.walk` を廃止し、追跡ファイル → `git ls-files --others --exclude-standard` → ファイルシステム走査（gitignore済みのみ・1リクエストにつき検索ルートごとに最大1回）の順に、ファイル名索引（`_LinkIndex`）を共有して解決する。
  - **git実行ファイル**: Git for Windows の `cmd\git.exe`（`mingw64\bin\git.exe` を再起動するランチャー）を避け、実体を直接起動する。`VISUAL_DIFF_GIT_EXE` で明示指定できる。
  - **gitオプション**: `--no-optional-locks`（読み取り専用でindexを更新しない）、`core.preloadindex=true`、`core.fscache=true` を付与する。
  - **テキスト差分**: 先頭・末尾の共通行を `SequenceMatcher` へ渡さず、行内ハイライトは置換行ごとに左右を1回の比較で生成する。
  - **HTML出力プレビュー作成**: 各ファイルのDiff取得を並列度2〜4で並列実行する（結果の順序は維持）。
- **Excalidraw埋め込みMarkdownのテキストDiff高速化**:
  - `difflib.SequenceMatcher` 実行前に Excalidraw データ行を除外して計算し、巨大なJSONデータの不要な行・文字差分計算を防止する。
- **Pythonコード・Markdown向けスマートテキストDiff**:
  - **トークン・単語単位のインライン差分**: 1文字ごとの細切れ比較ではなく、Python識別子・英単語・日本語（漢字・ひらがな・カタカナの塊）・記号のトークン単位で比較し、単語ごとのすっきりとしたハイライトを生成する。
  - **アンカー行保護と空行引きずられ防止**: 空行や単純な区切り文字（`:`や`---`など）をjunkとして除外することで、関数定義行やMarkdown見出しがアンカーとして保護され、自然な行マッチングを実現する。
- **テキスト差分表示の視認性・レイアウト仕様**:
  - **黒文字と高コントラスト背景（VS Code風）**:
    - 追加行（`added` / `insert` / 新側）: 鮮明なグリーン背景（`#86efac`）、変更単語ハイライト（`#4ade80`）、文字色 `#000000`（黒文字）、キャレット `#000000`。
    - 削除行（`removed` / `delete` / 旧側）: 鮮明なレッド背景（`#fca5a5`）、変更単語ハイライト（`#f87171`）、文字色 `#000000`（黒文字）、キャレット `#000000`。
    - `code` 要素の背景を透明化（`background: transparent !important`）し、親セルの背景色が確実に前面に出るよう保証。
    - 白文字を排除し、明るい背景＋黒文字によって圧倒的な視認性を確保。
  - **複数行折り返し時のセル自動伸縮（CSS Grid & Flexbox設計）**:
    - 親グリッド `.text-diff-columns` の行高さを `grid-auto-rows: max-content;` とし、従来の `minmax(24px, auto)` での 24px 固定化を防止。
    - 各行の `.diff-code-cell` を `display: flex; align-items: stretch;` とし、中身の行番号とコード領域が同等の高さで拡張される。
    - 長文行エディタ内には `.diff-line-sizer`（通常フロー）を配置し、折り返し行数に応じて物理的に高さを押し広げ、`diff-line-editor`（textarea）がそのサイズに完全追従。
    - これにより左右の行の高さが一致し、直下の行との重なり（overlap）が完全に解消される。
  - **左右行番号の同期と追加行（A）・削除行（D）表示仕様**:
    - **左右の行番号同期**: 共通行（`equal`）および置換行（`replace`）において、左右の行番号を完全に一致する同一通し番号（1, 2, 3...）で表示。左右を見比べた際の行番号ズレを防止。
    - **追加行（`insert`）**: 新側の行番号セルに "A"（Added）を表示し、旧側は空欄（None）。通し番号を消費しないため、後続の共通行番号が左右でズレずに一致する。
    - **削除行（`delete`）**: 旧側の行番号セルに "D"（Deleted）を表示し、新側は空欄（None）。通し番号を消費しないため、後続の共通行番号が左右でズレずに一致する。
- **3D差分（STEP比較）のマルチコア並列計算・高速化**:
  - 新旧STEPの読み込みおよびメッシュ化（テッセレーション）を `ThreadPoolExecutor(max_workers=2)` で並行実行。
  - 新旧メッシュの細分化（`refine_mesh`）を並行実行。
  - 頂点群を CPU コア数に応じて均等チャンク分割し、`parallel_closest_point` により相手メッシュへの最短距離を全コア並列計算。
  - `libspatialindex` のスレッド競合（クラッシュ）を回避するため、スレッド毎に独立した軽量メッシュを割り当てて安全に高速化。
