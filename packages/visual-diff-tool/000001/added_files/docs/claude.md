# 開発仕様書

## 概要
画像差分ツール (Visual Diff Tool) のGUI仕様および構成。

## GUIの仕様
- **テーマ**: 全体を通してダークモードを採用。
- **レイアウト**:
  - `header`: タイトルとファイル差分／git差分のモード切替を配置。対応フォーマットの説明は表示せず、差分領域を広く確保する。
  - `toolbar`: 画像選択（A・B）と比較実行ボタン、カテゴリ・表示切り替え、ズームコントロールをまとめて配置。これにより、画像の選択後すぐに比較を実行しやすい設計としている。
  - `viewer`: 左右に並べて画像を表示するエリア。左側に基準画像（A）、右側に比較結果（B）を表示する。
  - `git diff`: 画像と設定対象のテキスト変更を列挙する。テキストは行番号・行内強調付きの左右差分を表示する。
  - `diff memo`: 比較後に `差分メモ` ボタンから別タブで開く。A（旧）と補正済み画像B（新）をスライダーで比較し、画像差分とは独立したテキストメモを配置できる。表示サイズは10〜300%で、画面に合わせるボタンとCtrl+ホイール／ピンチで調整できる。通常の二本指スクロールは画像移動、画像上のドラッグ（マウス中央ボタンを含む）はつかみ移動として扱う。
  - 差分メモはTキーまたは左サイドバーの「メモ追加」で、ポインター位置を中心に作成する。番号は表示せず、固定色で識別する。Lキーで引出線を追加し、矢印（A）、変更雲（C）、矩形（R/2）、楕円（O/4）、細いマーカー（M）を選択中メモへ関連付けられる。矢印は起点・終点、線幅、矢尻サイズを調整できる。描画オブジェクトは選択枠を表示し、Deleteで削除する。Nキーでは独立した黄色の付箋を追加できる。
  - 左サイドバーは境界ドラッグで幅変更、境界マークのクリックで表示切替を行う。一覧本文は3行で省略し、項目をクリックすると対応する図中メモが中央付近に来るよう画像領域を自動スクロールする。HTML・クリップボード出力には色、本文、引出線、描画、付箋を反映する。
  - 差分メモ画面にもメイン画面と同じハンバーガーメニューを表示し、Git対象拡張子・Obsidian設定・表示倍率をlocalStorage／Backend設定から引き継ぐ。
- **メモ付きコピー**:
  - 差分メモ画面の右クリックメニューから、画像A（旧）または画像B（新）にメモを描画したPNGをクリップボードへ保存する。
  - メモはフロントエンド上の注釈であり、Backend APIの差分計算結果には含めない。
  - 別タブ用の比較画像ペイロードは、通常 IndexedDB に保存し、利用できない場合のみ localStorage にフォールバックする。
- **Gitレポート**:
  - ハンバーガーメニューではGit対象拡張子設定を開閉操作なしで直接編集でき、下部にAPIエンドポイント説明へのリンクを表示する。
  - Git画像の注釈とテキストファイル単位のメモを保持し、ファイルごとのチェックで選択した変更を1つの自己完結HTMLへ保存する。
  - HTML出力対象は一覧モーダルでファイルごとにON/OFFを切り替えられ、全件ON/OFFも指定できる。
  - 選択後は専用のHTML出力プレビューページでカード順・サイズ、画像位置・倍率・出力領域を調整する。テキスト差分行は現在の行インデックスまで照合したうえで1行ずつHEAD内容へ戻せる。
  - HTMLは画像、CSS、本文倍率変更用の短いスクリプトを内包し、外部スクリプト、Webフォント、ネットワーク接続を必要としない。

## 実装構成
- **Frontend**: React (Vite)
  - `main.jsx`: UIのメインロジック。
  - `styles.css`: ダークモード対応のスタイリング。
- **Backend**: Python (FastAPI, OpenCV)
  - **ポート**: `8078` (ローカルサーバー)
  - `alignment.py`: SIFT / AKAZE / ORB による段階的な特徴量マッチングと ECC 補正。
  - `diffing.py`: YIQベースのピクセル差分、細線を維持するマスク生成、オーバーレイ、矩形抽出。
  - `image_io.py`: PNG/SVG/PDF/TIFF/Excalidraw の解析・ページ単位ラスター化、Obsidian `compressed-json` 展開、Draw.io複数行文字のSVG化、入力上限チェック、Excalidraw変換警告。
  - `raster_cache.py`: アップロード内容・拡張子・DPI・ページ番号をキーにしたラスター化キャッシュ。
  - `result_cache.py`: しきい値再計算用の補正済み画像キャッシュ。

## API仕様メモ
- `POST /api/attachments`: 貼り付け画像を短期保存する。保存先は `attachments/`、保持期間は3日。
- `POST /api/analyze`: ファイル形式、ページ数、ページ寸法、変換警告を返す。PDF/TIFFは全ページ画像を保持せずメタデータ取得を優先する。
- `POST /api/convert`: 指定ページをPNGにラスタライズし、プレビュー画像と基準領域候補を返す。
- `POST /api/diff`: ファイル変換、ページ選択、位置合わせ、初回差分生成を行う。レスポンスには補正済み画像と、キャッシュ可能な場合の `result_id` を含める。
- `POST /api/rediff`: `result_id` と新しいしきい値から差分オーバーレイとマスクだけを再生成する。キャッシュが利用できない場合は `image_a` と `image_b_aligned` を直接送るフォールバックも受け付ける。
- `POST /api/git/images`: Git管理フォルダ配下の変更画像を列挙する。
- `POST /api/git/files`: Git管理フォルダ配下の変更画像・設定対象テキストを列挙する。
- `POST /api/git/markdown` / `GET /api/git/markdown`: Obsidianの現在ノートを受け取り、Markdown起点の変更一覧とDIFF画面用の `diff_url` を返す。
- `GET/PUT /api/settings/obsidian`: Obsidianフォルダーとレポート保存先をBackend設定ファイル（`backend/.visual-diff-settings.json`）へ保存・取得する。Git欄にMarkdownファイルを指定した場合、このフォルダーを起点に関連リンクを解決する。設定ファイルは安全な初期値（空文字列）でGit管理し、会社環境でのファイル不在エラーを防止する。
- `POST /api/reports/save`: 設定済みのObsidianレポート保存先へ50MB以下の自己完結HTMLを保存する。保存先はリクエスト側から上書きできない。
- Frontendの画像差分領域は左右ペインのスクロールを同期し、Ctrl+ホイール／ピンチで画像倍率を変更する。アプリ表示倍率はブラウザー倍率と分離してlocalStorageへ保存する。
- `POST /api/git/item`: 片側画像プレビュー、または構造化されたテキスト左右差分を返す。
- `POST /api/git/revert-line`: プレビュー上のテキスト差分行をHEAD内容へ戻す。現在差分と行種別・内容・インデックスが一致しない場合は409で拒否する。
- `POST /api/git/diff`: 現在の画像とHEAD側画像を比較する。リネーム/コピーでは `head_path` がHEAD側パスになる。

## 入力制限と変換の注意
- アップロード上限は100MB/ファイル。
- PDF/TIFFは60ページまで、ラスタライズ後は90MP/ページまで。
- Gitテキストは5MB、30,000行/片側まで。長大な変更行は行全体を変更として強調し、過大な文字単位計算を避ける。
- ExcalidrawはPython内蔵の軽量レンダラーで基本図形とテキストを描画する。埋め込み画像、要素回転、矢印ヘッド、テキストスタイル、透明度は未対応または近似で、APIは警告を返す。
- Git欄にはリポジトリ・サブフォルダーだけでなくMarkdownファイルも指定できる。リポジトリ全体の変更から、Markdownを起点に `![[画像]]`、`[[ノート]]`、相対Markdownリンクを再帰的にたどり、Git変更一覧を関連ファイルだけに絞り込む。
- **Obsidianショートリンク解決とVault自動検出**:
  - `![[図_test_convert.excalidraw]]` や `![[diagram.svg]]` のようにファイル名のみで指定されたショートリンクを、Obsidian VaultルートおよびGit管理下ファイルから自動解決する。
  - サーバー設定（`obsidian_folder`）が未設定または別フォルダであっても、対象Markdownファイルから親へ遡って `.obsidian` ディレクトリを自動検出し、見つからない場合もGitリポジトリ（`repo`）自身をVaultルートとしてフォールバックする。
  - Git管理下の追跡ファイル（`git ls-files`、`core.quotepath=false` UTF-8対応）を優先走査することで、作業ツリーで削除された画像（HEADにのみ存在）も含めて高速かつ正確に差分対象として検出する。
  - 拡張子省略リンク（`![[image]]`）の主要画像拡張子自動補完、およびURL形式リンク（`http://.../?filepath=...`）内のローカルファイルパス抽出に対応する。

## パフォーマンスと並列処理・最適化仕様
- **画像Diffパイプラインの並列処理**:
  - 画像Aと画像Bの変換・ラスタライズを `ThreadPoolExecutor` により並列実行する。
  - 特徴量検出（SIFT / AKAZE / ORB）において、画像Aと画像Bの `detectAndCompute` をスレッドセーフな独立インスタンスで並列実行する。
  - 差分生成後のレスポンス画像（原画A/B、補正後A/B、オーバーレイ、マスクの計6枚）のPNGエンコード（zlib圧縮）を並列実行し、レスポンス返却を高速化する。
- **Git一覧取得の軽量化（無駄な繰り返しの排除）**:
  - ファイル一覧（`/api/git/files`）取得時、変更されたテキストファイルに対して不要な `git show`（外部プロセス）を直列実行せず、拡張子およびローカル作業コピーの先頭サンプリングで高速判定する。
- **特定Markdownファイル指定時のピンポイント差分取得**:
  - 単一の Markdown ファイル（または特定パス）が指定されている場合、リポジトリ全体を `git status` 走査するのではなく、対象ファイルとその直接リンク先のみを抽出してパス指定で `git status` を実行し、無駄な全件走査を排除する。
- **Excalidraw埋め込みMarkdownのテキストDiff高速化**:
  - `difflib.SequenceMatcher` 実行前に Excalidraw データ行を除外して計算し、巨大なJSONデータの不要な行・文字差分計算を防止する。
- **Pythonコード・Markdown向けスマートテキストDiff**:
  - **トークン・単語単位のインライン差分**: 1文字ごとの細切れ比較ではなく、Python識別子・英単語・日本語（漢字・ひらがな・カタカナの塊）・記号のトークン単位で比較し、単語ごとのすっきりとしたハイライトを生成する。
  - **アンカー行保護と空行引きずられ防止**: 空行や単純な区切り文字（`:`や`---`など）をjunkとして除外することで、関数定義行やMarkdown見出しがアンカーとして保護され、自然な行マッチングを実現する。
- **テキスト差分表示の視認性・レイアウト仕様**:
  - **黒文字と高コントラスト背景（VS Code風）**:
    - 追加行（`added` / `insert` / 新側）: 鮮明なグリーン背景（`#86efac`）、変更単語ハイライト（`#4ade80`）、文字色 `#000000`（黒文字）、キャレット `#000000`。
    - 削除行（`removed` / `delete` / 旧側）: 鮮明なレッド背景（`#fca5a5`）、変更単語ハイライト（`#f87171`）、文字色 `#000000`（黒文字）、キャレット `#000000`。
    - `code` 要素の背景を透明化（`background: transparent !important`）し、親セルの背景色が確実に前面に出るよう保証。
    - 白文字を排除し、明るい背景＋黒文字によって圧倒的な視認性を確保。
  - **複数行折り返し時のセル自動伸縮（CSS Grid & Flexbox設計）**:
    - 親グリッド `.text-diff-columns` の行高さを `grid-auto-rows: max-content;` とし、従来の `minmax(24px, auto)` での 24px 固定化を防止。
    - 各行の `.diff-code-cell` を `display: flex; align-items: stretch;` とし、中身の行番号とコード領域が同等の高さで拡張される。
    - 長文行エディタ内には `.diff-line-sizer`（通常フロー）を配置し、折り返し行数に応じて物理的に高さを押し広げ、`diff-line-editor`（textarea）がそのサイズに完全追従。
    - これにより左右の行の高さが一致し、直下の行との重なり（overlap）が完全に解消される。
  - **左右行番号の同期と追加行（A）・削除行（D）表示仕様**:
    - **左右の行番号同期**: 共通行（`equal`）および置換行（`replace`）において、左右の行番号を完全に一致する同一通し番号（1, 2, 3...）で表示。左右を見比べた際の行番号ズレを防止。
    - **追加行（`insert`）**: 新側の行番号セルに "A"（Added）を表示し、旧側は空欄（None）。通し番号を消費しないため、後続の共通行番号が左右でズレずに一致する。
    - **削除行（`delete`）**: 旧側の行番号セルに "D"（Deleted）を表示し、新側は空欄（None）。通し番号を消費しないため、後続の共通行番号が左右でズレずに一致する。
