# 詳細仕様書

## 0. 初期版の前提

- 比較対象の主語は常に「ファイル全体」とする。
- マルチページファイルでは、読み込み後に左右それぞれのページをユーザーが手動選択して比較する。
- 位置合わせカテゴリは `汎用`、`図面`、`グラフ`、`書類` の4種を提供し、デフォルト値は `汎用` とする。
- 初期版の差分ロジックはピクセル差分を採用する。
- 差分表示の色分けは「追加 = 青」「削除 = 赤」を基本とする。
- 位置合わせに失敗した場合は処理を中断せず、未補正のまま差分表示を継続する。
- 初期版では VSCode 拡張機能の実装はスコープ外とし、Web アプリと Backend API を優先する。
- API は今後の拡張を見据えて、変換、解析、差分の責務を分離した構成を維持する。

## 1. 画像処理パイプライン

比較プロセスは以下の順序で実行される。

1. **Input**: 2つのファイル (A, B) を受け取る（PNG, JPEG, WebP, BMP, GIF, SVG, Excalidraw JSON, Obsidian Excalidraw Markdown, マルチTIFF, マルチPDF）。
2. **Pre-process**:
    - **マルチページ分解**:
        - PDFの場合: `PyMuPDF (fitz)` 等を用いて、ページメタデータを取得し、比較・プレビュー時は選択されたページのみを高解像度（現在のデフォルトは180 DPI）でPNG相当にラスタライズする。
        - マルチTIFFの場合: `Pillow (PIL.Image)` の `seek()` を用いてページメタデータを取得し、比較・プレビュー時は選択されたフレームのみをPNG相当にラスタライズする。
    - **単一画像変換**: SVG, Excalidraw JSON, Obsidian Excalidraw Markdown をPNGにラスタライズする。
    - **Excalidraw変換の初期方針**:
        - 通常の `.excalidraw` JSON を直接入力として受け付ける。
        - Obsidian の Excalidraw `.md` 形式も対象に含め、`compressed-json` Drawingブロックを展開して画像化する。
        - 初期版ではPython内蔵の軽量レンダラーで基本図形とテキストを描画する。
        - 埋め込み画像、要素回転、矢印ヘッド、テキストスタイル、透明度は未対応または近似扱いとし、APIレスポンスの `warnings` / `conversion_warnings` で通知する。
    - **アルファチャンネル処理**: 透過背景を「白」で塗りつぶし、図面の視認性を確保。
3. **Feature Matching**:
    - UIで選択されたカテゴリ（`汎用`、`図面`、`グラフ`、`書類`）に応じて前処理または特徴量抽出パラメータを切り替える。
    - OpenCVの `SIFT`、`AKAZE`、`ORB` 検出器を段階的に使用してキーポイントを抽出する。
    - 十分に信頼できる変換が得られた場合は後続検出器を省略し、難しい画像では複数検出器を試す。
    - `findHomography` / `estimateAffinePartial2D` (RANSAC / USAC_MAGSAC) で変換行列を計算し、回転・拡大縮小・歪みを補正。
    - 初期変換後、ECC による輝度ベースの微調整を試みる。
4. **Warping**: 画像Bを画像Aの座標系に射影変換。
5. **Diff Generation**:
    - 初期版ではピクセル差分を用いる。
    - YIQ距離に基づいてしきい値判定を行い、孤立した微小ノイズを連結成分ベースで抑制する。
    - 図面や回路図の1px〜2px程度の細線差分を消さないよう、マスク全体への opening 処理は行わない。
    - 二画面表示用に、変更があったピクセルを強調する。
    - 色分けは「削除箇所は赤」「追加箇所は青」「両画像にインクがある変更箇所は黄」を基本とする。
    - しきい値だけが変わる場合は、既存の補正済み画像を使って差分だけを再生成する。
6. **Fallback**:
    - 十分な特徴点が得られない、または変換行列を安定して推定できない場合は、未補正のまま差分表示を行う。
    - UI上では「位置合わせ失敗、未補正で表示中」のような警告を明示する。

## 2. API エンドポイント

- **Base URL**: `http://127.0.0.1:8078`

- `GET /api/health`: Backend の稼働確認。
- `POST /api/attachments`: クリップボード貼り付け画像などを短期保存する。
- `POST /api/analyze`: アップロードされたファイルの基本メタデータ（総ページ数、フォーマットなど）を取得。
- `POST /api/diff`: 2つのファイル（および指定されたそれぞれのページ番号 `page_a`, `page_b`）を受け取り、補正後の画像と差分データを返す。
- `POST /api/rediff`: 既存の比較結果に対して、しきい値変更後の差分オーバーレイ、マスク、矩形一覧を再生成する。
- `POST /api/convert`: 指定された特定ページまたは単一ファイルをPNGにラスタライズする。
- `POST /api/git/images`: 指定フォルダ配下のGit変更画像を列挙する。
- `POST /api/git/files`: 指定フォルダ配下のGit変更画像と設定対象テキストを、追加・削除・未追跡を含めて列挙する。
- `POST /api/git/markdown`: ObsidianのMarkdownファイルパスを受け取り、関連変更ファイル一覧とDIFF画面用の `diff_url` を返す。`GET /api/git/markdown?path=...` も同じ処理を行う。
- `GET /api/settings/obsidian`: サーバー設定ファイル（`backend/.visual-diff-settings.json`）に保存されたObsidianフォルダーとレポート保存先を取得する。設定ファイルは安全な初期値でGit管理され、会社環境等でのファイル不在エラーを防止する。
- `PUT /api/settings/obsidian`: Obsidianフォルダーとレポート保存先を検証してサーバー設定ファイルへ保存する。各値は空文字列で解除でき、省略した項目は既存値を維持する。
- `POST /api/reports/save`: Obsidian起点の自己完結HTML差分レポートを、リクエストから変更できない設定済み保存先へ保存する。ファイル名はベース名へ正規化し、50MBを上限とする。
- `POST /api/git/item`: Git変更の片側画像プレビュー、または構造化されたテキスト左右差分を返す。
- `POST /api/git/revert-line`: HTML出力プレビューに表示したテキスト差分行を、作業ファイル上でHEADの内容へ戻す。行種別・内容・両側インデックスを現在の差分と厳密照合し、古いプレビューから別の同文行を変更しない。
- `POST /api/git/diff`: Git管理下の現在画像とHEAD側画像を比較する。リネーム/コピー時は `head_path` をHEAD側パスとして扱う。
- `GET /`: `frontend/dist` に含まれる Web UI を配信する。

### 初期版 API 方針

- 比較操作はファイル単位で開始し、マルチページファイルではページ選択結果を `page_a`、`page_b` として指定する。
- 初期版の `POST /api/diff` は、少なくとも以下の情報を返せるようにする。
    - `result_id`（しきい値再計算用の短期キャッシュID。キャッシュ上限を超える巨大ペアでは `null`）
    - 補正後画像B
    - 差分オーバーレイ画像
    - 変換行列
    - 差分マスク
    - 差分矩形一覧
    - `conversion_warnings`（変換時の近似・未対応機能に関する警告）
- `POST /api/rediff` は `result_id` と `diff_threshold` を基本入力とする。
    - `result_id` が期限切れの場合に備え、`image_a` と `image_b_aligned` を直接渡すフォールバックも受け付ける。
    - フォールバック成功時は、画像ペアがキャッシュ上限内なら新しい `result_id` を返し、以後のしきい値変更を再び高速化する。
- 将来の拡張を見据え、レスポンス形式は追加フィールドを後方互換で増やしやすい構造とする。
- Windows オフライン利用を考慮し、`frontend/dist` はリポジトリに含め、Backend から静的配信する。
- 入力上限は、アップロード100MB/ファイル、PDF/TIFF 60ページ、ラスタライズ後90MP/ページを基本とする。全ページを一括ラスタライズする内部経路では合計180MPを上限とする。
- Gitテキストは5MB、30,000行/片側を上限とする。1行の変更文字数が大きい場合は行全体を変更表示し、極端に高コストな文字単位比較を避ける。

### パフォーマンス方針

- `convert`、`diff` 間で同じファイル・同じページを何度もラスタライズしないよう、アップロード内容・拡張子・DPI・ページ番号をキーにした短期キャッシュを利用する。
- `analyze` はPDF/TIFFの全ページ画像を保持せず、ページ数・寸法などのメタデータ取得を優先する。
- `diff` 後の補正済み画像ペアを短期キャッシュし、しきい値変更時は再アライメントせず `rediff` で差分だけを再計算する。
- GitテキストUIとHTML出力では未使用の全文フィールドを省略し、レスポンス転送量とブラウザのメモリ消費を抑える。HTML出力時は現在表示中の取得済み差分を再利用する。
- キャッシュは件数上限と総メモリ上限を持ち、巨大ファイルでは必要に応じて再計算する。
- 高速化は精度を落としすぎない範囲で行い、特徴量マッチングでは高信頼な結果が得られた場合のみ早期終了する。

## 3. UI/UX デザイン

- **File-first Flow**:
    - まずファイルAとファイルBを読み込む。
    - マルチページファイルの場合、その配下で左右それぞれのページを手動選択して比較する。
- **Category Selector**:
    - `汎用`、`図面`、`グラフ`、`書類` の4種類を選択可能にする。
    - デフォルト値は `汎用` とする。
- **Side-by-Side Diff**: 左にファイルA、右に補正済みファイルBを表示する。
- **Page Navigator**:
    - マルチページファイルの場合、ファイル選択欄のページセレクターからページを選択する。
    - 左右それぞれで比較したいページを個別に選択可能にする（例: Aファイルの1ページ目 vs Bファイルの2ページ目）。
- **Color Coding**:
    - 差分箇所を透過度を持たせた赤/青でオーバーレイ表示する。
    - 基本ルールは「追加 = 青」「削除 = 赤」「変更 = 黄」とする。
    - **Zoom Control**: 左右共通のズーム倍率を適用する。
    - **表示領域操作**: ハンバーガーメニューからアプリ固有の表示倍率（50〜200%）を変更でき、ブラウザー全体の倍率には影響しない。ヘッダー・操作バー・統計欄を固定し、画像領域だけをスクロールする。画像領域のCtrl+ホイール／ピンチで左右共通倍率を変更し、通常のホイール／トラックパッド2本指スワイプで上下左右にスクロールする。画像上の左ボタン／トラックパッドドラッグ、またはマウスの中央ボタンを押したままドラッグすると画像を掴んで移動でき、左右ペインのスクロール位置を同期する。画像領域端からの横スワイプはブラウザーの戻る／進むジェスチャーへ伝播させない。
- **Threshold Tuning**: 比較後に差分しきい値を変更でき、補正済み画像を再利用して高速に表示更新する。
- **Git Diff Flow**:
    - Git管理フォルダを指定し、変更された対応画像・テキストファイルを列挙する。
    - Git入力にMarkdownファイルを指定した場合、リポジトリ全体の変更を一度列挙したうえで、そのMarkdownを起点に `![[...]]` / `[[...]]` / 相対Markdownリンクを再帰的に解決し、関連する変更ファイルだけを対象にする。リンク先が別フォルダーにあっても対象に含める。Obsidianフォルダーはハンバーガーメニューから設定し、Backendの設定ファイルへ保存する。
    - 最後に読み込んだフォルダをブラウザへ保存して次回起動時に復元し、入力右側の履歴ボタンから最近使ったフォルダを選べる。
    - `*.excalidraw.md` / `*_excalidraw.md` は通常Markdownではなく画像として分類し、HEAD版と作業フォルダ版を同じ変換器で比較する。
    - テキストの初期対象は `.md`, `.txt`, `.csv`, `.json`, `.yaml`, `.yml` とし、ハンバーガーメニューを開くとGit対象拡張子の設定を直接表示する。設定はブラウザに保存し、同じメニューの下部にAPIエンドポイント説明へのリンクを配置する。
    - テキスト差分はHEAD版と作業フォルダ版を左右に並べ、行番号、明確な追加・削除色、片側だけの行を示す空欄パターン、変更行内の文字差分を表示する。
    - 追加・削除・未追跡ファイルも片側だけの差分として表示・出力する。
    - リネーム/コピー済み画像は現在パスとHEAD側パスを分けて比較する。
    - Git画像からも差分メモ画面を開ける。テキストにはファイル単位のメモ欄を用意する。
    - HTML出力対象はモーダルの一覧でファイルごとにON/OFFを切り替えられ、全件ON/OFFも指定できる。選択した変更、画像メモ、テキストメモを1つのHTMLへ保存する。HTMLは画像・CSS・本文倍率変更用の短いスクリプトを内包し、外部スクリプト・Webフォント・ネットワーク接続を必要としない。
    - HTML出力プレビューはモーダルではなく専用ページとして表示する。画像メモごとに、右下ハンドルのドラッグでカード幅・高さ、画像上のドラッグまたは2本指スワイプで画像位置、ピンチで画像倍率を調整できる。調整用スライダーは表示しない。領域指定がない場合は現在の表示範囲を出力し、領域指定ボタンで矩形を指定した場合はその領域を優先する。表示設定と指定領域はメモIDごとに保存し、別メモへ切り替えても独立して保持する。未設定のメモは対象メモを中心に表示する。テキストカードでは各差分行を変更前へ戻せるが、プレビュー後にファイルが変化していれば書き換えを拒否する。プレビューからメモ編集画面を開き、メモ編集画面から元のHTML出力プレビューへ戻れる。
    - メイン画面と差分メモ画面はハンバーガーメニューから操作ヘルプを開け、Hキーでも同じヘルプを表示する。HTML出力プレビューとAPI説明ページには画面上のヘルプボタンを配置し、Hキーにも対応する。
    - Obsidian起点のHTMLレポートはハンバーガーメニューで設定した保存先へ保存し、ファイル名を `<Markdownファイル名>_変更差分レポート.html` とする。レポート内のCtrl+ホイールはブラウザー倍率ではなく本文コンテンツ倍率を変更し、画像差分は3列で横幅を有効利用する。
    - Draw.io SVGのHTMLベース文字は、全文と明示的な改行を保持したSVGテキストへ変換してから画像差分を生成する。MuPDFで欠落する日本語の長音記号は互換グリフへ置換し、元文字列を属性に保持する。Draw.io SVGは2.5倍のラスタライズ倍率で変換し、低解像度による文字・線の欠落を抑える。
- **Conversion Warnings**:
    - Excalidrawなどの変換で近似・未対応機能がある場合、比較結果画面に警告を表示する。
- **Diff Memo View**:
    - 比較後に `差分メモ` ボタンから別タブのメモ画面を開く。
    - メモ画面では、A（旧）と補正済み画像B（新）を1枚のビューに重ね、GitHubの画像差分のようなスライダーでA/Bの境界を切り替える。
    - 表示サイズは10〜300%とし、`画面に合わせる` で表示領域に収まる倍率へ調整できる。図の領域ではCtrl+マウスホイール／macOSトラックパッドのピンチ（ctrl/meta/alt付きwheel）で5%単位に拡大・縮小する。通常の二本指スワイプはスクロールによる画像移動、画像上の左ドラッグまたはマウス中央ボタンを押したドラッグはつかみ移動とする。
    - メモ座標の保存基準は表示サイズ100%相当のステージ寸法へ正規化する。編集時の表示サイズを変更しても、HTMLプレビュー・HTML出力・クリップボード画像でメモ、引出線、図形、付箋の位置と大きさを一致させる。
    - Tキー／左サイドバーの「メモ追加」はポインター位置を中心に色付きメモを作成する。番号や変更種別の選択UIは表示せず、必要な内容は本文へ記入する。Lキーで選択中メモへ引出線を追加し、Escapeキーで本文編集を終了してショートカット操作へ戻れる。
    - 選択中メモには矢印（A）、変更雲（C）、矩形（R/2）、楕円（O/4）、マーカー（M）を関連付けられる。矢印は方向や縦横比にかかわらず矢尻の形を維持し、選択時に起点・終点を個別ドラッグできるほか、線の太さと矢尻の大きさを変更できる。マーカーは最初のドラッグで矩形範囲を指定して塗りつぶし、細い線として引いた場合はその細さを維持する。Nキーではメモに属さない黄色の付箋を追加でき、改行・文字数に応じて高さを自動調整する。描画と付箋はHTML・クリップボード出力にも反映する。
    - メモ、描画、付箋の編集操作はCtrl/Cmd+Zで元に戻し、Ctrl/Cmd+Shift+Zでやり直せる。ドラッグ中の連続更新や短時間の連続入力は1操作として履歴にまとめる。
    - 描画オブジェクトを選択すると水色の選択枠を表示し、Deleteキー（macOSではBackspaceも可）で削除する。図形上には削除用の×ボタンを表示しない。
    - 画像内のメモ本文はダブルクリックで文字編集状態へ入り、上部の本文欄はクリックで編集状態へ入る。Escまたは別の描画オブジェクトの選択で編集状態を終了する。
    - 左サイドバーは境界ドラッグで幅を変更し、境界のマークをクリックして表示・非表示を切り替える。メモ本文は最大3行まで表示して以降を省略し、一覧項目をクリックすると対応するメモが図の中央付近に来るよう画像領域を自動スクロールする。
    - 差分メモ画面のハンバーガーメニューはメイン画面と同じ設定項目を持ち、Git対象拡張子と表示倍率はブラウザ保存、Obsidian関連設定はBackend保存の値を共有する。
    - メモ、描画、付箋は画像差分とは独立したUI注釈として扱い、差分率、矩形、マスクなどの計算結果には影響させない。メモと関連する引出線・図形は右クリックからまとめて削除できる。
    - 右クリックメニューから画像A（旧）、画像B（新）、または左右配置したA/Bをメモ付きPNGとしてクリップボードへ書き込める。
    - 別タブに渡す画像ペイロードは IndexedDB に保存する。IndexedDB が使えない環境では localStorage にフォールバックする。
- **Alignment Failure Notice**: 位置合わせに失敗した場合は、未補正表示であることを明示する警告を表示する。

## 5. テスト用画像サンプル仕様

各カテゴリにおける15個のペア（合計30枚）について、画像A（基準）と画像B（一部変更＆位置ズレあり）の具体的な描画・変更仕様は以下の通りとする。

### 1) 機械設計図面 (Mechanical Drawings)
- **gear (歯車)**:
    - **A**: 基準歯車図面。中心円、ピッチ円、歯（24枚）、寸法線（`D = 120.0`）。
    - **B**: 歯車の右上の歯が1つ欠損。寸法値が `D = 125.0` に変更。反時計回りに3度回転。
- **flange (フランジ継手)**:
    - **A**: ボルト穴が4つの円形フランジ。
    - **B**: ボルト穴が6つに増加。右に8px、下に5px平行移動。
- **shaft (段付きシャフト)**:
    - **A**: 段付きシャフトの側面断面図。ハッチング、キー溝、全長の寸法線。
    - **B**: 段の長さが延長。キー溝の幅が2px縮小。全体が3%縮小。
- **bracket (L字ブラケット)**:
    - **A**: L字ブラケットの3面図（正面・平面・側面）。
    - **B**: 補強用リブ（斜め板）が正面図と側面図に追加。
- **bolt (ボルト・ナット)**:
    - **A**: 六角ボルトの頭部およびネジ部。ねじ山の長さ。
    - **B**: ねじ山部分のピッチが細かくなり、ボルト全長が10px延長。時計回りに1.5度傾斜。
- **pcb (配線基板)**:
    - **A**: 2層PCBの簡易的な配線パターン（導体配線、ハンダパッド、ビア）。
    - **B**: 一部の配線ルートが別ルートに変更、ビアが1つ削除。反時計回りに4度回転。

### 2) 解析データ (Graphs & Analysis)
- **stress_strain (応力ひずみ曲線)**:
    - **A**: 材料試験の応力-ひずみ曲線。降伏点、弾性変形領域、最大引張強さのプロットとラベル。
    - **B**: 最大引張強さのピークが上方にシフト。降伏点ラベルの位置が若干ズレ。右に15px平行移動。
- **thermal_heatmap (熱解析カラーマップ)**:
    - **A**: 中央部が高温（赤）で周辺が低温（青）の矩形グラデーションマップ。
    - **B**: 高温領域（赤）が右上方向に偏心。左に5px、上に5px移動。
- **fft_spectrum (振動周波数スペクトル)**:
    - **A**: 3つの鋭いピークを持つFFT解析スペクトル図。グリッド線、軸ラベル。
    - **B**: 3つ目のピークが消失、新しく高周波帯に小さなノイズピークが出現。全体が5%拡大。
- **bathtub_curve (バスタブ曲線)**:
    - **A**: 初期故障、偶発故障、摩耗故障の3段階を示す信頼性バスタブ曲線。
    - **B**: 摩耗故障の立ち上がり開始点が左にシフト。凡例テキストの変更。

### 3) 書類・ワークフロー (Documents & Workflows)
- **bom (部品表)**:
    - **A**: 5行の部品リスト（部品番号、部品名、数量、材質）。グリッド枠線。
    - **B**: 3行目の数量が `2` から `5` に変更。材質が `SUS304` から `S45C` に変更。
- **ecn (設計変更通知書)**:
    - **A**: 設計変更通知書の書式、日付、変更概要テキスト、右下に「承認」の丸い赤インク印影。
    - **B**: 変更概要テキストが2行追加。右下の「承認」印影が消失（未承認状態）。時計回りに5度回転。
- **workflow_flowchart (承認フローチャート)**:
    - **A**: 「設計」→「検図」→「承認」→「出図」の直線的フローチャート。
    - **B**: 「検図」から「修正」へ戻るフィードバックの分岐と、矢印が追加。
- **factory_layout (工場レイアウト)**:
    - **A**: 工場フロア内のCNC旋盤、マシニングセンタ、作業台の配置図（平面配置）。
    - **B**: CNC旋盤の位置が20px下に移動、空きスペースに「測定ベンチ」が追加。
- **inspection_certificate (検査成績書)**:
    - **A**: 外観、寸法、強度の検査結果表。すべての判定欄に「OK」が印字。
    - **B**: 強度の実測値が基準値外となり、判定欄が「NG」に変更されて赤文字強調。
