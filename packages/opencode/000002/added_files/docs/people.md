# 登場人物を覚える仕組み(`people`)

0.26.0 で段階 1 を実装した。段階 2・3 は未実装。

## 結論

- **人が判断する情報**(役割、自分との関係、業務の決まり)は、Vault の **人物ノート**(Markdown、1 人 1 ノート)に置く。人が読んで直せて、`ai_reviewed` の ✓ でレビューできる。
- **メールから自動で取れる事実**(やり取りの回数、最後の連絡、よく一緒に入る人、最近の件)は、新しく保存しない。既存のメールキャッシュ(SQLite)から、そのつど集計する。
- スキル **`people`** が、この 2 つを合わせて短く返す。メールを読むときは、`outlook` サブエージェントが、読む前に登場人物を引く。
- 覚えるのは、**インタビュー(`/people`)** か、`outlook` の「人物メモの案」をユーザーが承認したとき。自動では書かない。
- AI が作った人物ノートは **未レビュー**(`ai_reviewed: false`)。人が ✓ にするまで根拠にせず、「(未レビュー)」を付けて手がかりとして示す。

## 全体の形

```
メールキャッシュ (outlook-mail の SQLite, 読み取り専用) ─┐
                                                       ├─ people_cli.py ─→ 短い要約 (who)
Vault の 05_people/*.md (人物ノート) ──────────────────┘     ↑ 呼ぶのは outlook サブエージェント (who だけ)・メイン
                         ↑ new / set / memo (ユーザーの承認の後。メインだけ)
```

- `people` は、データを持たない。持つのは Vault の人物ノートだけ。データをスキルのフォルダに置かない(ハーネスの更新で上書きされるため)。
- 標準ライブラリだけで動く(`run.bat` / `run.sh`)。
- メールキャッシュの場所の決め方(`OPENCODE_OUTLOOK_MAILCACHE`、`LOCALAPPDATA`)と、`mails` テーブルの形に依存する。テストは本物の `outlook_cache` でキャッシュを作るので、形が変わると気付く。

## 人物ノート

### 置き場所

- Vault の `05_people/` に、1 人 1 ノート。ファイル名は氏名から空白を除いたもの(`山田太郎.md`)。
- Vault の場所は、環境変数 `OPENCODE_VAULT` → `skills/people/config.local.json` の `vault` → いまのフォルダから上へたどる、の順に探す。メールの作業は Vault の外のフォルダで行うことがあるため。フォルダ名は `people_dir` で変えられる(Vault の中、ドットで始まらない場所だけ)。

### 形

```markdown
---
created: 2026-11-11 10:00:00
tags:
  - 人物
type: person
name: 山田 太郎
kana: やまだ たろう
aliases:
  - 山田さん
  - 山田部長
emails:
  - taro.yamada@example.co.jp
org: ○○株式会社 設計部
role: 見積と仕様の窓口
relation: 客先
self: false
checked: 2026-11-11
ai_generated: opencode
ai_reviewed: false
---

## 要点

- 見積は部長決裁。金額の話は山田さんを通す。

## やり取りのメモ

- 2026-11-11 図面の改訂は PDF で送る決まり(出典: RE: B 案の図面)

## 関連
```

- `aliases` は Obsidian の別名と同じ項目。表示名・呼び方・ローマ字の違いは、ここに足す(照合に使う)。
- `relation` は、`自分`・`上司`・`同僚`・`社内`・`客先`・`協力会社`・`その他` のどれか。
- `checked` は、ユーザーに最後に確かめた日(`--checked`)。180 日より前のものは `check` で出る。
- `set` は、知らない項目と人の書いた行をそのまま残し、指定の項目だけを書き直す。入れ子など、自動で直せない形の項目を直そうとしたら止まる。

### 自分のノート

- `self: true`(`new 氏名 --self`)。1 つだけ。役職、担当、呼ばれ方、返信の文体と署名、よくやり取りする相手を書く。
- 返信の下書きを作る前に `who --self` で読む。メールの集計では、送信済みの差出人も自分として扱う(自分のノートが無くても、自分を候補に出さない)。

### 書いてよいこと・書かないこと

| 書いてよい | 書かない |
|---|---|
| 氏名、読み、会社・部署、業務上のメールアドレス | 電話番号、住所、私的な連絡先 |
| 役割、担当、決裁の範囲、自分との関係 | 私生活、家族、健康、思想・信条 |
| 業務の進め方の決まり(「図面は PDF で」「金額は部長決裁」) | 人物の評価(能力、性格、好き嫌い) |
| やり取りの経緯(日付と出典つき) | メール本文の転記 |

電話番号・郵便番号のような文字列は、スクリプトが書かずに止める。ほかは手順書と人のレビューで守る。共通 `AGENTS.md` の「個人情報を書かない」には、「人物ノートの業務の項目は除く」を足した。

## メールキャッシュからの集計

| 項目 | 求め方 |
|---|---|
| 受信・送信の件数 | 差出人・宛先・CC のどれかが人物に合うメールを、受信と送信で数える |
| 最後の連絡 | 合うメールの日時の最大 |
| よく一緒に入る人 | 合うメールのほかの人(自分を除く)の上位 3 人 |
| 最近の件 | 合うメールの件(RE: などを除いた件名)を新しい順に 3 つ。表示は最新の件名 |

### 照合

- キャッシュの宛先と CC は、Outlook の `To`・`CC` の文字列で、**表示名だけ**(アドレスが入らない)。社内の差出人のアドレスは、Exchange の形(`/O=EXCHANGELABS/...`)になることがある。**会社の環境でどうなるかは確認していない。**
- 照合は、アドレスと表示名の両方で行う。表示名は、全角半角・大文字小文字・空白をそろえ、括弧の中と `/` の後ろを除いた言い換えも作って、`name`・`aliases`・`emails` と比べる。
- 同じ表示名の人が 2 人いるときは、照合せずに「判別できない」と返す。

## コマンド

| コマンド | 内容 |
|---|---|
| `who <名前かアドレス>...` | 人物ノートの要点・最近のメモと、集計。一部の語でよい。人物ノートに無ければ、キャッシュから探して「未登録」として集計だけ |
| `who --mail <メールID>` | そのメールの差出人・宛先・CC の全員(自分は「自分」とだけ) |
| `who --self` | 自分のノート |
| `candidates [--since 90] [--min 3] [--limit 15]` | やり取りが多いのに未登録の人 |
| `new <氏名> [--kana] [--email]... [--alias]... [--org] [--role] [--relation] [--point]... [--checked] [--self]` | 人物ノートを作る。同じ氏名・同じアドレスがあれば作らない |
| `set <氏名・呼び方・アドレス> [同じ項目]` | 項目を直す。`--alias`・`--email`・`--point` は足す。別の人のアドレスは付けない |
| `memo <氏名・呼び方・アドレス> "本文" [--source 件名]` | `## やり取りのメモ` に、日付つきで 1 行足す |
| `check` | アドレスの重複、アドレスが無い、確かめた日が古い、未レビュー、自分のノートが無い・2 つある |

- `who` は 1 回に 10 人まで、1 人 5〜10 行(窓が狭いモデルのため)。
- 書き込みは、指定があいまい(2 人以上に合う)なら止まる。

## 流れ

### メールを読むとき

1. `outlook` が `cache-search` で対象を絞る。
2. 本文を読む前に `who --mail <ID>` で登場人物を引く(`outlook` に許すのは `who` だけ。`new`・`set`・`memo` は拒否)。
3. 答えで、人を「山田さん(客先・見積の窓口)(未レビュー)」のように補う。
4. 覚えるとよいことがあれば、返答の「人物メモの案」に書く。メインがユーザーに見せ、承認された分を保存する。

### インタビュー(`/people`)

1. 対象を決める。指定が無ければ、自分のノートが無いときは自分から、あるときは `candidates` の上位と、確かめた日が古い人。
2. 聞く前に `who` で調べる(アドレス、件数、件名)。分かることは聞かない。
3. 1 人ずつ、3 問まで、おすすめの答えつきで聞く(関係、役割、覚えておく決まり)。「はい」で受け入れられる形。
4. 書く内容のまとめを見せ、承認の後に `new` / `set` を `--checked` つきで実行する。書かないことに当たる答えは書かず、そのことを伝える。
5. 作った・直したノートを報告し、Obsidian で ✓ を付けてもらう。

## 段階

1. **段階 1(0.26.0、実装済み):** `people` スキル、`/people`、`outlook` との連携、ルールの変更。照合は表示名とアドレス。
2. **段階 2:** キャッシュに、宛先・CC の SMTP アドレスの列を足す(`Recipients` の各 `AddressEntry` から)。会社 PC で `SenderEmailAddress` と `Recipients` の値を確かめてから。
3. **段階 3(必要になったら):** 全文検索や、人と案件の結び付けのための索引(SQLite)。Markdown から作り直せる索引にする。
