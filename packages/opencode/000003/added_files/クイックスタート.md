# クイックスタート(会社の Windows PC)

会社の PC で、ハーネスを使えるようにするために**人が行うこと**だけを、順にまとめたもの。1 項目ずつの確認と、うまくいかないときの直し方は [docs/company-checklist.md](docs/company-checklist.md)、まとめて確かめるコマンドは [README.md](README.md) の「4. 会社への持ち込みと反映」。

以下の `<ユーザー名>` は Windows のユーザー名、`$cfg` は `$env:USERPROFILE\.config\opencode`(ハーネスのフォルダ)。PowerShell で行う。

## 0. 用意されていること(確かめるだけ)

- OpenCode CLI **V2**(V1 では動かない)。`opencode --version`
- `python --version` と `node --version` が出る(Node.js は `npm install`・`npx` ができなくてよい)
- Microsoft Edge、**クラシック版** Outlook
- Everything(HTTP サーバーを有効)と Local-fulltext-search が起動している
- 社内LLMの、モデル名・コンテキスト長・出力の上限が分かっている(3 の `limit` に使う)

## 1. ファイルを置く

- myao-patch-bridge で、パッチを `$cfg` に適用する(`company_repo_paths` に `.config\opencode` を対応付けてある)。
- 別のフォルダにリポジトリを置く場合は、`$cfg` に部品ごとのジャンクションを張る(README の「手順 1」の B。リポジトリ全体をリンクしない)。
- `$cfg` に、`AGENTS.md`、`agents\`、`commands\`、`skills\`、`templates\`、`mcp\playwright\node_modules\` が届いたかを見る。

## 2. Python の環境(`.venv`)

```powershell
cd $env:USERPROFILE\.config\opencode
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.lock
.\.venv\Scripts\python.exe -c "import win32com.client, pypdf, playwright; print('OK')"
```

`pip` の接続先を社内のミラーにするときは、コマンドで指定せず、`%APPDATA%\pip\pip.ini` か環境変数 `PIP_INDEX_URL` で決める(5)。

## 3. `opencode.json` を作る・直す(自分で書く)

`$cfg\opencode.json` は**リポジトリに入っていない**(社内の URL やモデルを書くため)。パッチでも上書きされない。`sample_opencode.json` と見比べて、手で反映する。

| 項目 | すること |
|---|---|
| `providers`・`model` | 社内LLMの接続先とモデルを書く(会社で決まっている値) |
| モデルの `limit` | **必ず書く。** `"limit": { "context": 130000, "output": 32000 }` の形で、実際の窓以下の値。省略すると 20 万と仮定され、窓を超える([docs/operations.md](docs/operations.md) の 5.4) |
| `update`・`share` | 雛形のまま(`disable`・`disabled`) |
| `instructions` | `["~/.config/opencode/memory/*.md"]`(プロフィールを毎回読ませる。6 で置く) |
| `permissions` | 雛形の配列を写す(会社側に古い行が残っていれば消す) |
| `mcp.servers.playwright` | `command` の中の `<ユーザー名>` を実際の名前に変える。使うときは `"disabled": false` |

書いたら、`opencode debug config` と `opencode debug agents` で読まれたかを見る(自作のエージェント 8 つが `subagent` で出る)。

## 4. スキルの設定ファイル(`config.local.json`)

各スキルのフォルダで、`config.sample.json` を `config.local.json` にコピーして書き換える。`*.local.json` は Git に入らない。**パスワードやキーは書かない**(5 の環境変数に置く)。

| スキル | 要否 | 自分で変える項目 |
|---|---|---|
| `file-finder` | **必須**(無いと止まる) | `roots`(検索してよいフォルダ)、`everything.url`・`user`、`fulltext.url`・`folders` |
| `doc-convert` | 任意(無ければ `file-finder` の `roots`) | `roots`(読んでよいフォルダ) |
| `obsidian-run` | Obsidian 連携を使うなら必須 | `api.url`、`api.ca_file`(HTTPS のとき)、`vault`、`commands`(実行を許すコマンド) |
| `people` | Obsidian を使うなら | `vault`、`people_dir` |
| `vault-notes` | 任意 | `daily_dir`(今日のフォルダの形) |
| `app-ecosystem` | 任意(ポートが既定と違うとき) | `apps` の URL |
| `browser-session` | 任意(Edge が見つからないとき) | `executable`、`browser`、`port`、`profile_dir` |

```powershell
$s = "$env:USERPROFILE\.config\opencode\skills"
Copy-Item "$s\file-finder\config.sample.json" "$s\file-finder\config.local.json"
notepad "$s\file-finder\config.local.json"
```

## 5. 環境変数

ユーザーの環境変数として設定し、OpenCode・Obsidian・ランチャーを**起動し直す**。キーやパスワードは、ファイルにもチャットにも書かない。

```powershell
[Environment]::SetEnvironmentVariable("OBSIDIAN_API_KEY", "<Local REST API のキー>", "User")
```

| 変数 | いつ要るか | 値 |
|---|---|---|
| `OBSIDIAN_API_KEY` | Obsidian 連携(`obsidian-run`)を使うとき | Obsidian の Local REST API の設定画面のキー |
| `EVERYTHING_PASSWORD` | Everything の HTTP サーバーにパスワードを付けたとき | そのパスワード(名前は `file-finder` の `password_env` で変えられる) |
| `OPENCODE_OUTLOOK_DATE_FORMAT` | 「予定の絞り込みに失敗しました」と出たとき | 日本語の環境では `%Y/%m/%d %H:%M` のことが多い |
| `PIP_INDEX_URL` | `pip` を社内のミラーにするとき(`pip.ini` でもよい) | ミラーの URL |
| `OPENCODE_VAULT` | 任意。`people` に Vault の場所を固定で教えるとき | Vault のフォルダ |
| `OPENCODE_OUTLOOK_MAILCACHE` | 任意。メールのキャッシュの場所を変えるとき(既定は `%LOCALAPPDATA%\opencode-harness\`。共有・同期されるフォルダにしない) | SQLite のファイルのパス |
| `SEARCH_APP_OPENCODE_DEFAULT_WORKING_DIR` | 任意(ランチャーの側)。AI_work を既定(`%USERPROFILE%\000_work\AI_work`)以外にするとき。ランチャーの ☰ メニューで選んでもよい | AI_work のフォルダ |

## 6. ひな形をコピーする

| 何を | どこへ | そのあと |
|---|---|---|
| `$cfg\templates\memory\profile.md` | `$cfg\memory\profile.md` | 【 】を自分の環境・立場に書き換える(2,000 文字以内。Git に入らない) |
| `$cfg\templates\obsidian\AGENTS.md` | Vault のルート(`.obsidian` のあるフォルダ)の `AGENTS.md` | フォルダの構成表を会社の Vault に合わせる。`.handoff/` を Vault の `.gitignore` に足す |
| `$cfg\templates\ai_work\` の中身 | AI_work(ランチャーの「opencode 実行フォルダ」) | 手順は `templates\ai_work\README.md`(既存は上書きしない。ランチャーにコマンドを 5 つ登録する) |
| Obsidian の CA 証明書(`obsidian-local-rest-api.crt`) | `$cfg\skills\obsidian-run\` | HTTPS で使うときだけ。`api.ca_file` にその場所を書く(HTTP にするなら要らない) |
| プロジェクトの `AGENTS.md` | 各プロジェクトのルート | コピーせず、OpenCode で `/init-project <フォルダ>` を使う |

```powershell
$cfg = "$env:USERPROFILE\.config\opencode"
New-Item -ItemType Directory "$cfg\memory" -Force | Out-Null
Copy-Item "$cfg\templates\memory\profile.md" "$cfg\memory\profile.md"   # 既にあれば、上書きしないように先に確かめる
robocopy "$cfg\templates\ai_work" "$env:USERPROFILE\000_work\AI_work" /E /XC /XN /XO
```

## 7. 動くかを確かめる

```powershell
cd $env:USERPROFILE\.config\opencode
opencode debug agents
& .\skills\file-finder\run.bat check
& .\skills\outlook-mail\run.bat check
& .\skills\doc-convert\run.bat check
& .\skills\obsidian-run\run.bat check        # Obsidian 連携を使うとき
& .\.venv\Scripts\python.exe .\mcp\playwright\smoke_test.py msedge
& .\.venv\Scripts\python.exe run_tests.py
```

- ランチャーの OpenCode ペインで `/env-check` を送り、`AGENTS.md あり`、`browser-session: あり`、`outlook-mail: あり` が出るかを見る。
- 残りは [docs/company-checklist.md](docs/company-checklist.md) を上から。結果は、その表の `[ ]` に書く。

## 8. 更新(パッチ)を当てたとき

1. [CHANGELOG.md](CHANGELOG.md) の、前回より新しい版の「**会社で手で行うこと**」を全部行う。
2. `sample_opencode.json` と `opencode.json` を見比べる(`permissions` と `mcp` が増えていることがある)。
3. `requirements.lock` が変わっていたら、2 の `pip install` をもう一度。
4. 新しいスキルに `config.sample.json` があれば、4 と同じように `config.local.json` を作る。
5. OpenCode・Obsidian・ランチャーを起動し直し、7 の確認をする。

## 確かめていないこと

- このファイルの手順を、会社の PC で通しで行ったことはない(自宅の Mac で書いた)。
- `[Environment]::SetEnvironmentVariable` で設定した変数が、起動中のランチャーや Obsidian から起動した OpenCode に渡るか(起動し直しが要る前提で書いた)。
