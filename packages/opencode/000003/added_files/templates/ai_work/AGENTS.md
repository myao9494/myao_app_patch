# AI_work(自動化の置き場)

このフォルダには、毎日の手作業を自動化したもの(Outlook の予定の作成、Web の勤怠入力など)を集める。1 つの自動化は、スキル 1 つ(`.opencode/skills/<名前>/`)と、その中の Python のスクリプトでできている。人は、Local-fulltext-search のランチャー(OpenCode ペイン)から `/コマンド 日本語の指示` で動かす。

依頼は 2 種類ある。最初に、どちらかを見分ける。

| 依頼 | 例 | 進め方 |
|---|---|---|
| **使う**(実行する) | `/kintai 今日 9:00-18:00`、「明日 10 時から設計レビューを予定に入れて」 | 合う自動化のスキルを読み込み、その「手順」どおりに動かす。迷ったら `automation-builder` の「使う」 |
| **作る・直す** | 「勤怠の入力を自動化したい」「/kintai が途中で止まる」 | スキル `automation-builder` を読み込み、その手順で進める |

合う自動化が無い「使う」依頼は、「自動化はまだ無い」と答え、今回だけ手で行うか、自動化を作るかを聞く。

## フォルダの構成

| 場所 | 役割 | 触り方 |
|---|---|---|
| `.opencode/skills/<名前>/` | 自動化 1 つ(`SKILL.md`、`run.bat`・`run.sh`、`scripts/`、`tests/`、`config.sample.json`) | 作る・直すときだけ変更する |
| `.opencode/skills/<名前>/config.local.json` | その自動化の個人の設定(URL、社員番号など) | 人が書く。AI は読むだけ。Git に入れない |
| `.opencode/skills/automation-builder/` | 自動化を作る手順とひな形 | 触らない |
| `.opencode/skills/env-check/` | 動作確認と今日の日付(自動化の見本) | 触らない |
| `.opencode/commands/` | OpenCode の画面(TUI)で使うコマンド | 触らない |
| `自動化一覧.md` | 自動化の目次(人が見る) | 自動化を作る・直すたびに直す |
| `launcher_slash_commands.sample.json` | ランチャーに登録するコマンドの例 | 触らない |
| `output/` | 自動化が作ったファイル(取り込んだ表、報告など) | 自動化が書く。消さない |
| `.handoff/` | 作業中の一時ファイル(ブラウザの段階ごとのスクリプトも) | 中身が残る前提にしない |
| `.venv/` | このフォルダの Python | スキル `python-env` の手順で |

## 使うとき(実行)

- ランチャーから 1 回の指示で動かす前提。指示から入力を読み取り、自動化の「入力」の表の「無いとき」で補って、**聞き返さずに進める**。聞くのは、結果が大きく変わる曖昧さがあるときだけ(1 回にまとめる)。
- 日付は推測しない。「今日」「明日」は `env-check` の「今日」を基準にし、日付の計算はスクリプトで行う。
- **取り消せない操作(送信、申請、確定、予定の作成、メールの移動)の前で、必ず止まる。** 何をするか(相手、日時、件数、値)を示し、ユーザーが「実行して」と返事をしてから実行する。ランチャーからの実行には許可の確認画面が無く、自動承認のこともあるので、この確認が歯止めになる。
- 自動化の手順に無い操作をしない。手順どおりに動かないときは、その場で作り直さず、何が起きたか(コマンド、エラー、どこまで進んだか)を報告し、`/auto-fix` で直せると添える。
- 報告: したこと、しなかったこと(止めた操作と理由)、出力したファイルのパス。

## 作るとき・直すとき

手順はスキル `automation-builder`。守ることだけを、ここに書く。

- 1 つの自動化 = 1 つのスキル。名前は英小文字・数字・ハイフン(例: `kintai-input`)。ハーネスのスキルと同じ名前にしない。
- 入力の解釈、計算、データの組み立ては Python のスクリプトにして、テスト(`tests/`)を書く。
- **画面の操作と取り消せない操作は、ハーネスのスキルの道具を通す**(Web は `browser-session`、Outlook は `outlook-mail`)。自分のスクリプトで、Outlook の COM、`requests` の POST、`sync_playwright()` を使って直接行わない。ハーネスの道具には、取り消せない操作を止める見張りと、許可の決まりがあるため。
- どの自動化にも、何も変えない確認の実行(`--dry-run`。ブラウザは送信の直前まで)を持たせる。
- パスワード・認証の情報を、スクリプトにも設定にも書かない。ログインは、人がブラウザで行う。
- 個人の設定は `config.local.json`(Git に入れない)。ひな形は `config.sample.json`。
- 作った・直したら、`自動化一覧.md` を直し、ランチャーに登録するコマンドを示す。**ランチャーへの登録は人が行う。**

## 使うハーネスのスキル

| 用途 | 使うもの |
|---|---|
| Web の画面の操作(勤怠、社内システムへの入力・取り込み) | `browser-session` |
| Outlook の予定の作成 / メールや予定を読むだけ | `outlook-mail` / `outlook` |
| 計算・単位の換算 | `calc-check` |
| Word・Excel・PDF を読む / ファイルを探す | `doc-convert` / `finder` |
| タスク・ガント | `app-ecosystem` |
| 何を自動化するかが決まらない | `interview` |
| Python を書く / パッケージを足す | `python-coding` / `python-env` |

## 会社の PC で

- `.bat` は ASCII だけで書く(日本語を入れない)。
- Python は、このフォルダの `.venv`(無ければ `python`)。パッケージは、スキル `python-env` の手順で `requirements.in` に書いてから入れる。標準ライブラリで足りるなら使わない。
- Node.js の `npm install`・`npx` は使えない。
- Git で管理しているなら、作る・直すの区切りでコミットを提案する(コミットは頼まれたときだけ)。
