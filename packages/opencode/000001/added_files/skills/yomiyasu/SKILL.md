# yomiyasu(要約版)

[nanaism/yomiyasu](https://github.com/nanaism/yomiyasu) v2.4.0(MIT)の手順書を、ハーネスのために短くしたもの。**細かい規則は `references/upstream-SKILL.md`(元の手順書、約 4.3 万文字)の同じ名前の節にある。迷ったら、その節だけを読む。** 全部は読まない。スクリプトと `references/` は元のまま。

**使い分け:** メインで使うのは、数段落までの短い文(チャットの返答、メール、1 つの節)。ファイルの文書や長い文書(目安: 3,000 文字を超える、`doc-writing` の `draft.md`)は、サブエージェント `polish` に任せる(検査の出力や資料を、子のコンテキストに閉じるため)。メインで使うときも、原文と最終稿は `.handoff/` のファイル(原文の写しは `.handoff/yomiyasu_<名前>_原文.md`、最終稿は `.handoff/yomiyasu_<名前>.md`。記録用の `.handoff/yomiyasu/` には置かない)に書いてから検査する。元の文書は書き換えない。

## 1. 最優先: 意味を保ち、足さない

直す前と後で、文ごとに次の 4 点が同じであること。1 つでも変わる案は捨てて、原文を残す。

1. **主張**: 何を言っているか。論点をすり替えない。
2. **比重**: 何を大事にし、何を否定しているか。否定していたものを並列(A に加えて B)や順位(A より B)にしない。
3. **言い切りの強さ**: 断定・推量・可能性、許可(〜してよい)・能力(〜できる)・義務(〜しなければならない)・保証(必ず)。強めも弱めもしない。
4. **文の働き**: 事実・意見・依頼や決まり・例え・皮肉・仮定・引用や伝聞。伝聞を断定に、意見を事実に、依頼を説明に、仮定を予定に変えない。完了した変更を予定の形にしない。

**足さない。** 根拠にしてよいのは、原文・依頼・渡された資料だけ(一般の知識や推測は使わない)。動作主・対象・原因・条件・数値・例・用語を作らない。ぼかした語を、より狭い具体的な事実に置き換えない。分からない所は直さず、「書き手に確かめたい点」に出す(本文に「要確認」などの注記を挟まない)。

**言い直しテスト**(型に当たった所を直す前に、案を 1 つ書いて原文と比べる): 何について述べるか / 何を認め何を否定するか / 誰が誰にするか / 範囲と条件 / 断定・推量・伝聞の強さ / 数値・固有名詞・時期。1 つでも変わるなら原文を残す(例と細部: `references/rephrase-test.md`)。

## 2. 直すもの(AI の文章に出やすい型)

| 型 | 直し方(細部: 元の手順書の節) |
|---|---|
| 主述のずれ、誰が何をするかの抜け | 原文・資料・前後の文から分かる主体と対象だけを補う。担当者を作らない。近くの名詞というだけで選ばない(「主語と目的語の明確化」、`references/gemini-syntax.md` 原則 1) |
| 擬人化(コードが語る、システムが願う) | 道具の働きの客観的な説明は残す。感情や意志を持たせた所だけ直す(「擬人化の解消」) |
| 比喩動詞(倒す、効く、溶かす、潰す、壊れる、静かに) | ふだんの言葉にする。**含み(うっかり、ようやく、〜てしまった)は残す**。強める語(確実に、劇的に)を足さない。定着した慣用句(骨が折れる)は残す(「比喩動詞の具体化」) |
| 前置きのラベル(重要なのは〜) | 評価を担うなら述語に移して残す(〜が重要です)。削るのは、削っても主張が変わらないときだけ |
| 否定対比(A ではなく B) | 意味を担う否定は残す。2 文に分けた否定対比は 1 文にまとめる(「セルフラベリングと否定対比の整理」) |
| 予告だけの文(次の点が挙げられます) | 予告の重みを残して、続く中身の文とまとめる。数の宣言と項目の数が合わなければ、変えずに確かめたい点へ |
| 言い終えた内容を繰り返す締め(まとめると〜) | 削る。その所にしかない数値・条件が無いかを先に確かめる。次の予定を述べる結びは残す |
| 大げさな名詞(契約、正本、ゲート、台帳、境界、仕組み) | 実際の役割の語(ルール、原文、確認、記録、一覧)にする。正式名称・専門用語の意味のときは残す |
| 詰めた漢語の句(設定変更後に) | 語を残したまま、助詞と動詞を補ってほどく(設定を変更したあとに)。定着した複合語は残す |
| 連用形の名詞(結果の確かめ) | 動詞の文に戻す(結果を確かめる)か、定着した漢語にする(結果の確認) |
| 間を作るだけの読点(応答は、〜 / 古いキャッシュが、〜) | 外す。長い主語・節のあと、並びの区切り、外すと掛かり先が変わる所は残す(「文長と読点の調整」) |
| コピー調(資料を、全員へ。/ 速い。軽い。安い。) | 対象と動作・評価を述語までつないで書く。対象が決まらなければ残す(「コピー調の抑制」) |
| 装飾(絵文字、文末のコロン、ダッシュ「──」、言い換えのカッコ) | 外す。ラベルと値のコロン(日時: 10 時)、罫線の図、引用は残す |
| 説明の文の前の太字ラベル(`**応答速度の低下**: …`) | ラベルとコロンを外し、意味を文に入れて 1 文にする。値の項目(状態: 対応中)は残す(「装飾記号の排除と太字の表示」) |
| 括弧に入れた手順(〜します(先にバックアップを)) | 括弧から出して、行う順に文で並べる |
| 表記 | 補助動詞と「事」「為」だけ、ひらがなにする(して下さい → してください、する事 → すること)。ほかの表記の揺れは直さない |

## 3. 直さないもの

- 数値、名前、日付、識別子、画面の項目名、コード、URL、表の項目名、API の名前・型・必須性。
- 引用(「」)、出典のリンク(`[[ノート]]`)、見出しと箇条書きの形、番号つきの手順、原文の記号(■ など)。文書の題名。
- 並列が明確で読みやすい箇条書き(地の文に戻さない)。自然にそろった文末。元から読みやすい文。
- 常体・敬体(指定が無い限り)。「未定」「調査中」と書かれた状態。
- 文書の種類ごとに当てない規則がある。種類を決めたら `references/doc-types/<種類>.md` を読む(manual: 番号つきの手順を地の文に戻さない。minutes: 見出しを直さない。formal: 正式な硬い語を残す。mail: 宛名・挨拶・署名を残す、など)。

## 4. 手順

**Step 1 文脈をつかむ。** 文書の種類(manual、minutes、proposal、incident、formal、mail、article、slides、pr、paper、essay、promo、script)、読者(expert / informed / general)、立場(勧め / 決まり / 説明)を、依頼から決める。分からなければ決めずに進む。立場で文末が変わる: 決まり(手順書・規程)は「〜します」「〜してください」、勧めは読み手への助言、説明は事実・結果。文書の主な用件と、段落ごとの話題を 1 行でつかむ(このメモは出さない)。ドメインの規則は `references/domains/`(tech、business、essay)。

**Step 2 書き直す。** 先に原文に lint をかける。候補は手がかりで、候補が 0 件でも本文を読んで 2 章の型を探す。型に当たった所は、言い直しテストを通った案だけを採る。直す所がほとんど無ければ、無理に書き換えない。

```
run.bat lint <原文> --doc-type manual
```

自分(AI)が書いた原稿で、比喩や誇張で中身が見えない所、数値・主語・条件の抜け、資料と食い違う値があるときは、`references/fact-recovery.md` を読む。

**Step 3 検査する。** 最終稿を原文と別のファイルに保存し、lint と差分をまとめて実行する(資料があれば `--material 資料` を足す。何個でも)。

```
run.bat check run --source <原文> --final <最終稿> --stance=決まり --doc-type manual --fact-gaps
```

出力の 1 行目に従う。出力の見方は `references/review-points.md`。

**Step 4 足したもの・削ったものを点検する。** 差分の候補を 1 つずつ見る: 言い回しの種類(依頼・義務・評価・可能)の増減、文の種類の変化、許可・能力・保証の変化、元にない語・消えた語、つなぎ言葉と指示語の指す先、条件・否定・並列・順序の範囲。ずれていれば元に戻す。**直すのは 1 回だけ。** 直したら Step 3 の `run` をもう一度実行し、その後は本文を変えない。

**Step 5 照合する。** 提出の直前に 1 回、`verify` を実行する。1 行目が「ハッシュが記録と合いました」を含むことを確かめる(合わなければ、検査の後に本文が変わっている)。

```
run.bat check verify --final <最終稿>
```

`run.bat` は、このスキルのフォルダにある(Mac・Linux は `run.sh`)。記録は、作業フォルダの `.handoff/yomiyasu/` に残る。標準入力(`--stdin`)とリダイレクトは使わない。

## 5. 返す形

```
### 書き直した本文
(ファイルに書いたときは、パスだけ)

### 変えたところ
- 元の表現 → 書き直し後(理由)   ※意味が動きやすい変更だけ、最大 5 件。無ければ「なし」

### 残したAIっぽいところ   ※意味や重みを担うので残したものがあるときだけ
### 書き手に確かめたい点   ※本文を確定するのに要るものだけ、最大 3 件
### 事実の確かめ           ※補った・直した事実の出典と、確かめられなかった点。無ければ出さない
### 確認の記録
- 場面: 種類 / 読者 / 立場(それぞれ「指定」か「推定」、決めていなければ「決めていない」)
- 実行した検査: lint、diff、資料との照合、最終稿の照合 のうち実行したもの
- 実行しなかった検査: (理由)
- (verify の出力の 2 行目をそのまま写す)
```

検査を実行したことは、意味が保たれたことや読みやすさの合格を示さない。「yomiyasu で整えた」と書くのは、実行しなかった検査が無いときだけ。
