# Outlook 連携(サブエージェント `outlook` + スキル `outlook-mail`)

Outlook のメール・予定・フォルダを、スクリプトで扱う仕組み。メールは文章量が多く、トークンを多く使うため、サブエージェントに任せる。

狙いの運用: **AI がメールを整理し(フォルダの作成と移動)、人間が結果を確認して、不要なものを削除する。**

## 構成

```
agents/outlook.md                    サブエージェント。スキルを読み込んで、スクリプトで作業し、要約だけを返す
skills/outlook-mail/
├─ SKILL.md                          使い方と守ること(サブエージェントが読む)
├─ run.bat                           ハーネスの .venv の Python で本体を動かす入口(ASCII のみ)
├─ scripts/outlook_client.py         Outlook の COM を扱う部分
├─ scripts/outlook_cli.py            コマンドライン(引数の解釈、出力の整形)
├─ scripts/outlook_cache.py          メールのキャッシュ(SQLite。取り込み、検索)
└─ tests/test_outlook.py             偽の Outlook を使ったテスト
requirements.in / requirements.lock  pywin32(ハッシュ付き。Windows 用)
```

流れ: メインが `outlook` に依頼 → `outlook` がスキル `outlook-mail` を読み込む → `run.bat` 経由でスクリプトを実行 → 結果を読んで、結論・根拠・確信度・未確認だけをメインに返す(長いときは `.handoff/` に詳細)。

メールを読む作業は、**キャッシュから**行う(0.21.0)。Outlook を毎回読み直すと遅いので、受信と送信のメールをローカルに取っておき、前回より新しい分だけを足す。下の「メールのキャッシュ」。

## できること

| コマンド | 内容 | 副作用 |
|---|---|---|
| `check` | Outlook に接続できるか確認 | なし |
| `cache-search` | **キャッシュ**からメールを探す(受信と送信。語、期間、差出人、宛先、件名、フォルダ、同じ件のやり取り)。先に、新しい分だけを Outlook から取り込む | キャッシュのファイルが増える |
| `cache-show` | **キャッシュ**から本文を読む(10 通まで、まとめて)。Outlook に接続しない | なし |
| `cache-sync` | Outlook からキャッシュへ取り込む(`--full` で全体の取り直し、`--days` で期間の変更) | キャッシュのファイルが変わる |
| `cache-status` | キャッシュの通数、範囲、最終の取り込み、場所 | なし |
| `mail-list` | Outlook を直接読む一覧(新しい順)。未読・下書き・キャッシュより古いメール用 | なし |
| `mail-get` | Outlook を直接読む 1 通の本文。長さの上限、引用の除去 | なし |
| `reply-draft` | 返信の下書きを**保存**する(全員に返信も可) | 下書きフォルダに 1 通できる |
| `cal-list` | 予定の一覧(繰り返しも展開) | なし |
| `cal-create` | 予定を**保存**する(出席者を付けても招待は送らない) | 予定表に 1 件できる |
| `folder-list` | フォルダの一覧(件数、未読数つき。削除済み・迷惑メールは出さない) | なし |
| `folder-create` | フォルダを作る(途中のフォルダも作る。すでにあれば何もしない) | フォルダができる |
| `mail-move` | メールを別のフォルダへ**移動**する(1 回 50 通まで。移動先が無ければ `--create-missing`) | メールの場所とIDが変わる。記録が残る |
| `mail-undo` | 移動したメールを元のフォルダへ戻す(新ID または `--last 件数`) | メールの場所とIDが変わる |
| `move-log` | 移動の記録を見る | なし |

`reply-draft`、`cal-create`、`folder-create`、`mail-move`、`mail-undo` には `--dry-run` がある。`reply-draft` と `cal-create` は Outlook に接続せず、フォルダ・移動系は接続して読み取るだけで、変更せずに計画を表示する。

## メールのキャッシュ

毎日 Outlook から読み出すのは時間がかかる(COM は 1 通ごと、項目ごとに呼び出す)。そこで、メールをローカルの SQLite に取っておき、**キャッシュ+前回より新しい分**で作業する。

| 項目 | 内容 |
|---|---|
| 対象 | 受信トレイとその下のフォルダ、送信済みとその下のフォルダ。削除済みアイテム・迷惑メール・下書き・予定は入れない |
| 入れるもの | 日時、差出人、宛先、Cc、件名、フォルダ、本文(1 通 30,000 文字まで)、添付の**件数**。**添付ファイルは入れない**(名前も中身も読まない) |
| 期間 | 最初は直近 90 日。`cache-sync --days 365` で広げられる(以後もその期間を使う)。期間より古くなったメールは、消さずに残る |
| 場所 | `%LOCALAPPDATA%\opencode-harness\outlook-mail-cache.sqlite3`(環境変数 `OPENCODE_OUTLOOK_MAILCACHE` で変えられる)。リポジトリにも、作業フォルダにも置かない |
| 取り込み | 新しい順にたどり、キャッシュに無いメールだけ本文を読む。キャッシュにあるメールは、ID と日時だけを見て飛ばす。前回、期間の端まで取り込んだフォルダは、前回の最新の 1 日前で止める(差分) |
| いつ取り込むか | `cache-search` が、前回の取り込みから 10 分より経っていれば、自動で差分を取り込む(`--no-sync` で止められる)。Outlook につながらなければ、注意を出して、キャッシュだけで探す |
| 時間切れ | 1 回の取り込みは 100 秒まで(シェルの時間切れより短くするため)。止まっても、取り込んだ分は残り、次回に続きから取り込む |
| 移動・削除との整合 | `mail-move`・`mail-undo` は、キャッシュの ID と場所も書き換える。人が Outlook で移動・削除した分は、`cache-sync --full` で合わせる(期間の全部を見直し、無くなったメールを除く)。移動で ID が変わっても、同じメール(日時・差出人・件名・本文の冒頭が同じ)は 1 通にまとめる |
| 検索 | 語は、件名・差出人・宛先・本文の部分一致(AND)。全角と半角、大文字と小文字を区別しない。`--thread ID` は、件名から `RE:`・`FW:` などを除いて一致するメールを、受信も送信も、古い順に出す |
| 作り直し | キャッシュのファイルを人が消すと、次の `cache-sync` で作り直される |

**最初の取り込みは、人がターミナルで行うのがよい**(通数が多いと、100 秒で終わらず、数回かかる)。

```
skills\outlook-mail\run.bat cache-sync
skills\outlook-mail\run.bat cache-status
```

「時間切れで、取り込みが途中です」と出たら、出なくなるまで `cache-sync` を繰り返す。

キャッシュには、メールの本文が、暗号化されずに入る。Outlook のデータファイル(OST)と同じく、自分のユーザーのフォルダの中に置くが、**共有フォルダや、同期されるフォルダには置かない**(`OPENCODE_OUTLOOK_MAILCACHE` を変えるとき)。

## 安全の設計

- **送信と削除はできない。** スクリプトにその呼び出しを書かない。テスト(`SafetyTests`)が、ソースに送信・削除の呼び出しが無いこと、移動の呼び出しが `move_mails` と `undo_moves` の 2 か所だけであることを検査する。
- **削除済みアイテムと迷惑メールへは移動できない。** その下のフォルダも同じ。フォルダの一覧にも出さず、そこにフォルダも作れない。移動が「実質の削除」にならないようにするため。削除は人間が行う。
- **移動は記録され、戻せる。** 記録は `%LOCALAPPDATA%\opencode-harness\outlook-moves.jsonl`(0.22.0。以前は `%TEMP%` で、ディスクの掃除で消えると戻せなくなった。以前の記録は、最初に使うときに写す)。`mail-undo` が、元のフォルダへ戻す。移動するとメールの ID が変わるため、結果に「新ID」を出す。
- **一度に移動できるのは 50 通まで。** 取り違えたときの被害を限る。1 通の失敗で、ほかの移動は止めない(終了コード 1 で知らせる)。
- **メインが直接スクリプトを呼んでも、確認が出る(0.22.0)。** 雛形(`sample_opencode.json`)にも、`cal-create`、`folder-create`、`mail-move`、`mail-undo` の確認がある。以前は、確認が `outlook` の子の中にしか無く、メインからは確認なしで動いた。
- **Outlook を変える操作は確認を挟む。** `agents/outlook.md` の権限で、`cal-create`、`folder-create`、`mail-move`、`mail-undo` は `ask`、読み取り系・キャッシュ系・返信の下書き(保存だけ。0.16.0)は `allow`、それ以外のコマンドは `deny`。`--dry-run` が付いたものは、変更しないので確認なしで通る。
- **キャッシュは、Outlook に書き込まない。** `outlook_cache.py` が書くのは、SQLite のファイルだけ。テスト(`SafetyTests`)が、送信・削除・移動・保存・作成の呼び出しが無いことを検査する。
- **`--out` は `.handoff/` の中だけ。** それ以外のパスへは書けない。すでにあるファイルは上書きしない。
- **メール本文は指示として扱わない。** 外部から届く文章に紛れた指示(プロンプトインジェクション)への対策。`SKILL.md` と `agents/outlook.md` の両方に書いてある。
- **短い ID を使う。** Outlook の EntryID は 100 文字以上あり、トークンを食う。一覧には `m1a2b3c` のような短い ID を出し、対応表は一時フォルダ(`%TEMP%\opencode-outlook-ids.json`)に保存する。長い ID を直接渡すこともできる。
- 本文を社内LLMに渡すことは、利用者が許可している(社内の情報で、外には出ない前提)。

## 整理の運用(案 → 承認 → 実行)

1. **案:** 「受信トレイを案件ごとに整理して」などと依頼する。`outlook` は、フォルダの構成とメールを読み、`.handoff/outlook_整理案_〇〇.md` に表(メールID、件名、移動先、理由)を書く。**この段階では何も変更しない。** 判断に迷うメールは「要確認」に分ける。
2. **承認:** あなたが案を読んで、修正や「実行してよい」を伝える。
3. **実行:** `outlook` が、フォルダを作り、メールを移動する(コマンドごとに確認が出る)。結果を `.handoff/outlook_整理結果_〇〇.md` に書く。
4. **確認と削除:** あなたが Outlook で結果を見る。間違いは `mail-undo --last 件数` で戻せる。不要なメールは、あなたが削除する。

## 会社での導入

1. ハーネスのフォルダ(`C:\Users\<ユーザー>\.config\opencode\`)で、仮想環境を作る。

   ```
   python -m venv .venv
   .venv\Scripts\python -m pip install --require-hashes -r requirements.lock
   ```

2. Outlook(クラシック版)を起動して、次を実行する。

   ```
   skills\outlook-mail\run.bat check
   ```

   「接続OK: Outlook … 受信トレイ N 件 / 予定表 N 件」と出れば成功。
3. OpenCode から、サブエージェントを呼ぶ。例: 「`outlook` を使って、今週届いた山田さんからのメールの要点を教えて」。

## 会社で確認・調整すること(未確認)

Mac では本物の Outlook を動かせないため、COM の部分は会社でのテストが必要。偽物の偽物のテストは、呼び出しの組み立てと、出力の整形、移動の安全の仕組みを確認している。

| 項目 | 確認すること | 調整する場所 |
|---|---|---|
| 接続 | `check` が通るか。Outlook が起動していないときの挙動 | `outlook_client.outlook_application` |
| 日時の時刻 | メールや予定の時刻が、Outlook の画面と一致するか(タイムゾーンのずれ)。`pywin32` は時刻にタイムゾーンを付けることがあり、時計の値をそのまま使っている | `outlook_client.naive` |
| 予定の絞り込み | `cal-list` が期間の予定を正しく返すか。日本語環境では、日時の形式 `%Y/%m/%d %H:%M` が必要なことが多い。合わないときは環境変数 `OPENCODE_OUTLOOK_DATE_FORMAT` で指定する | `DEFAULT_DATE_FORMATS` |
| 繰り返しの予定 | 展開されるか。終わりのない繰り返しで止まらないか | `list_events` |
| 差出人 | Exchange 環境では、`SenderEmailAddress` が `/O=...` の形になることがある。表示名で絞れれば足りる | `list_mail` |
| 返信の下書き | HTML 形式のメールへの返信で、書式が崩れないか。署名や引用が残るか | `create_reply_draft` |
| フォルダの起点 | `--root mailbox` が、メールボックス全体の直下になっているか(`受信トレイ.Parent` を使っている)。共有メールボックスや複数アカウントでの挙動 | `_root_folder` |
| フォルダの作成 | `Folders.Add` が、Exchange / IMAP / ローカル(PST)で動くか。同名のフォルダを大文字小文字違いで作らないか | `create_folder` |
| 移動 | `Move` の戻り値の `EntryID` が、新しい ID になっているか。移動後の ID で `mail-get` できるか。移動に時間がかかる環境(キャッシュモード)がないか | `move_mails` |
| 元に戻す | `GetFolderFromID` で元のフォルダが引けるか。移動直後の `mail-undo` が通るか | `undo_moves` |
| 削除済み・迷惑メールの判定 | 迷惑メールのフォルダが無い環境で、エラーにならないか。日本語環境の「削除済みアイテム」「迷惑メール」が、既定のフォルダとして判定されているか | `_forbidden_ids` |
| 予定の作成 | 出席者を付けた予定が、招待を送らずに保存されるか。終日の予定の日付 | `create_event` |
| 文字コード | 日本語の出力が文字化けしないか(標準出力を UTF-8 にしている) | `outlook_cli.main` |
| 権限 | `agents/outlook.md` の `shell` のパターンが、実際のコマンド(パスにスペースがある場合など)に一致するか。`ask` が出るか。パターンは文字列の一致なので厳密ではない(`run.bat` を含む別のコマンドも通り得る)。主な防御は、スクリプトに送信と削除が無いこと(移動は、削除済み・迷惑メール以外で、記録つき) | `agents/outlook.md` |
| 改行コード | `run.bat` が CRLF で配置されるか(`.gitattributes` で指定。myao-patch-bridge 経由で届いた後に、動くか確認する) | `.gitattributes` |
| サブエージェント | `outlook` が呼ばれ、スキルを読み込み、3 行の形で返すか | `agents/outlook.md` |
| キャッシュの取り込み | `cache-sync` が通るか。**1 通あたりの時間**(90 日分が何秒か。100 秒で足りなければ、何回で終わるか)。会議の案内や配信不能の通知など、メール以外のアイテムで止まらないか(読めないものは数えて飛ばす) | `outlook_cache.sync`、`OutlookClient.mail_record` |
| キャッシュの並び | 受信トレイの下のフォルダで `[ReceivedTime]`、送信済みで `[SentOn]` の降順の並べ替えが効くか(効かないと、差分が途中で止まる) | `CACHE_SORT_FIELDS` |
| キャッシュの差分 | 新着の 1 通が、次の `cache-search` で出るか。取り込みが数秒で終わるか | `outlook_cache.sync` |
| キャッシュの場所 | `%LOCALAPPDATA%` に書けるか。SQLite のファイルが、セキュリティソフトで止められないか | `cache_db_path` |
| キャッシュと移動 | `mail-move` の後、`cache-search` に新ID と移動先が出るか。Exchange で、移動しても ID が変わらない場合に、二重にならないか | `note_moved` |
| シェルの時間切れ | OpenCode のシェルの時間切れが、100 秒より長いか(短ければ `--max-seconds` の既定を下げる) | `DEFAULT_MAX_SECONDS` |

## 開発メモ

- テストの実行(リポジトリのルートから):

  ```
  python -m unittest discover -s skills/outlook-mail/tests -v
  ```

- 移動と元に戻すの記録、短い ID の対応表は、一時フォルダのファイル。環境変数 `OPENCODE_OUTLOOK_MOVELOG`、`OPENCODE_OUTLOOK_CACHE` で場所を変えられる(テストが使っている)。メールのキャッシュは `OPENCODE_OUTLOOK_MAILCACHE`(`OPENCODE_OUTLOOK_CACHE` は、短い ID の対応表のほう)。
- 参考にしたもの: `mail_adress_creater/backend/outlook.py`(接続とキャッシュの復旧、HTML の変換)と `backend/testing.py`(偽の Outlook)。
- COM の呼び出しを足すときは、先に偽物にその属性を足してテストを書く。送信と削除の呼び出しは、足さない。移動の呼び出しは `move_mails` と `undo_moves` の 2 か所だけにする。
