# ファイル操作の安全設計（ファイルが勝手に消えないこと）

本アプリのファイル操作（削除・移動・コピー・上書き・アップロード・保存）が守るルールをまとめます。
実装は `backend/app/services/` にあり、`backend/tests/test_file_safety.py` で各ルールをテストしています。

## 基本方針

| ルール | 内容 |
|--------|------|
| 削除はゴミ箱へ | ローカルの項目は必ずゴミ箱へ移動する。完全削除へは絶対に自動で切り替えない |
| 衝突したら何もしない | 移動先・コピー先に同名の項目があれば、上書きの確認が取れるまで何も変更しない |
| 移動元は確認してから消す | 別ドライブへの移動は、全ファイルのコピーと検証が終わってから移動元を削除する |
| 置き換えたものは退避 | 上書きで置き換えられる既存ファイルはゴミ箱へ退避する |
| 失敗したら元のまま | 途中で失敗・キャンセルした場合、移動元・元のファイルは残す |

## 削除（`services/deletion.py`, `services/trash.py`）

- **ローカル**: `send2trash`（Windows は `SHFileOperationW`）でゴミ箱へ移動する。フォルダは中身ごと1回で移動するため、ゴミ箱から階層を保ったまま元に戻せる。
- **ゴミ箱への移動に失敗した場合**: エラーを返すだけで、ファイルは残る。Windows ではロックが一時的な場合に最大約8秒リトライし、それでも失敗したらロック中のプロセス一覧（`locked_by`）を返す。画面ではプロセスを終了して再試行するかを確認する（同意した場合のみ終了する）。
- **ネットワークドライブ**: ゴミ箱が使えないため、利用者が削除を指示した項目のみ完全削除する。削除確認ダイアログにもその旨を表示する。ネットワークドライブの判定は次のとおりで、判定できない場合はローカル扱い（＝ゴミ箱）にする。
  - Windows: UNC パス（`\\server\share`）、または `GetDriveTypeW` が `DRIVE_REMOTE` のドライブ。ローカルの `D:` などは対象外
  - macOS / Linux: マウントテーブルの種別が `smbfs` / `afpfs` / `nfs` / `cifs` / `webdav` / `sshfs` など。USB メモリ等の外付けディスクは対象外

## 移動・コピー（`services/transfer.py`）

1. 移動先に同名の項目がある場合
   - `overwrite=false`（既定）: 何も変更せず「同名のファイルが存在します」エラーを返す。画面で上書きするか確認する。
   - `overwrite=true`（利用者が確認済み）: ファイルは既存のものをゴミ箱へ退避してから置き換える。フォルダ同士は**統合（マージ）**し、移動先にしかないファイルは残す。
2. 移動元と移動先が同じ場所の場合: 移動は何もしない（`skipped`）。コピーはエラー。
3. 自分自身の配下への移動/コピーはエラー（`/a/foo` → `/a/foobar` のような名前の前方一致は誤判定しない）。
4. **同じドライブ内で移動先が空いている移動**: `os.rename` で一瞬で移動する（データのコピーなし）。
5. **それ以外の移動**: 全ファイルを並列コピー → 1件ずつサイズ（チェックサム検証を有効にした場合は SHA256）を確認 → 移動元の全ファイルがコピー済みであることを再確認 → 移動元を削除。
   - 1件でも失敗・キャンセルした場合、移動元は一切削除しない。今回新規に作ったコピー先だけを片付ける。
   - コピー中に移動元へファイルが追加された場合も、移動元を残してエラーにする。
6. 結果は項目ごとに `{"path", "dest", "status": "success" | "error" | "skipped", "message"}` で返す。

### Undo（元に戻す）との関係

Undo 履歴には**実際に成功した項目だけ**を記録する（`frontend/src/utils/batchResult.ts`）。
失敗した項目まで記録すると、Undo で移動先に元からあった別のファイルを動かしたり削除したりしてしまうため。
Undo 用の単一移動（`POST /api/move`）も、戻し先に同名の項目があれば上書きせず 409 を返す。

## 書き込み（`services/fileio.py`）

- **ファイル保存（`/api/update-file`）**: 同じフォルダの一時ファイルに書いてから置き換える（アトミック書き込み）。書き込み途中で失敗しても元の内容は失われない。シンボリックリンクはリンク先を更新し、パーミッションも引き継ぐ。Windows で他アプリが開いていて置き換えできない場合のみ直接書き戻す。
- **アップロード（`/api/upload`）**: 同名ファイルは上書きせず「name (1).ext」の別名で保存し、レスポンスの `renamed` に記録する。
- **新規作成・リネーム**: 既存の項目は上書きしない。名前に `/` `\` を含むもの、`.` `..` は拒否する（別の場所への書き込みを防ぐ）。大文字小文字だけのリネームは可能。
- **設定ファイル・フォルダ履歴**: アトミック書き込み。保存中に異常終了してもファイルが壊れない。

## タイムアウトとの関係

移動・コピー・削除・保存・解凍は、クライアント側のタイムアウト（`apiTimeout`）の対象外。
途中で通信だけ切ると、サーバー側では処理が続いているのに画面では「失敗」と表示される食い違いが起きるため。
大量の項目は非同期モード（進捗モーダル）で実行する。
