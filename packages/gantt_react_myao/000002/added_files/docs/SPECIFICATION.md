# ガントチャートアプリケーション仕様書

この文書は、現在のコードの挙動をまとめた仕様書です。コードと食い違いがあればコードが正で、この文書を直します。
開発時のルール（起動方法・テスト・ディレクトリ構成）は、リポジトリ直下の `CLAUDE.md` を参照してください。

## 1. 概要

[myao9494/gantt_chart_myao](https://github.com/myao9494/gantt_chart_myao)（DHTMLX Gantt + Node.js）を、React + FastAPI + SQLite で作り直した個人用のガントチャートアプリです。

| 層 | 技術 |
| --- | --- |
| フロントエンド | React 19 + TypeScript + Vite、DHTMLX Gantt（ガントチャート）、Univer（Excel風グリッド）、PWA対応 |
| バックエンド | FastAPI + SQLAlchemy + SQLite（`backend/gantt.db`） |
| 連携する外部サービス（任意） | open-path API（ポート8001、ローカルファイルを開く）、Local-fulltext-search（ポート8079、同義語） |

画面は3つあり、URLで切り替えます。複数のブラウザタブで別々の画面を開いて並べられます。

| URL | 画面 |
| --- | --- |
| `/` | ガントチャート |
| `/grid` | グリッド編集（Univer） |
| `/api-guide` | APIガイド（AIや外部ツール向けのAPIリファレンスと簡易テスト実行） |

## 2. データモデル

### 2.1 タスク（`tasks` テーブル）

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | INTEGER PK | タスクID（自動採番。最大IDのタスクを消すと、その番号は再利用されることがある） |
| `text` | TEXT NOT NULL | タスク名 |
| `start_date` / `end_date` | TEXT NOT NULL | 開始・終了日時。`YYYY-MM-DD HH:mm:ss`（時刻は `00:00:00`） |
| `duration` | INTEGER | 期間（日数）。終了日 − 開始日、最低1 |
| `progress` | REAL | 進捗 0.0〜1.0。1以上が「完了」 |
| `parent` | INTEGER | 親タスクID。0 が最上位 |
| `kind_task` | INTEGER | 1: タスク、2: プロジェクト、3: マイルストーン（MS） |
| `owner_id` | INTEGER | 0: 自分、10: 待、20: サイン取、30: 他 |
| `sortorder` | INTEGER | 同じ親の中での並び順（小さい順） |
| `color` / `textColor` | TEXT | バーの色・文字色（`#RRGGBBAA`） |
| `ToDo` / `memo` | TEXT | 自由記述 |
| `task_schedule` | TEXT | スケジュール。1行1件の `YYYY-MM-DD テキスト`（→ 3.7） |
| `hyperlink` | TEXT | URL、またはローカルファイルの絶対パス |
| `folder` / `url_adress` / `mail` | TEXT | 旧システム互換の項目（画面からはグリッドでのみ編集可） |
| `edit_date` | TEXT | 編集した日付の履歴（カンマ区切り） |
| `is_pinned` | INTEGER | 固定（ピン留め）。1: 固定 |
| `created_at` / `updated_at` | TEXT | 作成・更新日時 |

外部キー制約はありません。親子関係の整合（子孫の削除など）はバックエンドの処理で保ちます。

### 2.2 リンク（`links` テーブル）

| カラム | 説明 |
| --- | --- |
| `id` | リンクID |
| `source` / `target` | 元タスクID / 先タスクID |
| `type` | 0: FS（終了→開始）、1: SS、2: FF、3: SF |

### 2.3 その他の保存先

| 保存先 | 内容 |
| --- | --- |
| `grid_tasks` / `grid_links` テーブル | グリッド編集のステージング（→ 4章）。`tasks` / `links` と同じカラム構成 |
| `backend/data/holidays.txt` | 休日。1行1日付（`YYYY-MM-DD`） |
| `backend/data/business_trips.txt` | 出張日。1行 `YYYY-MM-DD,種別`（`normal_trip` / `day_trip`） |
| ブラウザの localStorage | 表示設定（→ 8.1） |
| バックエンドのメモリ | 更新シーケンス、入力画面オープン要求（再起動で消える） |

### 3.3 左側タスクリストとタイムライン

- 左側は「Task name」（ツリー表示）と「owner」の2列。`Ctrl+B` または境界の ◀/▶ ボタンで表示/非表示を切り替えられます。
- 読み込み時はすべてのプロジェクトを開いた状態で表示し、今日の位置へスクロールします。
- タイムラインの表示範囲は今日の前後1年です。現在時刻に「Now」の縦線を表示します。
- 土日と休日はセルの背景色を変え、出張日は種別ごとの色で表示します（出張日が優先）。
- ツリーのアイコンは [Catppuccin-Perfect-Icons](https://github.com/thang-nm/Catppuccin-Perfect-Icons) を使います。

| 対象 | アイコン |
| --- | --- |
| プロジェクト（kind 2） | `folder_project`（開いていれば `folder_project_open`） |
| 子を持つタスク | `folder` / `folder_open` |
| リンクなしのタスク | `file` |
| リンクありのタスク | リンク先の拡張子で決まる（`.md` → `markdown`、`.pdf` → `pdf`、`.excalidraw` → `excalidraw` など。該当なしは `url`） |

タスクバーの表示:

| 種類 | バーの中 | バーの右側 |
| --- | --- | --- |
| プロジェクト | `[id]名前` | なし |
| タスク・マイルストーン | なし | `[id] 名前 > [親id] 親の名前`（親がなければ自分のみ） |

- `hyperlink` があるタスクは、上記のテキストがリンクになります（→ 3.8）。
- 固定（ピン留め）したタスクはバーの見た目が変わります。
- スケジュール（→ 3.7）はバー上に📌で表示します。
- タスク名などはHTMLとして解釈せず、文字どおり表示します。

マウス操作:

| 操作 | 動作 |
| --- | --- |
| バーをドラッグ / 端をドラッグ | 日程の移動 / 期間の変更 |
| バーの進捗つまみをドラッグ | 進捗の変更 |
| バーの端の丸からドラッグ | 他のタスクへリンクを引く |
| 左側リストの行をドラッグ | 並び替え・親の変更。複数選択中は選択したタスクをまとめて移動。閉じたプロジェクトの直下に落とすと、そのプロジェクトの子になる |
| ダブルクリック | 編集画面（Lightbox）を開く |
| Shift/Ctrl+クリック | 複数選択 |
| タイムラインの空き領域をドラッグ、または中ボタンドラッグ | 掴んでスクロール |
| マウスホイール | 縦スクロール |

### 3.4 検索とフィルター

フィルターの判定は `utils/filterUtils.ts` にあり、ガントチャートとグリッドで共通です。

- **タスク検索**: 空白（全角含む）区切りのAND検索。各語は「タスク名に含まれる」または「ID番号に含まれる」とマッチします。大文字小文字は区別しません。
- **同義語**: 検索語が同義語グループのいずれかの語と部分一致する場合、そのグループの全単語を検索対象に加えます。同義語は起動時にバックエンド経由で外部APIから取得し、取得できなければ通常の検索になります。
- **プロジェクト検索**: 名前またはID番号がマッチしたプロジェクトと、その先祖・子孫だけを表示対象にします。
- **親の表示**: タスク検索・固定・表示期間のいずれかで絞り込んでいるときは、条件に合うタスクの先祖も表示します（子が孤立しないように）。
- **表示期間**: 「今日以前」は開始日が今日以前のもの、「期間限定」は指定した範囲と期間が重なるものを表示します。
- 検索欄に入力すると、180ms 後に反映し、同時に「全て」「ALL」（完了済み・全期間も対象）に切り替えます。
- プロジェクトを右クリック →「フィルターに追加」で、そのプロジェクト名をプロジェクト検索に設定します。
- 大量データでも速いよう、フィルター変更時に表示対象のID集合を1度だけ計算し、行ごとの判定は集合の参照だけにしています。

### 3.7 スケジュール（📌）

- `task_schedule` に `YYYY-MM-DD テキスト` を1行1件で書くと、その日付のセル中央に📌を表示します。タスクの期間外の日付にも表示されます。形式に合わない行は無視します。
- マウスを載せると、日付とテキストを下向きのツールチップで表示します（時刻は表示しません）。
- 追加はモーダルで行います（日付は「前日」「今日」「基準日」「翌日」ボタンでも変更可）。同じ日付が既にあれば `, ` 区切りで追記し、日付順に並べ直します。
- 📌をドラッグすると日付を移動できます。別のタスクの行に落とすと、そのタスクのスケジュールへ移します。

### 3.8 ハイパーリンク

- `http://` / `https://` で始まるリンクはそのまま新しいタブで開きます。
- それ以外（ローカルの絶対パス）は、外部の open-path API `http://localhost:8001/api/fullpath?path=...` 経由で開きます。
- リンク先がObsidianホーム配下の場合は、開く前にバックエンドでパスを確認し、ノートがリネーム・移動されていればタスクIDで探し直してリンクを更新します（→ 5.1）。

### 3.9 休日・出張

- 休日は、土日と同じ背景色で表示します。右クリックメニュー、またはハンバーガーメニューの「休日・出張の追加」で追加・解除します。
- 出張日は「通常の出張（`normal_trip`）」と「日帰り出張（`day_trip`）」の2種類で、それぞれ別の背景色になります。同じ日付を再登録すると種別を上書きします。
- どちらもバックエンドのテキストファイルに保存します（→ 2.3）。読み込み時に重複を除いて日付順に整えます。

### 3.10 task自動移動

開始日が今日以前の未完了タスクを、期間（日数）を保ったまま移動します。

- タスク（kind 1）: 開始日を今日にする
- プロジェクト（kind 2）: 開始日を直近の月曜日にする
- 完了済み・固定（ピン留め）・マイルストーン・開始日が未来のものは動かしません

### 3.11 印刷モード

左側タスクリストを隠し、バーの中を空にして、バーの右側にタスク名だけを表示します。切り替え時に今日の位置へスクロールします。紙への印刷時はヘッダーを出力しません。

## 4. グリッド編集画面（`/grid`）

Excel風のグリッドでタスク・リンクをまとめて編集する画面です。

- **シート**: `Tasks`（タスクの全カラム）と `Links`。1行目はヘッダーです。
- **表示**: ヘッダーのフィルターをガントチャートと共有し、ツリー順（親の直下に子）で並べます。タスク名には、階層の深さ分の全角スペースと種類を表す絵文字を付けて表示します。開始日・終了日は年月日のみ、進捗は 0〜100(%) で表示します。
- **ステージング**: セルを編集しても本データにはすぐ反映されず、ステージングテーブルに保存されます。グリッド画面を開くたびに、ステージングは本データで初期化されます。
- **差分パネル**（左側）: 本データとステージングで値が異なるセルを一覧表示し、グリッド上でもそのセルを黄色で示します。
  - 差分を右クリック →「元に戻す」で、その1件だけ本データの値に戻します。
  - 「DBにアップロード」で、差分をまとめて本データに反映します。
- **日付と期間の連動**（バックエンドで補完）: 開始日または終了日を変えると期間を再計算し、期間だけを変えると「開始日 + 期間」で終了日を再計算します。
- 反映できるのは、既にあるタスク・リンクの値の変更だけです（行の追加・削除はできません。IDも変更できません）。
- タスク名のセルに表示している装飾（インデント・絵文字）は保存しません。
- 行の挿入・削除などで行とIDの対応がずれた場合は、別のタスクを書き換えないよう保存を止めて知らせます。

## 5. Obsidian連携・差分確認

### 5.1 Obsidianノートの作成とリンク

- 右クリックメニューの「Obsidian (O)」または `O` キーで、タスクのノートを作ります。
- 作成先: `{Obsidianホーム}/01_data/{YYYY}/{MM}/{DD}/{タスク名}【{id}】.md`（日付は作成日）
  - タスク名のうち、ファイル名に使えない文字（`\ / : * ? " < > |`）は `_` に置き換え、前後の空白は除きます。
  - 同名のファイルが既にあれば作り直さず、そのファイルをリンクします。
- 内容:
  ```markdown
  ---
  created: YYYY-MM-DD HH:mm:ss
  tags:
  ---
  ```
- 作成後、タスクの `hyperlink` にファイルの絶対パスを保存し、ノートを開きます。
- Obsidianホームが未設定の場合、バックエンドは環境変数 `OBSIDIAN_HOME` のパスを使います。
- **リンクの再解決**: ノートのファイル名を変えたり移動したりしても、ファイル名に `【{id}】` が残っていれば、リンクを開くときに Vault 内を探して `hyperlink` を更新します。

### 5.2 差分比較（過去のエクスポートとの比較）

ハンバーガーメニューの「差分比較」で、過去にエクスポートしたCSVまたはZIP（中のタスクCSVを使用）を読み込み、現在のタスクと比べます。

- 追加（現在だけにある）・削除（ファイルだけにある）・変更（同じIDで内容が違う）を一覧表示します。
- 比較する項目: タスク名、開始日、終了日、期間、進捗、親、種類、オーナー、色、メモ、リンク、スケジュール。既定では開始日・終了日を比較から除きます。
- タスクや変更項目を右クリック →「元に戻す」で、ファイルの内容に戻せます。

### 5.3 Obsidian VaultへのCSV定期保存

Obsidianホームを設定していると、アプリを開いたときと、開いている間30分ごとに、現在のデータを `{Obsidianホーム}/70_gantt_csv/` へ保存します。

| ファイル | 内容 |
| --- | --- |
| `gantt_tasks.csv` / `gantt_links.csv` | 最新のデータ（エクスポートと同じ形式） |
| `gantt_diff_summary.json` | 前回保存分との差分（追加・削除・変更の件数と一覧）と、その履歴 |
| `gantt_diff_summary.md` | 上記を読みやすくしたもの。新しい順に追記 |

前回保存分と内容が同じ場合は、ファイルを書き換えません。「差分サマリ」メニューで履歴を確認できます。
このCSVは、DBを壊したときの復元元にもなります（`backend/restore_from_csv.py`）。

## 6. CSVのエクスポートとインポート

**エクスポート**: `gantt_data_{日時}.zip` をダウンロードします。中身は次の2ファイル（BOM付きUTF-8）です。

```
gantt_tasks_{日時}.csv:
id,text,start_date,end_date,duration,progress,parent,kind_task,ToDo,task_schedule,folder,url_adress,mail,memo,hyperlink,color,textColor,owner_id,sortorder,edit_date,is_pinned

gantt_links_{日時}.csv:
id,source,target,type
```

**インポート**（データ読み込み）: 読み込んだファイルの内容で、テーブルを丸ごと置き換えます。

| 読み込むファイル | 置き換える対象 |
| --- | --- |
| CSV単体 | タスクのみ（リンクはそのまま残す） |
| ZIP（ファイル名に `task` を含むCSV） | タスク |
| ZIP（ファイル名に `link` を含むCSV） | リンク |

- 値を変換できない行はスキップし、件数と理由を結果に含めます。
- 空欄の項目は既定値（期間 1、進捗 0、親 0、種類 1 など）で補います。`is_pinned` 列がない古いCSVも読み込めます。
- 置き換えは一括で行い、途中で失敗した場合（IDの重複など）は元のデータを残してエラーを返します。
- UTF-8以外のCSVは読み込めません。

## 7. API

FastAPI の Swagger UI（`/docs`）でも確認できます。失敗時は HTTP ステータスと `{"detail": "..."}` を返します。

### 7.1 タスク

| Method | Endpoint | 説明 |

## 9. 設計メモ

### 9.1 画面とサーバーのデータ同期（ガントチャート）

DHTMLX Gantt は画面内に自分のデータを持つため、「サーバーのデータ（Reactのstate）」と「Gantt内部のデータ」を一致させ続ける必要があります。

- **Gantt上の操作 → サーバー**（`ganttEvents.ts`）: ドラッグ・編集・削除などはまず画面に反映され、Ganttのイベントから保存APIを呼びます。保存が失敗した場合は画面をサーバーの値へ戻し、エラーを表示します。
- **サーバー → Gantt**（`ganttSync.ts`）: データを取り直すたびに、前回反映した内容から変わったタスクだけを更新します（全体の作り直しはしません）。
  - 保存・削除・作成のAPIが応答待ちのタスクは、その間に別の再取得結果が届いても上書きしません（操作結果の巻き戻りを防ぐため）。
  - 同期による変更は、保存APIを呼び直さず、Undo/Redo の履歴にも残しません。
  - 一度に50件を超えるタスクが増えた場合（CSVインポートなど）だけは、全体を読み込み直します（開閉状態は保ち、Undo/Redoの履歴は消えます）。
- **Undo/Redo**: DHTMLX の Undo プラグインを使います。Undo/Redo による更新・削除・並び替え・リンク操作は、通常の操作と同じイベントで保存されます。削除のUndoなどでタスクが復活した場合は、同じIDのままバックエンドに作り直します。
- gantt はアプリ全体で1つのシングルトンです。`GanttChart` コンポーネントのマウント時に初期化とイベント登録を行い、アンマウント時に必ずイベントを解除してデータを消します（解除しないと、画面を切り替えて戻るたびに保存が多重に呼ばれます）。

### 9.2 自動更新

他のタブやランチャーなど外部からの変更を、開いている画面へ自動で反映する仕組みです。

- バックエンドは、タスク・リンクの作成/更新/削除、並び替え、複製、CSVインポート、グリッドのアップロードのたびに、メモリ上の「更新シーケンス番号」を1つ進めます。
- フロントエンドは2秒ごとに番号を確認し、前回データを取得したときの値から変わっていればデータを取り直します。バックエンドの再起動で番号は0に戻るため、大小ではなく「変わったかどうか」で判定します。
- 取り直しに失敗しても、表示中のデータは消さずにエラーを表示し、次の確認時に再試行します。

### 9.3 PWA

- `vite-plugin-pwa` で Service Worker と manifest を生成します。Univer を含むJSが大きいため、キャッシュ対象の上限を20MBにしています。
- `/api/` へのリクエストはキャッシュしません。

## 10. 既知の制約

- 個人利用を前提としており、認証はありません。CORSは無制限です。同じネットワークの他の端末からもアクセスできる設定で起動するため、信頼できるネットワークで使ってください。
- 複数のタブで同じタスクを同時に編集した場合は、後から保存した内容が残ります。グリッドのステージングは全タブで共有で、グリッド画面を開いたタブがあるたびに初期化されます。
- グリッドは、データや差分が変わるたびにシート全体を作り直します（スクロール位置と選択は保持されません）。
- 最大IDのタスクを削除すると、その番号が次に作るタスクに再利用されることがあります。Obsidianノートは `【id】` でタスクと対応付けるため、削除したタスクのノートが残っていると、同じ番号の新しいタスクに結び付くことがあります。
- 編集日の履歴（`edit_date`）は、画面が `YYYY-M-D`、バックエンドが `YYYY-MM-DD` の形式で追記するため、同じ日が2通りの表記で入ることがあります。
