# プロジェクト仕様書 (gantt_react_myao)

> 詳細な仕様書は `docs/SPECIFICATION.md`、開発ドキュメントは `docs/claude.md` を参照。

## 概要
Google Sheetsのような操作感を目指した、ReactとDHTMLX Ganttを使用したガントチャートアプリケーション。
フロントエンドにReact + Univer (Excelライクなグリッド)、バックエンドにFastAPI + SQLiteを使用。

## 仕様

### Obsidian連携
- **目的**：ガントチャートのタスクからObsidian上に直接ノートを作成し、リンクする
- **作成パス**：`{obsidian_home}/01_data/{YYYY}/{MM}/{DD}/{タスク名}【{id}】.md`
  - `obsidian_home` はハンバーガーメニューの設定画面から変更可能（`localStorage`に保存）
  - `/` や `:` などのファイル名に使えない文字は `_` に置換し、タイトル末尾の空白も除去する
- **ファイル内容（Frontmatter）**：
  ```markdown
  ---
  created: YYYY-MM-DD HH:mm:ss
  tags:
  ---
  ```
- **フロントエンド**：右クリックメニューに「Obsidian」を追加
- **連携動作**：
  1. API `POST /api/tasks/{task_id}/obsidian` をコール（`obsidian_home`をパラメータで渡す）
  2. バックエンドがノートファイルを生成し、`hyperlink` フィールドに「ローカルの絶対パス（生の文字列）」を保存
  3. フロントエンドのリンククリック時は、ポート `8001` で稼働している外部 de `open-path` APIを経由してファイルを開く

### グリッド編集と差分管理
- **ステージング管理**：グリッド（UniverSheet）上の編集は即座に本データに反映されず、ステージングテーブル（`grid_tasks`, `grid_links`）に保持される。
- **差分確認**：差分は大きく2種類存在する。
  1. ステージングデータと本データの差分：画面左上の差分パネル(`GridDiffPanel`)にリアルタイムで一覧表示される。
  2. 過去のエクスポートファイルとの差分：ハンバーガーメニューから「差分比較」ダイアログを開き、ローカルのCSVファイルまたはZIPファイルを読み込ませることで現在のタスク一覧と比較できる。ZIPの場合は中に含まれる `tasks.csv` を抽出し自動でパースする。
- **元に戻す (Undo)**：差分パネルの一覧で特定の差分項目を右クリックし「元に戻す」を選択すると、その変更のみを破棄し本データの値に戻すことができる。
- **一括アップロード**：確認後、差分を一括で本テーブルに反映（コミット）することができる。
- **期間と日付の自動計算**：グリッド上で「開始日」「終了日」「期間」のいずれかを単独で変更した場合でも、Ganttチャートでの描画との整合性を保つためバックエンド（`grid.py`）で不足している日付や期間が自動計算・補完されてからステージングに保存される。

### プロジェクトフィルターのクイック追加
- **目的**：プロジェクトの右クリックから即座にプロジェクト単位での絞り込み（フィルター）ができるようにする。
- **実装**：プロジェクト（`kind: 2`）を右クリックした際のコンテキストメニューに「フィルターに追加（検索アイコン🔍）」を追加し、クリック時にそのプロジェクトの名前を `searchProject` フィルターパラメータへ反映させて即座に絞り込みを行う。

### カレンダー日付右クリックによる休日追加・解除
- **目的**：ガントチャートのカレンダー日付部分から直感的に休日を追加・解除できるようにする。
- **実装**：
  - 上部のカレンダー日付ヘッダー（スケールセル）およびタイムライン背景（空き領域）を右クリックした際、クリック位置の日付（`YYYY-MM-DD`）を判定。
  - 未登録の日付であれば「休日を追加 (YYYY-MM-DD)」を表示し、クリック時に即座に `POST /api/holidays` で休日登録。
  - 既に登録済みの休日の場合は「休日を解除 (YYYY-MM-DD)」を表示し、`DELETE /api/holidays/{date}` で休日解除。
  - タイムライン背景の右クリックでは、従来の「新規プロジェクト追加」「新規タスク追加」に加えて休日操作項目を表示。

### 表示形式の調整
- **グリッド（UniverSheet）表示**：
  - 開始日・終了日のカラム表示から時刻を省き、「年月日（YYYY-MM-DD）」形式で表示するように変更。
  - ヘッダー含め全項目を中央揃えで表示する。
- **ガントチャート（GanttChart）表示**：
  - 開始日・終了日のカラムは不要なため表示しない。
  - スケジュールのピンアイコン（📌）の表示位置が前日にズレて見える問題に対応するため、1日分のセル幅をオフセットとして加算し、対象日の枠内に表示されるよう調整。
  - スケジュールのホバー時ツールチップから不要な時間情報(00:00:00など)を削除し、日付とテキストのみを表示するように変更。
  - スケジュールのホバー時ツールチップを上向き（bottom）から下向き（top）表示に変更し、一番上のタスクでもガントチャート上部で見切れないように改善。
- **タイムスケール（表示期間）のデフォルト設定**：
  - アプリ起動時のデフォルト表示を「月（month）」に設定（`localStorage` の初期値）。


### アイコン表示
- **ソース**：[Catppuccin-Perfect-Icons](https://github.com/thang-nm/Catppuccin-Perfect-Icons)
- **種類**：
  - **プロジェクト (kind: 2)**：`folder_project.svg`
  - **タスク (kind: 1, 3)**：
    - リンクあり：拡張子に応じたアイコン（`.md` -> `markdown.svg`, `.pdf` -> `pdf.svg`, その他 -> `url.svg` 等）
    - リンクなし：`file.svg`
- **実装**：Ganttの「Task name」列にアイコンを表示し、ツリーのデフォルトアイコンをこれらで置換する。

### 主な画面と機能ショートカットキー
- **Gantt チャート画面 (左側ツリー部分)**
    - `A`: タスクの追加 (選択中の要素がプロジェクトの場合は子階層に、タスクの場合はアクティブなタスクの直下に追加)
- **Gantt チャート編集 (Lightbox)**
    - `Enter`: 保存 (日本語入力の確定時は除く)
    - `Shift + Enter`: 改行 (テキストエリア内)
    - `Tab`: 次の入力項目へ移動
    - `Shift + Tab`: 前の入力項目へ移動
    - `Esc`: キャンセル

### データ同期
- タスクの追加・更新・削除、およびリンクの作成・更新・削除はバックエンドのデータベースと同期される。
- Undo/Redo をサポート（タスク・リンクの両方）。
- **タスク追加時のLightbox制御**：一般の追加時は自動表示を抑制しているが、ショートカット 'A' による追加時は即座に編集画面（Lightbox）を開き、迅速な入力作業を可能にしている。
- **タスク名の自動整形**：GanttやGrid等での操作に起因する不要なインデント（空白類）やアイコン（絵文字等）がDBに保存されるのを防ぐため、保存前にタスク名（textフィールド）の先頭にあるインデントや特定の絵文字を無視（自動除去）する処理を行っている。

### フィルタパフォーマンス最適化
- **問題**：タスク数が多い場合（数百〜数千件）、フィルタ適用時に`onBeforeTaskDisplay`内で各タスクごとに全子孫を走査するO(n²)のコストが発生し、Windowsで顕著に遅延していた。
- **対策**：`utils/filterUtils.ts`に事前計算ユーティリティを抽出し、フィルタ変更時に1度だけMap（インデックス）を構築。`onBeforeTaskDisplay`内ではO(1)のMap参照のみ行う方式に変更。また、DHTMLX API（`gantt.eachTask`など）への依存を排除し、純粋なJS配列（`tasks`）を活用することでDOM操作オーバーヘッドをなくした（数千件データでの右クリックフィルターが瞬時に反映されるよう改善）。
  - `buildChildrenMap`: 親ID→子タスク配列のMap構築
  - `buildDescendantMatchMap`: ボトムアップ方式の子孫マッチ事前計算
  - `buildAncestorMatchMap`: メモ化先祖マッチ計算
  - `buildTreeOrderFromMap`: Map参照による高速ツリー順構築
- **適用箇所**：`GanttChart.tsx`の`onBeforeTaskDisplay`（ガントチャートビュー）と`App.tsx`の`gridFilteredTasks`（グリッドビュー）の両方。

### 同義語検索
- **目的**：検索窓に入力した単語の同義語も合わせて検索できるようにする。
- **実装**：
  - ポート `8079` で稼働している外部の `Local-fulltext-search` API（`/api/index/synonyms`）から同義語グループリストを取得。
  - 検索キーワードがいずれかの同義語グループに含まれる場合、そのグループ内の全単語を対象にタスク名の部分一致（`includes`）チェックを行う。
  - 外部APIが利用不可な場合は通常の検索を継続する（フォールバック）。

### 自動更新 (Auto Reload)
- **目的**：ランチャー等からタスクが追加された際に、Gantt画面を開いているブラウザを自動でリロードして最新の追加タスクを表示する。
- **実装**：
  - バックエンドで更新シーケンス（インメモリの整数値カウンタ）を管理。
  - タスク・リンクの作成・更新・削除、CSVインポート、グリッドコミットなどのデータ変更時に、このカウンタをインクリメント。
  - フロントエンドは2秒間隔でシーケンス取得API (`GET /api/tasks/update-sequence`) をポーリングし、値に変化があった場合のみ自動でデータを再取得 (`fetchData`) する。

## 開発ノート
- **デプロイ・起動**:
  - `start_app.sh`: 本番ビルド(npm run build)を行い、FastAPIで静的ファイルを配信.
  - `start_dev.sh`: 開発モード。Frontend(Vite)とBackend(Uvicorn)を並行起動。
- **ビルドエラーの修正**:
  - `npm install` の不足を `start_app.sh` に追加して解決。
  - `syncToDatabase.test.ts` の定義不整合（COLUMN_DEFINITIONS名の不一致）を修正。
  - `UniverSheet.tsx` の未使用変数 `workbook` を削除。
- **PWA設定**:
  - Univer等の重いライブラリによる11MB超のJSファイルに対応するため、`vite.config.ts` の `workbox.maximumFileSizeToCacheInBytes` を 20MB に拡大。
  - `useLocalStorage`フックの`setValue`は関数型更新パターンで参照安定性を保つこと。`storedValue`を依存配列に入れると`setValue`が毎回再生成され、Gantt初期化useEffectが不必要に再実行される（PWAモードでのみ問題が顕在化）。
  - GanttChart.tsxのgantt初期化useEffectは`[timeScale]`のみに依存。コンテキストメニュー/キーボード用コールバックはrefパターンで間接参照し、初期化の不要再実行を防止。
- **テスト環境**:
  - ユニットテストには `Vitest` を使用。
  - ブラウザ環境のシミュレーション用に `jsdom` を導入。
  - バックエンドテストのSQLite接続を安定化（`setup_db` fixture 内で `app.dependency_overrides` の設定とクリーンアップを徹底し、テスト間の干渉を防止）。
  - **バックエンドテストの実行注意**: 
    - `pytest` を実行する際はモジュール解決のため、`PYTHONPATH=$(pwd)` を付与して実行すること。（例: `PYTHONPATH=$(pwd) uv run pytest`）
  - **データ保護と復元の徹底 (最重要)**:
    - AIエージェントがテスト（`pytest`）の実行や動作検証、負荷データ生成などによってSQLiteデータベース（`gantt.db` 等）のデータを書き換えたり消去したりした場合は、**作業終了時またはテスト終了後に、必ずデータを元の状態に完全に復元してください。**
    - **通常の復元フロー（優先）**: 検証やテストを実行する前に、必ず対象のデータベースファイル（`backend/gantt.db` 等）を一時的に別名で退避（コピー）しておき、検証完了後に必ずその退避ファイルを元の場所に書き戻して復元してください。これを通常のムーブとします。
    - **最終手段の復元フロー**: 万が一、退避ファイルからの復元が困難になった場合のみ、最終手段として復元用スクリプト（`python backend/restore_from_csv.py`）を実行し、バックアップ用CSVから最新データを復元してください。
- **Windows環境でのCSVエクスポート対策**:
  - `backend/main.py` のCSVエクスポートにおいて、Windows環境での改行コード自動変換（CRLFへの意図しない変換）を防ぐため、`newline=""` を指定してファイルを書き込む `_write_text_without_newline_translation` を適用。
- **UI更新**: ビューモード（ガント/グリッド）切替をヘッダー内のアイコンボタンに集約。

### 負荷テスト用データ生成
- **目的**：大量データ（3000件等）でのパフォーマンス検証用。
- **実行方法**：`python backend/generate_load_test_data.py`
- **内容**：
  - 既存のタスクとリンクを全削除した上で、ランダムな3000件のデータを生成。
  - 10個の「負荷テストプロジェクト」を作成し、その配下にタスクを分散配置。
  - 開始日・終了日・進捗率などはランダムに設定。
