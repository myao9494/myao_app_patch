# AI インプット (Chat AI Export) 仕様書

## 1. 概要
本機能は、ハイブリッド検索やベクトル検索の結果から、ユーザーが必要なファイルを選択し、ChatGPT や Claude 等の AI チャットにそのまま入力（コピペまたはファイルアップロード）できる**完全自己完結型 HTML ファイル**を生成する機能である。
外部リソースへの依存を排除し、画像や Excalidraw / draw.io 図面を Base64 インライン化することで、AI が視覚情報（図表・フローチャート・画面構成）も含めて完全にドキュメントを理解できるように設計されている。

## 2. 主な機能と構成

### 2.1 ドキュメント選択 & 抽出 (PoC 準拠リッチ UI)
- **拡張子フィルター (包含 & 除外)**:
  - 検索ボックスの右隣にメイン検索画面と同様の拡張子フィルター入力欄（`input.small-input.extension-filter-input`）を配置。
  - **既定値**: デフォルトで `md` が事前設定され、AIインプット画面表示時点で Markdown ファイルが優先的に候補対象となる。
  - スペースやカンマ区切りの複数指定（`md excalidraw`）、および先頭マイナスによる除外（`-png`, `-.jpg`）に対応。
  - メイン検索バーで拡張子が入力されていた場合はその値を引き継ぎ、未入力時はデフォルト値 `md` に自動フォールバック。
  - 候補ドキュメント取得APIの `types` パラメータへの受け渡しに加え、取得済み候補テーブルに対しても `filterSearchResultsByExtensions` によるリアルタイム動的フィルタリングを適用。
- **上部HTML作成ボタン**:
  - 候補選択後、画面最下部までスクロールすることなく即座にHTMLプレビューを生成できるよう、ステップ2（候補ノート選択）ヘッダー右側に目立つグラデーションスタイルの「🚀 AI用HTMLファイルを生成する ({selectedPaths.size}件)」ボタンを配置。
- **クリックで切り替え**: チェックボックス（とその周りのセル）を押すたびに選択・解除が切り替わる。行のほかのセルを押しても切り替わる。
- **ドラッグ範囲選択**: チェックボックスから押したままドラッグすると、押した行と同じ状態に通過した行をそろえる
  （未選択の行から始めれば連続選択、選択済みの行から始めれば連続解除）。
- **Shift + ドラッグ解除**: Shift キーを押しながらドラッグすると、始めた行の状態によらず連続で解除する。
- **検索結果連動 & パス直接追加**: 検索画面の上位結果だけでなく、手動でのファイルパス指定追加にも対応。
- **全選択 / 全解除**: 1クリックで候補を一括選択・全解除。
- **自動タイトル推定**: 選択されたドキュメントの共通パスやファイル名からエクスポートタイトルを賢く自動提案。
- **リアルタイムトークン数概算**: 選択ファイル群の合計文字数から AI の消費トークン（推定値）をリアルタイムに計算・警告表示。
- **除外キーワードの厳格適用**: 除外キーワードはファイル名に対する除外フィルタとして機能し、ファイル名（またはパス）に除外キーワードが含まれるファイル（例: `gantt_diff_summary.json` や `2026_gantt_diff_summary_v1.md` 等）を候補一覧や検索結果から自動的・確実に除外。


### 2.2 プロンプト設定
- **プリセットテンプレート（5種網羅）**:
  - `統合サマリー`: 提供された複数ドキュメントを統合した要約と論点整理を指示。
  - `課題・ToDo抽出`: ドキュメントから未解決の課題、アクションアイテム、ToDo を抽出。
  - `Q&A・質問応答`: 添付資料に基づき、前提知識なしでも正確に回答することを指示。
  - `コード設計・実装計画`: 仕様書に基づくシステム設計、データ構造、実装タスク分解を指示。
  - `差分・変更点分析`: 複数ドキュメント間やバージョン間の変更点・相違点を分析。
  - `カスタム`: ユーザー独自のプロンプトを自由に入力可能。

### 2.3 自己完結型 HTML 生成エンジンの仕様
1. **画像・図面インライン化 (Base64 Data URI)**:
   - Markdown やテキスト内の画像リンク（`![alt](path)`）を検出し、ローカルの画像実体（PNG, JPG, GIF, SVG 等）を Base64 Data URI に変換して `<img>` タグへ置換。
   - `.excalidraw` / `.excalidraw.md`: 描画シーンの SVG データを生成または埋め込み画像から復元し、SVG/Base64 として埋め込み。
   - `.dio` / `.dio.svg`: draw.io の XML/SVG データをそのまま SVG としてインライン展開。
2. **構造化ドキュメント**:
   - 先頭に AI 向けの `<system-instruction>` / プロンプトブロック。
   - 目次（Table of Contents）リンク一覧（指定されたドキュメント順序通りに #1, #2... とナンバリング）。
   - 各ドキュメントごとにメタ情報（ファイル名、パス、更新日、ファイルサイズ）を明記。
   - HTML レンダリング表示と、AI が直接テキスト解析できる `<details>` 内の Raw Markdown の両方を保持。
3. **スタイル & デザイン**:
   - Glassmorphism & モダンデザイン（CSS がすべて `<style>` にインラインで同梱）。
   - オフラインでも完全に閲覧可能（CDN や外部フォント、外部スクリプトを一切ロードしない）。

### 2.4 出力とデュアルタブ表示
- **デュアルタブ切替**:
  - `プレビュー`: 画面内のサンドボックス化された `<iframe>` で生成結果をリアルタイムプレビュー。
  - `HTML ソース`: 生成された生の自己完結 HTML コードを表示し、部分コピーや確認が容易。
- **HTML ダウンロード**: `.html` ファイルとしてローカルに保存（AI チャットへの添付ファイルアップロード用）。
- **クリップボードコピー**: HTML ソースをクリップボードにワンクリックコピー（プロンプト欄への直接貼り付け用）。

### 2.5 特大プレビュー & ファイル選択・順序並び替えモーダル
- **物理的フルスクリーン最大化表示 (`width: 100vw; height: 100vh; padding: 0;`)**:
  - 生成完了時に画面全体を余白なく使い切るフルスクリーンモーダル（100vw × 100vh）を自動起動。
  - 外枠の余白（backdrop padding）を完全ゼロ化し、大画面ディスプレイでも左右ペインの表示面積を極限まで拡大。
  - Esc キーまたは最上部ヘッダーの✕ボタンで安全に閉じる。
- **左右2カラム構成**:
  - **左側ペイン (プレビュー & ソース)**: iframe によるリッチ表示と HTML ソース表示をタブ切り替え可能。
  - **右側ペイン (対象ファイル選択 & ドキュメント表示順序並び替え)**:
    - 候補ドキュメント一覧を順序配列（`modalOrderedPaths`）に基づき表示。
    - **ドラッグ＆ドロップ（DnD）並び替え**:
      - 各行にドラッグハンドル（`⋮⋮`）を配置。HTML5 Drag & Drop によりアイテムを掴んで任意の位置へ直接ドラッグ＆ドロップ可能。
      - ドラッグ中の要素は半透明（点線枠）となり、ドロップ先ホバー時は青色インジケーター（発光ハイライト）が表示される。
      - ドロップ完了時にデバウンス（200ms）を挟んで自動的にバックエンド `generateAiHtml` が並び替え後の順序で再実行され、左側プレビューの目次およびドキュメント順序がリアルタイムに更新される。
    - **「▲」「▼」ステップ移動ボタン**:
      - 各行に順位番号バッジ（`#1`, `#2`...）および「▲（上へ移動）」「▼（下へ移動）」ボタンも併設。
      - 先頭要素の「▲」および末尾要素の「▼」は自動で disabled 制御。
      - ドラッグ操作だけでなく、確実な1ステップずつのクリック移動にも完全対応。
    - チェックボックスを外したファイルはHTML生成から除外され、チェックを戻すと元の順序位置で復帰。
- **ローカル保存 & 絶対パスのクリップボード自動格納**:
  - モーダル上部の「💾 HTMLを保存（パスをコピー）」ボタンを押下。
  - バックエンド `POST /api/export/ai-html/save` が OS のダウンロードフォルダ（`~/Downloads`）へ同名連番付きで直接書き込み。
  - 並び替えられた順序通りのHTMLファイルが保存される。
  - 保存されたローカルファイルの絶対パス（例: `/Users/.../Downloads/AI_Context_Document.html`）を返却し、フロントエンド側で `navigator.clipboard.writeText` により即座にクリップボードへ自動コピー。
  - ユーザーはそのまま外部 AI（ChatGPT、Claude、Cursor 等）の入力欄に `Command + V` でパスを貼り付けて参照させることが可能。




## 高速化: ファイル名索引と既定階層

- **既定のリンク展開階層**: topタグ付きノートは 2、それ以外は 1（`link_expander.TOP_TAG_DEFAULT_LINK_DEPTH`）。UI のノートごとの階層入力で変更できる。
- **ファイル名索引**（`app/vector/file_name_index.py`）: 画像・図面・リンク先ノート・メールが見つからないときの再帰探索は、
  書き出し（HTML / Markdown+画像 / リンク展開）1 回の間、根フォルダごとに 1 回だけ走査して結果を共有する。
  スコープ外では従来どおり見つかった時点で打ち切る。探索の優先順位（走査順で先のフォルダ、同一フォルダ内は候補順）は変えない。

## 段階別の所要時間ログ（遅い環境の切り分け用）

- 書き出し（HTML / Markdown+画像）ごとに、段階別の合計秒・回数・遅い上位 5 件を計測する（`app/vector/export_timing.py`）。
  段階: リンク展開 / ノート読み込み / 画像・図面の埋め込み・解決 / Excalidraw図面のSVG生成 / SVGラスタライズ / Markdown→HTML変換 /
  メールリンク探索・解析・描画 / 結合画像の生成 / フォルダ走査（索引作成・早期終了）。
- 集計は、書き出し応答の stats（`timings`）、INFO ログ、データフォルダの `export_timing.log`（追記）へ出す。出力内容は変えない。

### メール Cc 行除去の高速化（実測に基づく修正）

- 社内 Windows の実測で、メール描画が書き出し全体の約半分（25 通で 128 秒、1 通 47 秒）を占めた。
  原因は `strip_email_cc_lines`（HTML）の表の Cc 行用の正規表現が、Cc の無い表だらけの本文で `<tr>` ごとに文書末尾まで探して 3 乗で遅くなること
  （35 KB で約 30 秒）。
- 対応: Cc 見出しが 1 つも無い本文では除去用の正規表現を走らせない。表の Cc 行の除去は 1 つの `<tr>` の中だけに限る
  （以前は手前の行まで巻き込んで消すことがあった）。
- MSG 解析は、オープン・プロパティ取得・HTML 本文取得とデコード・HTML→テキスト変換・添付取得を段階別に計測する（`export_timing.log`）。

## 処理できないリンクを飛ばして出力を優先する（AI用HTML）

- 目的: 社内のネットワークドライブなどで 1 つの項目が終わらず、「AI用HTMLファイルを生成する」が返ってこない状態を避ける。
  まず出力を返し、詰まった箇所を一覧で見せて、順に対処できるようにする。
- `app/vector/export_guard.py` の時間制限スコープを `export_documents_to_html` が開く。スコープの中では、次の項目を 1 件ずつ
  別スレッドで処理し、制限時間（既定 10 秒、`item_timeout_seconds`）を超えたら待たずに飛ばす。止まったスレッドは放置する。
  - 選んだノート・リンク先ノートの解決と読み込み（`link_expander` / `html_exporter`）
  - 埋め込み画像・図面の解決（`figure_assets.replace_obsidian_image_embeds`）、図面ノートの画像化
  - リンクされたメールの解決（`email_links`）と、APPENDIX 用の解析・描画
  - ノート本文の Markdown→HTML 変換（時間切れなら元のテキストを `<pre>` でそのまま載せる）
- 項目が例外を出したときも飛ばして続ける。見つからない項目（選んだノート・リンク先ノート・`![[...]]` / `![...](...)` の画像・メール）も記録する。
  埋め込みでない `[[...]]` は通常のノートへのリンクでもあるため、画像として見つからなくても記録しない。
  リンク先が実在するフォルダ（ノートへのリンクではない）のときも記録しない。
- 時間切れのまま続いているフォルダ走査（ファイル名索引）があれば、同じフォルダの探索は重ねて走査せず、待たずに「見つからない」として返し、
  `folder_scan` として 1 度だけ記録する。
- 記録（`skipped_links`）: 種類（note / linked_note / image / figure / email / render / folder_scan）・対象・リンク元・
  理由（not_found / timeout / error）・詳細・秒数。同じ項目は 1 度だけ。
  `POST /api/export/ai-html` の応答、`export_timing.log` の末尾（「処理できなかったリンク: N 件」）、WARNING ログへ出す。
- 画面: プレビューの上と生成結果パネルに「⚠️ 処理できなかったリンク (N 件)」を、時間切れ → エラー → 見つからない の順で表示する。
  0 件なら出さない。HTML 本体には載せない（AI へのトークンを増やさない）。
- スコープの外（Markdown+画像の書き出し、`/api/export/resolve-links`）では従来どおり、制限時間なしでその場で処理する。

## 書き出し対象の拡張子（変換対象）

- `app/vector/export_document_reader.py` が対象文書の本文を読む。HTML 書き出しと Markdown+画像の書き出しで共通。
- 変換対象は `.md` / `.markdown` / `.txt`（UTF-8、読めなければ CP932）と、`.docx` / `.pptx`（`extract_text` による本文テキスト抽出。壊れたファイルは空文字）。
- Excel（`.xlsx` / `.xlsm`）・PDF・画像・メール・その他の拡張子は変換対象外。出力に含めず、文書数にも数えない。
  以前はバイナリを UTF-8 テキストとして Markdown 変換へ流しており、文字化けするうえ 1 ファイル約 10 秒かかっていた。
- リンク展開が辿るのは従来どおり `.md` / `.excalidraw.md` のみ。
