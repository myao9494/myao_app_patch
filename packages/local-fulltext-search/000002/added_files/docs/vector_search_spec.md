# ベクトル検索 & ハイブリッド検索 仕様書

## 1. 概要
本機能は、埋め込みモデル（Embedding Model）による意味・概念の類似度検索（Dense Retrieval）と、SQLite FTS5 による高速な全文キーワード検索（Sparse Retrieval）を融合したハイブリッド検索システムを提供する。
また、PoC (`PoC_lag`) の知見を活かし、Markdown 以外の全選択拡張子・全登録フォルダを対象とし、専門用語辞書（Glossary）による表記揺れ展開や、ノイズフロアカット・Dense/Lexical 複合ブーストを備える。

## 2. 検索方式と既定値

| 方式 | 識別子 (`search_type`) | 特徴 | 適用ユースケース |
| :--- | :--- | :--- | :--- |
| **ハイブリッド検索**（既定） | `hybrid` | キーワード完全一致と意味類似度を RRF ($k=60$) で合成 | 日常的な検索全般（見落とし防止と高精度順位を両立） |
| **ベクトル検索** | `vector` | 埋め込みベクトルのコサイン類似度で検索 | 言い換え、類義語、質問文、抽象的な概念検索 |
| **通常検索** | `keyword` | SQLite FTS5 による全文キーワード検索 | 特定の型番、英数字コード、完全一致テキスト検索 |

※ Web UI および API の既定値は必ず `hybrid` とする。

## 3. アーキテクチャ

```
[クライアント (Web UI / ランチャー)]
           │
           │ search(q, search_type="hybrid")
           ▼
[Search API (/api/search)]
           │
           ├─► search_type == "keyword" ─► [SearchService (FTS5)] ──────────────────┐
           │                                                                         │
           ├─► search_type == "vector"  ─► [VectorSearcher (FAISS)] ────────────────┤
           │                                                                         │
           └─► search_type == "hybrid"  ─► [HybridSearchService]                     │
                                                  │                                  │
                                     ┌────────────┴────────────┐                     │
                                     ▼                         ▼                     │
                            [SearchService (FTS5)]    [VectorSearcher (FAISS)]       │
                                     │                         │                     │
                                     └────────────┬────────────┘                     │
                                                  │ RRF 融合 (k=60)                   │
                                                  │ 一致バッジ & 核心文付与           │
                                                  ▼                                  ▼
                                        [SearchResultItem 一覧] ◄────────────────────┘
```

## 4. データモデルとストレージ
- **モデル配置**: `models/` ディレクトリ（例: `models/ruri-v3-30m`, `models/ruri-v3-310m`, `models/ruri-v3-70m`）。Git 管理からは除外。
- **ベクトルデータベース**: SQLite (`backend/data/vector_index_<model_name>.db`)
  - `documents`: ファイルパス、SHA256、mtime、サイズ、チャンク数
  - `chunks`: チャンク番号、見出し階層（パンくず）、本文テキスト、前後の文脈（prev/next_chunk_id）
  - `embeddings`: チャンクIDごとの float32 ベクトル BLOB
- **FAISS インデックス**: `faiss.IndexFlatIP`（正規化済みベクトルの内積＝コサイン類似度）により、数万件〜数十万件のチャンクを数ミリ秒で高速探索。

## 5. チャンキング仕様
- **Markdown ファイル**:
  - 見出し（H1〜H6）単位でのセマンティック分割。
  - フロントマター（YAML）やパンくず（`# 見出し1 > ## 見出し2`）のコンテキスト保持。
  - Obsidian wikilink (`[[リンク\|表示名]]`) の自動展開。
  - Excalidraw 描画バイナリ/JSON データの自動除去によるクリーンなテキスト抽出。
- **非 Markdown ファイル（PDF, Word, Excel, TXT, JSON, MSG 等）**:
  - 汎用テキスト抽出エンジン経由で本文を取得。
  - スライディングウィンドウチャンキング（既定 500 文字 / オーバーラップ 100 文字）。
- **画像・音声・本文なし拡張子（PNG, JPG, MP3 等）**:
  - ファイル名をテキストとして埋め込みベクトル化（例: `2026年度_予算計画書.xlsx` のファイル名から意味を捉えて類似検索可能）。

## 6. インデックス自動同期
- 全文インデックスの作成・更新完了時（`index_service._index_target`）に、連動して自動でベクトルインデックスの差分同期（`vector_state.sync_index`）をトリガー。
- ファイルの更新日時（mtime）および SHA256 ハッシュを比較し、変更のないファイルは走査・埋め込みをスキップして高速同期。

## 7. 類似語・専門用語の一元連携（Glossary）
- 専門用語辞書は個別の Excel ファイル管理を廃止し、検索ルール管理の `synonym_groups.txt`（形式: `用語1,用語2,... : 意味・解説`）を単一データソースとして一元統合。
- 意味検索（ハイブリッド / ベクトル / AIインプット）時は、`GlossaryDictionary` が `synonym_groups.txt` を自動ロードし、最長一致アルゴリズムでクエリから用語を検出して表記揺れ・意味展開に活用。
- 通常キーワード検索時はコロンより前の類似語のみを OR 展開に利用し、解説文は混入させない。
- 検索ルール管理画面での保存時（`PUT /api/index/settings`）に `vector_state.reload_glossary()` が連動実行され、ベクトル辞書も即座にホットリロード。

## 8. 一致理由バッジ & 核心文 (Salient Sentence)
- **一致理由バッジ (`match_source`)**:
  - `both`: キーワード検索とベクトル検索の両方で高順位ヒット（`🌟 両方一致`）
  - `vector`: ベクトル検索による意味的類似でヒット（`🔮 意味一致`）
  - `keyword`: キーワード完全一致でヒット（`🏷️ キーワード一致`）
- **核心文 (`salient_sentence`)**:
  - ヒットしたチャンクの文（句点区切り）のうち、クエリとのコサイン類似度が最も高かった一文を抽出し、検索結果カードにハイライト表示。

## 9. デスクトップランチャー連携
- **macOS Cocoa 版 (`NSPanel`)**:
  - 検索バー右上に `NSSegmentedControl`（🔀 ハイブリッド [既定] / 🔮 ベクトル / 🏷️ 通常）を常設。
  - 各結果カードに一致バッジおよび核心文を表示。
- **Python Flet 版**:
  - 検索欄の横にセレクトボックスを設置し、3方式を切り替え。一致バッジ・核心文を表示。
- **Windows WPF 版 (`MainWindow.xaml`)**:
  - 検索ボックス右側に `SearchTypeCombo` を設置し、API クエリパラメータ `search_type` を送信。
  - 検索結果カードにバッジおよび核心文を表示。

## 10. ベクトル管理画面 (PoC 同等以上の管理 UI)
- **モデル別ステータスバッジ**:
  - 超軽量（30M）、標準（70M）、高精度（310M）各モデルのインデックス済みドキュメント件数、DBファイルサイズ（MB）、未インデックス状態をカードヘッダーにバッジ表示。
- **差分インデックス更新 ⚡ vs 全件再インデックス 🔄**:
  - 更新ボタンを2つに明確分離。差分更新は mtime / sha256 比較で未変更ファイルをスキップし数秒で完了。
  - プログレスバー（アニメーション付き）と完了サマリー（新規、更新、スキップ、削除、所要時間、DBサイズ）を可視化。
- **類似語・専門用語の一元連携**:
  - ベクトル管理画面内の個別辞書エディタは廃止し、「検索ルール管理」の「類似語・専門用語リスト」へ一元化。ヘッダーに検索ルール管理への連携案内バッジを表示。
- **単一ファイル差分更新ベンチマーク**:
  - ファイルパス入力と意地悪テスト用プリセット4種（長文、空、記号・HTMLタグ、見出し多用）を提供。
## 11. 除外キーワード（Exclude Keywords）のファイル名適用
- **ファイル名に対する除外フィルタ**:
  - 除外キーワードは文書本文（中身）ではなく、ファイル名（またはパス）に対する除外フィルタとして機能する。
  - 通常検索（FTS5）、ベクトル検索（`v_res.results`）、ハイブリッド検索（`final_items`）のすべてにおいて、ファイル名（またはステム）に除外キーワードが含まれるファイル（例: `gantt_diff_summary.json` や `2026_gantt_diff_summary_v1.md` 等）を完全に除外。
- **誤除外防止（記号/単語境界ガード）**:
  - `old`, `env`, `bin`, `git` などの4文字以下の短い英数字キーワードについては、`older.md`, `environment.md` 等の通常ファイルへの過剰除外を防ぐため、記号/単語境界でのみ一致判定する。

## 12. モデル切替とインデックス開始の堅牢性
- **モデル未指定・変更時の自動ロード連動**:
  - UI上でモデルカードを選択後、明示的な「モデルをロード」ボタンを押下せずに「⚡ 差分更新」や「🔄 全件再作成」を開始した場合でも、選択されたモデルが未ロードあるいは現在と異なるモデルであれば、自動的に対象モデルのロードを実行してからインデックス処理を開始する。
  - API エンドポイント `POST /api/vector/index/start` は `model_path` を受け付け、指定モデルが未ロードであれば自動でロードした上でインデックス同期を実行する。
- **対象フォルダ未指定時のフォールバック**:
  - `target_folders` がリクエストに含まれない場合、DB（SQLite）の `targets` テーブルから現在有効なローカル検索対象フォルダ群を自動で抽出し、安全に全件を対象としてインデックス作成を開始する。

## 13. アクティブ（稼働中）モデルの視覚的強調ハイライト
- **稼働状態の最優先可視化**:
  - 現在バックエンドでロードされ検索・インデックス処理に利用可能なモデルカードに対し、発光枠線（`boxShadow`）、背景色強調、および「🟢 稼働中 (アクティブ)」バッジを付与。
  - 画面表示時やモデルロード時に、稼働中のモデルタイプ（`ruri-v3-310m` なら標準モデル、`ruri-v3-30m` なら超軽量モデル）へ選択状態を自動同期し、非稼働モデルの誤ハイライトを完全に排除。
- **選択状態（切替準備）との明確な区別**:
  - ユーザーが未ロードのカードをクリックした際は「👉 選択中 (未ロード)」バッジおよび点線枠線を表示し、ロードボタンを「🚀 選択したモデルをロードして切替」に更新して直感的なモデル切替操作を支援する。

## 14. インデックス作成中のリアルタイム状態可視化
- **初回ロードからの自動検知**:
  - `refreshData()` 内で `fetchVectorIndexProgress()` を初期取得し、画面を開いた時点で既にバックグラウンドでインデックス処理が実行中であっても即座に検知して 800ms 間隔の定期ポーリングを開始する。
- **画面全体のマルチインジケーター**:
  - **ページヘッダー**: タイトル横に「🔄 ベクトルインデックス作成中... (XX%)」の発光バッジを表示。
  - **インデックス管理パネル**: 発光アクセント枠線（`boxShadow`）および「🔄 インデックス同期中」バッジを表示。
  - **稼働中モデルカード**: 稼働中バッジ内に「🔄」スピナーを表示。
  - **操作ボタン**: 実行中のボタンがローディング表示となり、ボタンの二重押下を排他ガード。

## 15. モデル選択の永続化 (`config.json`) とサーバー起動時自動復元
- **モデル選択の自動保存 (`config.json`)**:
  - ユーザーがモデル（超軽量 `ruri-v3-30m` / 標準 `ruri-v3-310m` 等）を選択またはロードすると、`VectorState.save_model_selection()` により `backend/data/config.json`（またはルート `config.json`）へ選択モデルのパス・モデル名・更新日時が即座に記録される。
- **サーバー起動時（Lifespan）の自動ロード**:
  - FastAPI の起動時コンテキスト（`lifespan`）にて `vector_state.load_saved_model()` が呼び出され、`config.json` に記録された前回のモデルを自動的にバックグラウンドロードする。
  - 設定ファイルが存在しない場合や無効なパスの場合は、規定の超軽量モデル（`ruri-v3-30m`）へ安全にフォールバックする。
- **即時検索の保証（ノンストレス運用）**:
  - サーバー再起動直後であってもユーザーが設定画面を開いてモデルをロードする必要はなく、最初から前回使用していたモデルでハイブリッド検索・ベクトル検索・AIインプットが即座に機能する。
- **UI連携**:
  - ベクトル管理画面のモデル選択カード下部に、現在記憶されているモデル情報（`config.json` の内容）をインライン表示し、ユーザーが永続化状態を把握できるようにする。

## 16. デバイス自動検出 & GPU加速 (MPS / CUDA) と CPU フォールバック
- **デバイス優先判定**:
  1. 環境変数 `VECTOR_DEVICE`（明示指定がある場合は最優先）
  2. NVIDIA CUDA (`torch.cuda.is_available()`): Windows RTX A500 等で自動適用
  3. Apple Silicon Metal (`torch.backends.mps.is_available()`): Mac 環境で自動適用（実測で CPU 比約 7.2 倍高速化）
  4. CPU: 非対応環境、初期化エラー、OOM 発生時等の自動フォールバック先
- **自己修復・フォールバック機能**:
  - モデルロード時（`Embedder.__init__`）やエンコード推論時（`encode`, `encode_batch`）に、万一 GPU ドライバ異常やメモリ不足（OOM）が発生した場合、プロセスを終了させずに自動的に `self.device = "cpu"` にフォールバックして処理を継続する。
- **バッチ処理最適化**:
  - GPU の高い並列演算性能を引き出すため、最適なバッチサイズで一括エンコードを実施。
- **ステータス API と UI 可視化**:
  - `GET /api/vector/model/status` に `device`, `device_name`, `cuda_available`, `mps_available` を追加。
  - ベクトル管理画面のヘッダー最上部に常時表示のデバイスバッジ（`⚡ GPU稼働中: Apple Silicon (Metal)` / `⚡ GPU稼働中: NVIDIA RTX A500 (CUDA)` / `💻 CPU稼働中 (フォールバック)`）とデバイス名を表示。
- **Windows NVIDIA GPU (RTX A500) 向けセットアップ環境**:
  - `backend/requirements-cuda.txt`: PyTorch 公式の CUDA 12.4 対応 wheel を自動解決してインストール。
  - `setup_windows_cuda.bat`: 仮想環境作成から CUDA 版 PyTorch インストール、GPU 動作検証までをワンクリックで実行可能。
  - `start_windows.bat`: 起動時に現在の実行環境（CUDA or CPU）をコンソール上に表示。

## 17. FAISS 高速エンジンと NumPy 自動フォールバック（未導入時のUI可視化）
- **高速ベクトル検索エンジン (`FAISS`)**:
  - `faiss-cpu`（または `faiss-gpu`）がインストールされている場合、`FaissVectorIndex` は `faiss.IndexFlatIP`（正規化済みベクトルの内積計算）を用いて数万〜数十万件のチャンクを数ミリ秒で検索する。
- **NumPy 自動フォールバック (`FaissVectorIndex`)**:
  - 一部の Windows 環境や Python バージョンで prebuilt wheel が提供されていない場合や、オフライン環境等で FAISS がインストールされていない場合でも、プロセス起動を阻害しない。
  - `import faiss` 失敗を安全に捕捉し、`HAS_FAISS = False` を検出。
  - FAISS 未導入時は、NumPy の行列内積計算（`np.dot`）および `np.argpartition` による上位 K 件探索へ自動でフォールバック。計算結果は FAISS と完全に等価であり、動作が保証される。
- **API および UI での稼働状態可視化**:
  - `GET /api/vector/model/status` に `has_faiss: bool` を追加。
  - **ベクトル管理画面の最上部ヘッダー**: 稼働デバイスバッジの横にベクトルエンジンバッジ（`⚡ エンジン: FAISS (高速)` または `⚠️ エンジン: NumPy (フォールバック / faiss未導入)`）を常時表示。
  - **モデル選択カード**: 右上バッジ群にエンジン状態を表示。
  - **インストール案内バナー**: `has_faiss === false` の場合、モデル設定パネル内に `pip install -r backend/requirements.txt` または `pip install faiss-cpu` の手順を記した警告ガイダンスバナーを表示し、導入方法を一目で把握できるようにする。

## 18. インデックス対象拡張子の連動適用（検索ルール管理との統合）
- **対象拡張子の設定連動**:
  - 「検索ルール管理」画面の「インデックス対象拡張子」カードで保存された選択拡張子（`index_selected_extensions`）および追加拡張子（`custom_content_extensions`, `custom_filename_extensions`）を、ベクトルインデックス作成（`VectorIndexManager`）へ自動適用。
  - ユーザーがチェックを外した拡張子のファイルはベクトルDBの走査対象から完全に除外され、不要な埋め込み計算やストレージ消費を防止する。
  - 追加した本文用拡張子（`.py` 等）は汎用テキスト抽出エンジン経由で本文チャンクが生成され、追加したファイル名のみ拡張子はファイル名テキストとしてベクトル化される。
- **検索時の拡張子フィルタ適用**:
  - 検索リクエスト（`extensions` または `index_types`）で拡張子が指定されている場合、キーワード検索だけでなくベクトル検索結果（`v_res.results`）に対しても同一の拡張子フィルタリングを適用し、指定外拡張子の結果を除外する。
