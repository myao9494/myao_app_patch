# デスクトップランチャーの単一インスタンス管理 & トグル動作安定化

## 1. 背景と課題
デスクトップランチャー（macOS Cocoa / Windows WPF / Linux Flet）は、OS全体のグローバルホットキー（`Command + Option` など）によって呼び出され、検索やメモ追加を素早く行うための常駐ツールです。

しかし、以下の問題が発生していました：
1. **プロセスの多重起動**:
   - バックエンドの再起動やリロード、開発環境（`start_dev.sh`）の実行に伴い、古いランチャープロセスがバックグラウンドに残存。
   - 結果として、同一のランチャーが **5プロセス以上多重起動** し、修飾キーの押下イベントを互いに競合して奪い合っていた。
   - また、全く同一の画面座標に複数枚のパネルが重なって表示されるため、1枚が非表示になっても背面のパネルが見えたままとなり、「`Command + Option` を押しても消えない」という不具合が発生。
2. **Escape キーの捕捉漏れ**:
   - 入力フィールドにフォーカスがあるときだけ Escape キーが効き、ボタンやセグメントコントロールにフォーカスがある場合はパネルが閉じられなかった。
3. **ホットキー判定フラグの非同期**:
   - パネル非表示時に `hotkey_activated` フラグが残存し、次回の押下判定が不発になる可能性があった。

---

## 2. 解決策と実装アーキテクチャ

### 2.1 単一インスタンス（Single Instance）ガード
ランチャー起動時のエントリーポイント（`launcher/src/launcher_app/main.py`）において、OSネイティブの排他ファイルロックを取得します。

- **macOS / Linux**: `fcntl.flock(fd, fcntl.LOCK_EX | fcntl.LOCK_NB)`
- **Windows**: `msvcrt.locking(fd, msvcrt.LK_NBLCK, 1)`
- **動作フロー**:
  1. プロセス起動時に一時ディレクトリ内の `local_fulltext_search_launcher.lock` に対して非ブロッキング排他ロックを試行。
  2. 既に別のランチャープロセスが稼働している場合はロック取得に失敗。
  3. ロック失敗時はログを出力し、二重起動せずに直ちに `sys.exit(0)` で正常終了。
  4. プロセス終了時（`atexit`）にロックを自動解放。

```
[Launcher 起動要求]
       │
       ▼
[ロック取得試行 (fcntl / msvcrt)]
       │
   ┌───┴───┐
   │ 成功  │ 失敗 (既に起動中)
   ▼       ▼
[UI起動]  [警告ログ出力 & 即座に exit(0)]
```

### 2.2 Escape キー全域捕捉 (Full-Scope Escape Handling)
Cocoa ネイティブ版（`LauncherPanel.keyDown_`）において、キーイベントを最優先で直接判定します。

- キーコード 53（macOS の Escape）または `\x1b` を捕捉。
- フォーカスが検索欄、拡張子欄、Web GUI ボタン、gantt チェックボックス、セグメント、結果カードのどこにあっても必ず発火。
  - **gantt メモ画面表示時**: 検索画面へ復帰（`delegate._switch_screen("search")`）。
  - **検索画面表示時**: パネルを確実に非表示化（`delegate.hide_panel()`）。

### 2.3 ホットキー押下中の誤再トリガー防止 & トグルクールダウン
ユーザーが `Command + Option` を押してパネルを非表示にする際、指がキーを押している時間（約150ms〜300ms）の間に watchdog（80ms毎）や `CGEventTap` が「まだキーが押されている」と再検知することがあります。
もし非表示時にフラグをリセットしてしまうと、「キーが押された」と誤認されて即座に再表示されてしまいます（これが「消えた瞬間、もう一度出る」現象の原因）。

そのため、以下の二重防御を採用しています：
1. **キー解放時（Release）のみリセット**:
   - `hotkey_activated` は `hide_panel()` でリセットせず、ユーザーがキーから指を離した時（`active == False`）にのみ `False` にリセットします。キー押し下げ中はどれだけイベントが来ても再トリガーされません。
2. **350ms トグルクールダウン**:
   - `toggle_panel()` に 350ms の最小呼び出しインターバルを設け、短時間のチャタリングやイベント重複による点滅動作を物理的に遮断します。

### 2.4 開発スクリプトのクリーンアップ強化 (`start_dev.sh`)
開発環境で `start_dev.sh` を実行する際、ポート 8079 を LISTEN しているプロセスの停止に加え、残存している `launcher_app.main` を `pgrep` で検知し、確実に終了（SIGTERM → SIGKILL）させる `kill_launcher` 関数を組み込みました。

## 3. テストと検証
以下の自動テストによって挙動を保証しています：
- `launcher/tests/test_single_instance.py`:
  - ロック初回取得の成功
  - 多重ロック試行時の失敗
  - ロック解放と再取得
  - 別インスタンス稼働時の `main()` 即時終了（exit 0）
- `launcher/tests/test_native_mac_escape.py`:
  - 検索画面における Escape キー押下時の `hide_panel()` 発火
  - メモ画面における Escape キー押下時の検索画面復帰
  - `hide_panel()` 呼出時の `hotkey_activated = False` リセット保証
