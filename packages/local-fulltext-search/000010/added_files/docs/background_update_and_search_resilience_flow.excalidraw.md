# Excalidraw Data

## Text Elements
バックグラウンド更新時のベクトル同期連動 & 検索時409耐性フロー ^title
① ファイル名変更 / 新規作成 / 更新 ^step1
OSのファイルシステムでファイルがリネームまたは更新される ^step1-desc
② OS変更通知（FSEvents / USN / ReadDirectoryChangesW） ^step2
対象パスを含む登録ターゲットを dirty 化 (target_change_states.is_dirty = 1) ^step2-desc
③ dirty_refresh_worker（バックグラウンドワーカー） ^step3
2秒のデバウンスを経て静まった対象を1件ずつバックグラウンド差分走査 ^step3-desc
④ 全文検索 & ベクトルインデックスの連動同期 ^step4
IndexService(connection, enable_vector_sync=True) を実行 ^step4-desc
・SQLite / FTS5: 旧ファイル削除(クリーンアップ) & 新ファイル登録 ^step4-fts
・Vector DB: vector_state.sync_index() が自動実行され差分更新 ^step4-vec
⑤ ユーザーからの検索リクエスト（macOS / WPF ランチャー等） ^step5
バックグラウンド更新中にユーザーが検索バーに入力 ^step5-desc
⑥ 409 Conflict（Indexing is already running）のハンドリング ^step6
同期更新実行時に 409 Conflict を検知 ^step6-desc
【耐性フォールバック】例外で落とさず安全に continue ^step6-fallback
同期更新をスキップし、既存インデックスから即座に検索結果を返答（フリーズ防止） ^step6-result
