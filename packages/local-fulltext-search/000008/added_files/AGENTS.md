# Local Fulltext Search - 開発仕様書

## プロジェクトの目的
ローカル環境にある文書・設定・図表ファイル(`.md`, `.json`, `.txt`, `.xml`, `.pdf`, Office, `.msg`, `.excalidraw`, `.dio`)を高速に全文検索し、画像・音声など本文抽出しないファイルはファイル名検索で補助するためのアプリケーション。

## 開発ルール

### Test-Driven Development (TDD)
- 原則としてテスト駆動開発 (TDD) で進める。
- 期待される入出力に基づき、まずテストを作成し、テストの失敗を確認してから実装を行う。

### コメント・仕様の記述
- 各ファイルの冒頭や主要な関数の前には、日本語のコメントで仕様を明確に記述すること。
- （例）
  ```typescript
  /**
   * 2点間のユークリッド距離を計算する
   **/
  ```

### ドキュメントについて
- コアな仕様はこの `AGENTS.md` に簡潔にまとめる。
- 新規のドキュメントは `docs/` フォルダの中に作成し、コードの変更に合わせて常に最新化する。
- 構成図などが必要な場合は、Excalidraw 形式で作成・更新する。

## UI・デザインの仕様

### ダークモード & モダンデザイン
- **テーマ**: ダークモード (`#0f172a` ベースのネイビー/ブルー系)
- **Glassmorphism**: 主要コンポーネント（カードやサイドバー等）の背景半透過 + `backdrop-filter: blur(16px)` を利用して、背後のオブジェクトが透ける美しい表現を採用する。
- **アクセント**: 視認性の高いフューチャリスティックなブルー（`hsl(217, 91%, 60%)`）をプライマリカラーとし、洗練された印象を与える。
- **インタラクション**: 各ボタンやカードがホバー時になめらかに浮き上がる (translateY) 等、動的で触り心地の良いマイクロアニメーションを取り入れる。
- **タイポグラフィ**: `Inter` などのクリーンな Sans-Serif フォントを使用。
- **ファイル種別アイコン (Catppuccin)**: 検索結果の種別・拡張子ごとに統一された Catppuccin スタイルのアイコンを表示する。`.msg` / `.eml` には専用のメール（封筒）アイコン（`email.svg` / `email.png`、カラー: Catppuccin Blue `#1E66F5`）を表示し、Webおよび各ネイティブランチャーで共通適用する。

## パフォーマンス最適化

### インデックス作成
- **バッチ commit**: ファイルごとの commit を廃止し、100件ごとのバッチcommitで I/O 削減。
- **os.scandir 走査**: `rglob` の代わりに `os.scandir` で再帰走査。除外ディレクトリの子ディレクトリに入らない。
- **エントリ名のみ除外チェック**: 再帰走査で親パーツはチェック済みなので、`entry.name` だけで除外判定。
- **除外キーワード**: `frozenset` による `O(1)` ルックアップ。非ASCII キーワードは事前分離。
- **IN 句バッチ削除**: 削除済みファイルのレコード削除を IN 句でバッチ化。`file_segments` を先に DELETE し FTS5 トリガーを発火。
- **failed_file 一括クリア**: ファイルごとの DELETE を廃止し、インデックス完了後に一括クリーンアップ。
- **ワーカー数**: I/Oバウンド対応で `min(16, cpu_count * 2)` に設定。

### SQLite 設定
- WAL モード + `synchronous = NORMAL` + `cache_size = -64000` + `temp_store = MEMORY` + `mmap_size = 256MB`
- **範囲クエリ**: `LIKE` の代わりに、子孫パス用の共通境界ヘルパーで `>= / <` を組み立てて B-tree インデックスを活用。`/` や `C:/` のようなルートパスでも壊さない。
- 詳細は `docs/performance.md` 参照。

### 検索
- **CTE 統合**: FTS5 の COUNT と結果取得を1クエリに統合。
- **正規表現イテレータ**: `fetchall()` の代わりにカーソルイテレータでメモリ効率化。
- **OR 検索**: 大文字 `OR` または小文字 `or` でキーワードを繋いだ場合、いずれかのキーワードを含むドキュメントを検索する OR 検索をサポート。空白区切りによる AND 検索との組み合わせ（例: `report 2025 OR 2026` は `report` AND (`2025` OR `2026`)）、除外キーワード（`-keyword`）、同義語展開、フォルダ検索、gantt タスク検索、Web ページ検索とも連携。`\OR` や `\or` は通常語としてエスケープ可能。
- **マイナス除外キーワード & 拡張子除外フィルタ (`-.png` / `-keyword` / `-ext`)**:
  - **検索ボックス**: `-.png` や `-draft` のように先頭に `-` を付与した語を除外語として扱う。`alpha -.png`（組み合わせ）だけでなく、`-.png` 単独指定でも全スコープ対象から `.png` を含む候補を除外して検索可能。エスケープ（`\-.png`）にも対応。
  - **拡張子フィルタ**: 拡張子欄（Web UI、macOS Cocoa、Windows WPF、Python Flet）にて `-png` や `-.png` と入力すると該当拡張子を除外。`md -png` のように包含と除外の組み合わせにも対応。SQL WHERE 句の `files.file_ext NOT IN (...)` による高速除外、およびベクトル・ハイブリッド検索の事後フィルタリングにも連動。
- **デフォルト並び替え**: 初期状態は `default` とし、ファイル名・Obsidian `title` / `aliases` の一致レベル、`top` タグ、同じ検索語からのクリック履歴、本文関連度バケット、利用価値スコア、更新日時の順で優先する。検索語別クリックは30日基準で減衰する。利用価値は飽和させたアクセス数55%、Obsidian重要度25%、90日基準の更新鮮度20%で合成する。作成日・更新日・アクセス数の個別並び替えではこれらを強制優先しない。
- **最大走査階層（index_depth）の無制限化およびUIコンパクト化**: UIでの階層指定が未入力（空欄または `None`）のときは、上限なし（無限大、内部的には 99999 階層）として走査する。また、検索画面の縦幅を削減して結果一覧の視認性を高めるため、階層入力UIを1段目（フォルダ指定行の右側）へインライン配置し、説明テキストはホバー時のみツールチップ（`title` 属性）で表示する。


### OS変更追跡 (Change Tracking)
- **macOS**: `FSEvents` により変更通知を検知し、対象フォルダを dirty 化。
- **Windows**: ローカル NTFS では `USN Change Journal` を使用し、停止中の履歴も復元。権限不足・非NTFS・エラー時は自動的に `ReadDirectoryChangesW` へフォールバック。全ボリュームがフォールバックされた場合は USN ポーリングスレッドを停止。
- **差分リフレッシュ**: 変更通知受信後 2 秒のデバウンスで、バックグラウンドの `dirty_refresh_worker` が dirty 対象を1件ずつ差分走査。Windows では追跡起動の成否に関わらず worker が常時稼働。
- 詳細は `docs/change_tracking.md` 参照。

### DB 接続
- 起動時に `lifespan` コンテキストマネージャでスキーマを初期化する。
- API リクエストごとに SQLite 接続を開閉し、スレッド間で同一接続を共有しない。
- インデックス中止要求は DB の `index_runs.cancel_requested` にも保存し、別プロセスのスケジューラー実行から検知できるようにする。

## デスクトップランチャー (Flet / PyObjC)
- **フォルダ**: `launcher/` にソースコードとドキュメントを分離して管理。
- **UI**: macOS では PyObjC / Cocoa `NSPanel`。その他 OS では Flet をフォールバック使用。
- **ホットキー**: `Command + Option` (Mac) / `Windows + Alt` (Windows Flet) / `Windows + Alt + Space` (Windows WPF) によるグローバル表示切り替え。
- **設定**: `LAUNCHER_API_BASE_URL`（Search/API接続先、既定 `http://127.0.0.1:8079`）、`LAUNCHER_WEB_BASE_URL`（Open/UIハブ、既定 `http://127.0.0.1:8001`）、`LAUNCHER_SEARCH_LIMIT`、`LAUNCHER_REQUEST_TIMEOUT` を環境変数で設定可能。
- **挙動**: 
  - macOS 版はマウスカーソルのあるディスプレイに表示。Flet 版は Flet の `window.center()` で中央表示。
  - フォーカス喪失時（blur）に自動非表示。
  - **検索挙動**: 
    - macOS: 検索時に登録済みフォルダのインデックス更新を許可。
    - その他 OS: 既存インデックスのみを使用して高速にレスポンス（更新チェックOFF時は `/api/search/indexed` により再インデックス・ベクトル作成を待たず既存DBだけで検索）。
    - Windows WPF: 「更新」チェックボックスOFF時は既存DB専用API `/api/search/indexed` でインデックス作成を待たずに検索し、「更新」チェックON時は `/api/search` でインデックス作成・更新を待って検索。
  - 立ち上がった（再表示された）時に、検索欄に残っているテキストを全選択状態にしてフォーカスする。
  - Web版のデザイン（Glassmorphism）を踏襲。
  - ウィンドウの表示・非表示時に、キーボードの押下状態（pynputフック）をリセットして、Enterキーが反応しなくなるのを防止する。
  - **単一インスタンス保証 (Single Instance Guard)**:
    - ランチャー起動時にファイル排他ロック（macOS/Linux: `fcntl.flock`, Windows: `msvcrt.locking`）を取得。
    - 既に別プロセスが稼働している場合は多重起動せず直ちに安全終了（`sys.exit(0)`）する。
    - 開発スクリプト（`start_dev.sh`）でもバックエンド再起動時に残存ランチャープロセスを確実に強制終了する。
  - **Escapeキー全域捕捉 & トグルクールダウン**:
    - フォーカスが検索入力欄・ボタン・チェックボックス等のどこにあっても、Escapeキー（keyCode 53）をパネル全体で確実に捕捉。
    - メモ画面では検索画面へ復帰、検索画面ではパネルを即時非表示とする。
    - キー押下継続中の watchdog やイベント重複による即時再表示（消えた瞬間に再出現する点滅）を防ぐため、`hotkey_activated` はキー解放時のみリセットし、さらに `toggle_panel()` に 350ms の最小クールダウン間隔を設ける。
  - **gantt 送信 UI**:
    - gantt タスク追加用のメモ画面を、「タスク名（名前）」と「メモ」の独立した入力ボックスに分離。
    - 「送信」および「キャンセル」ボタンを追加。
    - メモ画面内では `Tab` / `Shift + Tab` によって「名前欄 ⇔ メモ欄 ⇔ 送信ボタン ⇔ キャンセルボタン」の間でフォーカスを巡回移動させる。
    - メモ入力欄およびタスク名入力欄での `Return` / `Enter` （通常のEnterまたはShift+Enter）はすべて改行（または通常の入力継続）とし、即時送信は行わない。
    - 送信処理は、「送信」ボタンをクリックしたとき、または「送信」ボタンにフォーカスがある状態で `Return` / `Enter` キーを押したときのみ実行する。
    - メモ画面での `Escape` キー押下時は、ランチャーを閉じるのではなく検索画面へ戻る挙動とする。
    - 送信成功時は入力値をクリアし、「タスク名」入力欄へフォーカスを戻してランチャーを開いたままにし、連続でタスクを追加可能にする。
    - 詳細は `docs/gantt_launcher_ui.md` 参照。

- **詳細は `launcher/docs/spec.md` 参照。**

## 外部Open/UIハブ
- **8001**: 別の必要アプリが提供する既存Openハブ。このリポジトリでは実装・起動・停止・監視・プロキシを行わない。
- **8079**: 検索・設定・click記録・`open-location`などのSearch/API面。primary openの入口にはしない。
- ランチャーとWebクライアントは外部8001の既存`/api/fullpath?path=...`と`/?path=...`へ従来どおり送る。8001停止時は接続エラーでよく、8079へフォールバックしない。
- DNS無し環境では`127.0.0.1`または固定IPだけを差し替える。詳細は`docs/open_hub.md`参照。

### Windows WPF ランチャー
- **フォルダ**: `launcher/windows/`。Windows x64 / .NET 8 WPFで、外部NuGet依存なし。
- **配布**: self-containedフォルダ版を第一候補とし、self-contained single-file版も発行する。会社PC側のSDK・ランタイム・インストーラーは不要。
- **Git配布**: 会社PCでビルドしないため、`launcher/windows/publish/folder` と `launcher/windows/publish/single-file` の発行成果物（EXE、.NETランタイム、同梱アセット）は C# ソース変更と同じコミットでGitへ追加・pushする。`bin/`・`obj/`、Python仮想環境、依存キャッシュは追跡しない。
- **ホットキー**: Windows標準APIによる `Shift` の2回押下（400ms以内、間に他キーを挟まない）で表示・非表示を切り替える。入力は遮断せず、`RegisterHotKey` は使用しない。
- **仮想デスクトップ**: 非表示時に検索ウィンドウを破棄し、次回表示時にHWNDを再生成して、呼び出した仮想デスクトップへ表示する。
- **フォールバック**: 発行済みEXEがない場合だけ既存Python/Flet版を起動する。
- **macOS版準拠**: WPF版も検索欄右側の拡張子フィルタ、gantt検索、タスク名・メモ・送信・キャンセル、共有parent、パスコピー、保存場所、フォルダ、ganttリンク、GUIボタン、上下キー循環選択を提供する。`Tab` / `Shift + Tab` は「検索欄 → 拡張子欄 → タスク名 → メモ → 送信 → 検索欄」を循環し、送信後のTabでは検索画面を表示する。`.py`、`.bat`、`.exe`、`.lnk` は8001を経由せず、親フォルダをcurrent directoryとして直接起動する。
- **再表示**: 仮想デスクトップ移動のためUIウィンドウを再生成しても検索文字列は保持し、検索欄へ復元して全選択する。WPF初期版は半透明パネルを使用し、DWM/Acrylic背景ブラーは未実装。
- **WPF検索結果UI**: 横スクロールなしで結果全体を確認できる幅とし、長いパス・抜粋・操作ボタンは折り返して表示する。ランチャー表示直後は検索欄へフォーカスし、検索結果の先頭が選択済みなら矢印操作なしの `Return` / `Enter` でも選択結果を開く。
- **WPF検索対象 & インデックス更新連動**:
  - ローカルファイルとWebページの両方を横断検索する。
  - 通常時（「更新」チェックOFF）: 既存DB専用API `/api/search/indexed` を使用し、ベクトルのインデックス作成や差分走査を待たずに既存DB（SQLite DB および既存ベクトルインデックス）だけで即座に高速検索する。
  - 「更新」チェックON時: 統合API `/api/search` を `search_all_enabled: false`, `skip_refresh: false` で呼び出し、登録済みフォルダのインデックス作成・差分更新（ベクトルインデックス同期を含む）の完了を待ってから最新結果を検索する。

## ウェブページ全文検索
- **目的**: 指定したベースURL階層下の全ページをクロール・本文抽出し、ローカルファイルと同様に全文検索可能にする。
- **データ統合**: `files` テーブルに `source_type` 列（`local` or `web`）を追加。Webページのパス（URL）を `normalized_path` とし、本文を `file_segments` 経由で FTS5 へ登録する。
- **検索の切り替え・オプトイン**: GUI上に「ローカル検索」と「ウェブページ検索」を切り替えるトグル/タブを設置。検索APIでは `source_type` パラメータ（デフォルト: `local`）によって挙動を制御し、パラメータのないAPI呼び出し（デスクトップランチャー等）ではWebページ検索を完全に除外することで影響範囲を極小化する。
- **キーワードジャンプ**: 検索結果をクリックすると、URLの末尾に URL Text Fragments (`#:~:text=...`) を付与して開き、目的の箇所へ自動ハイライトジャンプする。
- **認証・JavaScript描画**: Web取得方式は通常HTTP（既定）・Microsoft Edge・Google Chromeから選択する。Edge/ChromeモードはPython版Playwrightで端末にインストール済みの正式版ブラウザを画面あり・アプリ専用永続プロファイルで起動し、Windows統合認証やJavaScript描画後のDOMを利用する。ブラウザ拡張機能およびPlaywrightブラウザの追加ダウンロードは不要とする。
- **詳細は `docs/web_page_search_spec.md` 参照。**

## 検索ルールの一元管理（除外キーワード・類似語・インデックス対象拡張子）
- **UI一元化**: 「検索ルール管理」タブにて「除外キーワード」「類似語・専門用語リスト」「インデックス対象拡張子」の3大ルールを一元的に編集・管理。
- **インデックス対象拡張子**:
  - ハンバーガーメニューから「検索ルール管理」へ移設。
  - 標準拡張子チェックボックス、本文抽出用追加拡張子（`.py` / `.dat` 等）、ファイル名のみ追加拡張子（`.cae` / `.mesh` 等）の追加・削除、全選択・全解除・保存を提供。
  - 拡張子検索欄によるインライン絞り込みに対応。
- **ベクトル検索および全文検索への完全連動 & 除外設定（キーワード・拡張子）の厳格スキップ**:
  - ここで設定された「除外キーワード」および「インデックス対象拡張子」は、通常の FTS5 全文検索だけでなく**ベクトル検索（インデックス走査および検索フィルタ）にも連動して完全適用**される。
  - 除外キーワード（絶対パス・フォルダ名・単語境界・隠し要素）やチェックを外した拡張子はインデックス走査時に確実にスキップされる（全文インデックス・ベクトルインデックスともに走査・テキスト抽出しない）。
  - Web UI の「差分同期 ⚡」や「全件再作成 🔄」、再インデックス時にも未指定フォールバックにより除外キーワードが漏れなく適用される。
- **インデックス削除確認（削除通知）& フォルダ追加・拡張子変更・差分更新時のインデックス保護**:
  - **フォルダ追加時の保護**: 検索対象フォルダの追加時、グローバル除外設定・拡張子・指定階層数を確実に引き継ぎ、既存インデックス済みファイル群を勝手に削除せず安全に保持する。
  - **削除通知チェックボックス**: ハンバーガーメニュー内に「インデックス削除時に確認する（削除通知）」チェックボックス（既定値: 有効 `true`）を設置し、`backend/data/confirm_index_deletion.txt` に永続化。
  - **拡張子変更時の確認**: 拡張子を除外して保存する際、削除通知が有効であればダイアログで確認し、ユーザーが許可した場合のみ既存レコードを安全にクリーンアップする（キャンセル時は既存データを保持し、設定のみ保存）。削除通知が無効な場合も勝手な自動削除は行わない。
  - **ベクトル差分インデックス時の削除確認 & 許可なき削除の完全抑止**: 会社の低スペック端末やネットワーク環境での半日かかる再インデックスの無駄を防ぐため、バックエンド API およびインデクサーは既定値 `clean_deleted_files = False` とし、ユーザーの明示的な許可なしにインデックスからレコードを勝手に削除しない。差分インデックス更新前に走査対象外となったファイルが存在する場合は、事前にファイル一覧付きダイアログで削除可否を確認し、キャンセル時は削除のみをスキップして新規・更新ファイルの学習・同期を安全に継続する。
- **類似語・専門用語形式**: `backend/data/synonym_groups.txt` にて `類似語1,類似語2... : 意味・解説` の形式で管理。通常検索はコロン前のみを OR 展開し、意味検索（ベクトル・ハイブリッド・AIインプット）は用語と解説を辞書（Glossary）として活用。
- **詳細は `docs/index_deletion_confirmation_spec.md` および `docs/synonym_management.md` 参照。**

## gantt タスク検索
- **目的**: gantt アプリのタスク内容を、通常のローカルファイル検索とは分離した任意選択の検索対象として扱う。
- **API 連携**: 
  - 既定の取得先は `http://localhost:8000/api/tasks`。バックエンド設定 `SEARCH_APP_GANTT_API_BASE_URL` で変更可能。
  - レスポンスからタスク一覧を取得し、空白区切りの検索語を AND 条件で照合する。
- **検索仕様**:
  - `include_gantt_tasks: true` が指定されたときだけ gantt API を呼び出す（デフォルトは `false`）。
  - 検索結果は `source_type: "gantt"`, `full_path: "gantt://tasks/{id}"` として返す。
  - タイトルクリック時は `POST /tasks/{task_id}/open-input` を呼び出す。
  - タスク JSON に `link` / `url` / `href` / `input_url` / `external_url` がある場合のみ、結果アクションに「ganttのリンクを開く」を表示する。
- **UI**: Web 版検索バーに `gantt` の追加チェックを設置。ランチャー（macOS/Flet版）も同様に `gantt` チェックを有効にした時のみ結果に追加する。
- **詳細は `docs/gantt_task_search.md` 参照。**

## ベクトル検索 & ハイブリッド検索
- **目的**: 意味・概念による類似度検索（Dense Retrieval）と高速な全文キーワード検索（FTS5 Sparse Retrieval）を統合。
- **検索方式の3択 & 既定値**:
  - `hybrid`（ハイブリッド検索 [既定]）、`vector`（ベクトル検索）、`keyword`（通常キーワード検索）の3つから選択可能。
  - デフォルトは Web UI および全デスクトップランチャーともに必ず `hybrid` とする。
- **デスクトップランチャー連携**:
  - macOS Cocoa、Python Flet、Windows WPF の全ランチャーで検索方式（🔀 ハイブリッド [既定] / 🔮 ベクトル / 🏷️ 通常）を切り替え可能。
  - 検索結果に一致理由バッジ（🌟両方一致 / 🔮意味一致 / 🏷️通常一致）および最も類似度の高い核心文（`salient_sentence`）を表示。
- **対象範囲**:
  - Markdown だけでなく、選択中の全拡張子（PDF, Word, Excel, TXT, JSON, MSG 等）および全登録フォルダを走査対象とする。
  - テキスト抽出可能ファイルは意味単位でチャンキング。画像・音声等の本文なしファイルはファイル名をテキストとしてベクトル化し、意味検索でもヒット可能にする。
- **順位融合 (RRF) & スコア正規化 & 並び替え**:
  - キーワード検索の順位とベクトル検索のコサイン類似度順位を RRF ($k=60$) で融合。
  - 理論最大スコア（両方1位: $S_{\max} = \frac{w_v+w_k}{k+1}$）で除算して $0.0 \sim 1.0$ に正規化し、UI上で直感的な $0\% \sim 100\%$ の融合スコアとして表示。
  - 各検索結果に `match_source`（`both` [両方一致], `vector` [意味一致], `keyword` [キーワード一致]）、核心文（`salient_sentence`）、正規化融合スコア・類似度を付与。
  - 並び替えオプションに「ハイブリッドスコア順 (`hybrid_score`)」「ベクトル類似度順 (`vector_score`)」「通常検索スコア順 (`keyword_score`)」を追加。
  - デフォルト（`default`）ソート選択時は、ハイブリッド検索結果に対してハイブリッド順位（`hybrid_score` 降順）を最優先にして表示。
- **インデックス自動連動 & モデル切替**:
  - 全文インデックスの作成・差分更新完了時に、自動でベクトルインデックスも連動して差分更新（`mtime` と `sha256` でスキップ判定）。
  - ベクトル管理画面でモデルを選択後、未ロード状態のままインデックス開始（差分・全件）を実行しても自動で対象モデルをロードして同期を開始する。
- **モデル配置 & 保存先**:
  - モデルはローカル `models/` ディレクトリ（Git除外）に配置（`ruri-v3-30m`, `ruri-v3-310m`, `ruri-v3-70m`）。
  - ベクトルDBおよびFAISSインデックスは `backend/data/vector_index_<model_name>.db` に一括管理。
- **モデル選択の永続化 & 起動時自動復元 (`config.json`)**:
  - 選択・ロードされたモデルは `backend/data/config.json` に即座に自動保存（記憶）される。なお `mock_model` などのテスト用ダミーモデルは保存せず設定ファイルの汚染を防止する。
  - バックエンドサーバー起動時（FastAPI `lifespan`）に、`config.json` に記録が残っている場合のみ前回のモデルを自動検知・ロードし、再起動直後でもユーザーが手動でリロードすることなく即座にハイブリッド/ベクトル検索を利用可能とする。
  - 初回起動時や未記録時はモデルを自動ロードせず、未ロード状態で安全に待機する（勝手なデフォルトモデルのロードを行わない）。
- **UIページ**:
  - **ベクトル管理ページ**: モデル別ステータスバッジ（登録件数/MB/未インデックス）、アクティブ（稼働中）モデルの視覚的強調ハイライト（発光枠線・🟢稼働中バッジ・自動選択同期）、インデックス作成中リアルタイムインジケーター（ヘッダーバッジ/パネル発光/同期スピナー）、差分学習 ⚡ vs 全件再作成 🔄、進捗プログレスバー・完了サマリー、専門用語辞書の Excel インライン編集・保存、単一ファイルの差分更新ベンチマーク（意地悪プリセット4種）。
  - **AIインプットページ**: 検索ボックス横の拡張子フィルター（既定: `md`、包含・除外対応）、ステップ2上部からのワンクリックHTML生成ボタン、検索結果のドラッグ矩形選択・Shift解除、AIプロンプトプリセット5種、タイトル自動推定、概算トークン数カウンター、デュアルタブ（プレビュー/HTMLソース）、画像・図面（Excalidraw/draw.io）のインラインBase64化自己完結HTMLの生成・ダウンロード・コピー、特大プレビューモーダル（100vw×100vhのフルスクリーン最大化表示、左右2カラム、ドラッグ＆ドロップおよび▲▼ボタンによるMarkdown表示順序並び替え、チェックボックスによるリアルタイム除外連動、ローカル保存＆絶対パス自動クリップボードコピー）。
- **GPU自動活用 & CPU自動フォールバック (Mac MPS / Windows RTX A500 CUDA)**:
  - **Mac (Apple Silicon)**: `torch.backends.mps.is_available()` を検知し、Metal GPU (MPS) で高速推論（CPU比約7倍高速）。
  - **Windows (NVIDIA GPU)**: RTX A500 等の CUDA 対応 GPU 環境では `torch.cuda.is_available()` を検知し、自動的に `cuda` で実行。
  - **CPU自動フォールバック**: GPU 非対応環境、初期化エラー、メモリ不足（OOM）発生時にはプロセスを停止させず、安全かつシームレスに `cpu` にフォールバックして処理を完遂。
  - **稼働デバイス可視化**: ベクトル管理画面の最上部ヘッダーおよびモデル選択カードに稼働デバイス（`⚡ GPU稼働中: Apple Silicon (Metal)` / `⚡ GPU稼働中: NVIDIA RTX A500 (CUDA)` / `💻 CPU稼働中`）を常時表示。
  - **Windows NVIDIA GPU (RTX A500) 配布対応**: `requirements-cuda.txt` およびワンクリックセットアップ `setup_windows_cuda.bat` を同梱し、Windows PC でも簡単に CUDA 12.4 環境を構築可能とする。
- **有効ターゲットフォルダ制限 & 実在ファイル実在性検証**:
  - ベクトル検索およびハイブリッド検索の候補抽出時、現在有効な登録検索対象フォルダ（`targets` テーブルで `is_search_target_enabled = 1` のフォルダ）配下に属するファイルのみをヒット対象とする。登録フォルダ外のファイル（過去の登録解除フォルダやテスト・一時ファイルなど）は結果から自動除外される。
  - ローカルファイルについてはファイルシステム上の実在性（`Path.is_file()`）も検証し、削除されたファイルのゴーストレコードを検索結果に返さない（スタブ・ダミーサービス時は除く）。
  - テスト実行環境では `conftest.py` による `vector_state` の一時ディレクトリ自動隔離および `IndexService` のカスタムDB接続時ガードにより、テスト走査による実環境ベクトルDBへの混入・汚染を完全防止する。
- **詳細は `docs/vector_search_spec.md` および `docs/ai_context_export_spec.md` 参照。**

### AIインプット: 呼び出されたメール（MSG/EML）追加 & Base64画像埋め込み
- **目的**: 選択されたMarkdownファイルから参照されているメールファイル（`.msg`, `.eml`, `winmail.dat` 等）を自動抽出し、AI投入用HTMLの末尾に APPENDIX として安全・美麗に展開。
- **UIオプション**:
  - AIインプット画面に「✉️ アウトプットに呼び出されるメールを追加する」チェックボックス（初期値: `true`）を追加。
  - 「🖼️ 画像・図面をBase64埋め込み」と連動し、ON時はメール内のCID画像や添付画像も Base64 Data URL として HTML 内へインライン埋め込み。
- **サニタイズ (`sanitize_outlook_html`) & CP932デコード (`decode_best_effort_text`)**:
  - Word/Outlookの条件付きコメント（`<!--[if ...]>`）、`<xml>`, `<o:p>`, `<w:...>`, `<head>`, `<style>` 等を完全除去し、文字化けやタグ露出を防止。
  - 画像なし・表なし時はタグ混入のないプレーンテキスト本文を最優先利用。
  - `RegisterCustomCommands.md` に準拠し、プロパティがcp1252等と誤認されたMSGファイルに対しても `overrideEncoding='cp932'` 再試行や生ストリーム直接取得、`mojibake_score` による自然な日本語選択を行い、`UnicodeDecodeError` によるHTML生成中断を完全に防止。検索テキスト抽出（`_extract_msg_text`）にも連動。
- **詳細は `docs/ai_linked_emails_spec.md`、`docs/msg_encoding_support.md` および `docs/ai_linked_emails_flow.excalidraw.md` 参照。**

### .excalidraw.md の画像ファイル（図面アセット）取り扱い & 貼り付け画像（PNG等）の完全復元
- **目的**: Obsidian の `明和高校.excalidraw.md` のような `.excalidraw.md` ファイルを「画像・図面アセット」として美しく取り扱い、かつExcalidraw図面内に貼り付けられたPNG画像やアイコンがHTML上で欠損することなく完全に表示・復元されるようにする。
- **貼り付け画像（PNG等）の多段階自動解決**:
  - **インラインBase64**: `files[fileId].dataURL` のBase64画像データをそのまま利用。
  - **`## Embedded Files` WikiLinkマッピング**: Markdownテキスト内の `## Embedded Files` セクションから `{fileId}: [[画像.png]]` を抽出し、カレントフォルダ、Vaultルート、共通画像フォルダ（`01_data/common_image/` 等）、Vault全体から画像実体を自動探索してBase64化。
  - **ハッシュファイル名探索**: ノートと同フォルダやVault内から `{fileId}.png`, `{fileId}.jpg`, `{fileId}.svg` 等を探索してBase64化。
  - **SVG内 `<image>` 埋め込み**: 動的SVG生成（`excalidraw_to_svg`）時に `<image href="data:image/png;base64,...">` として確実に展開し、キャッシュ有無に関わらず画像が表示されることを保証。
- **ノート内リンクの画像置換**: `![[xxx.excalidraw.md]]`（埋め込み）だけでなく、`[[xxx.excalidraw.md]]` や `[[xxx.excalidraw.md|300]]` も画像ファイルとして検知し、`.excalidraw-cache/` の PNG/SVG または動的生成 SVG を Base64 Data URL の `<img>` タグへ置換。
- **Excalidrawノート直接指定時のレンダリング**: ユーザーがAIインプットの対象ファイルとして Excalidraw ノートを直接選択した場合、スキップせず図面画像（SVGまたはキャッシュPNG）をドキュメント本文（`<article>`）に美麗に描画。
- **アイコン統一**: Web画面 (`fileIcon.ts`)、macOS/Flet ランチャー (`file_icons.py`)、Windows WPF ランチャー (`SearchModels.cs`) で `markdown.svg` ではなく `excalidraw.svg`（図面アイコン）を適用。
- **詳細は `docs/ai_html_excalidraw_image_spec.md`、`docs/excalidraw_image_handling_spec.md` および `docs/excalidraw_image_flow.excalidraw.md` 参照。**

### 社内制限環境（pip installのみ可能）自己完結運用 & モデル管理
- **目的**: 会社PC等の外部ダウンロード不可・ビルドツール（Node.js, .NET SDK）不可環境でも、`git pull` と `pip install` のみで全機能が完全稼働する。
- **モデルのローカル配置と柔軟な自動検知**: モデルファイル（数GB）は Git にコミットせず `.gitignore` で除外。会社PC側で別途ダウンロード・配置して運用する。バックエンド（`VectorState.resolve_model_path`）は `models/<モデル名>/` または `backend/models/<モデル名>/` のどちらに置かれても自動検知してロードする。
- **モデル未配置時の安全起動**: モデルが未配置の場合でもバックエンド起動はクラッシュせず正常に立ち上がり、通常キーワード検索（FTS5）が即座に利用可能。Web画面のベクトル管理ページで未配置状態を案内する。
- **設定ファイルの環境別個別保持（Git除外）**: 各種設定ファイル（`synonym_groups.txt`、`exclude_keywords.txt`、`index_selected_extensions.txt`、`config.json` 等）は各端末・環境固有のパスや設定を含むため、`.gitignore` で Git 管理から除外し各環境で独立保持する。ディレクトリ構造維持用の `.gitkeep` および参考用テンプレート（`*.example`）のみを Git 追跡し、設定未作成時はバックエンドが安全にデフォルト値を自動生成する。
- **ビルド済み成果物の同梱**: `frontend/dist/`（Web UI）および `launcher/windows/publish/`（WPFランチャー）を Git 同梱。社内PCで Node.js や .NET SDK のインストールは一切不要。
- **Windows ワンクリックセットアップ**: `setup_windows.bat`（CPU用）および `setup_windows_cuda.bat`（GPU用）を提供。`start_windows.bat` でワンクリック起動。
- **詳細は `docs/offline_environment_and_models.md` 参照。**
