# AIインプット用 マークダウン＆結合画像エクスポート仕様書

## 1. 概要と背景
社内AI（LLM）チャットのハーネス（ラッパーシステム）は、PDFファイルから画像を削除してテキストのみを抽出し、HTMLのBase64画像も認識できない仕様であることが判明した。
そのため、PDFエクスポートを完全撤廃し、**「統合マークダウンファイル（.md）」** と **「全図面を1枚に連結した結合画像ファイル（.png / .jpg）」** の2ファイルを出力してチャットに同時インプットする方式へ移行する。

---

## 2. 仕様詳細

### 2.1 統合マークダウンファイル (`〇〇_context.md`)
1. **マークダウン本文の生テキスト維持 (Obsidian互換性)**:
   - 本文内の画像リンク記法（例: `![[全体構成.excalidraw.md]]`, `![[db_schema.png]]`, `![[image.png|300]]`, `[[image.png]]`）は**一切改変せず、生のマークダウン記法のまま維持**する。
   - AIチャットの修正・推敲結果をそのまま Obsidian にコピペするだけで、画像リンクがそのまま有効になりメモを最新化できるようにする。
2. **最上部「AIへの指示ルール」の埋め込み**:
   - ドキュメント最上部に、以下のルールを自動配置する：
     - 本文中の `![[...]]` は同時添付された結合画像ファイル内の各図面と対応していること。
     - 結合画像側の上部ヘッダーに所属マークダウンファイル名とリンク記法が記載されていること。
     - **AIが回答・編集出力する際は、元の図面リンク記法を勝手に削除・変更せずそのまま出力すること**（Obsidian貼り付け互換性維持）。
3. **複数ファイルの境界明確化**:
   - 各ファイルの区切りに `# ===== [ファイル X/N] ファイル名 =====` を配置。
4. **呼び出しメールの末尾集約 (APPENDIX)**:
   - 選択されたマークダウンからリンクされているメール（`.msg`, `.eml` 等）を末尾にまとめる。
   - **重複排除**: 同一メールが複数箇所からリンクされている場合は1件のみ掲載。
   - **リンクつながりの明示**: どのマークダウンファイルのどのリンクから呼び出されたかを明記。
   - **宛先（To）および CC の完全除外**: トークン消費削減のため、メール本文・ヘッダーから `To:` および `Cc:` を完全に除去（件名・差出人・日時のみ保持）。
5. **不要コードの除外 (トークン最適化)**:
   - DataviewJSの静的展開不能な生コードを省略・注釈化。
6. **Excalidraw描画バイナリ・圧縮JSONの完全除去 (`# Excalidraw Data` 以下の切り捨て)**:
   - Excalidrawノート（`.excalidraw.md` 等）に含まれる `# Excalidraw Data` 以降（テキスト要素 `## Text Elements`、`## Drawing`、圧縮JSON ````compressed-json ... ````）は、AI（LLM）にとって解釈不能な文字列・バイナリであり、大量のトークンを無駄に浪費する。
   - `strip_excalidraw_data` により、見出し `# Excalidraw Data` から末尾までを完全に切り捨てて出力しない。
   - 代わりに、ドキュメント内の図面は最高精度のベクターSVGからラスタライズされた「結合画像ファイル（`〇〇_images.png` / `.jpg`）」として添付提供されるため、情報損失なく視覚的にAIへ提供される。
   - `# Excalidraw Data` より手前の本文（見出し、通常段落、リスト、テーブル、コードブロック）および画像リンク記法（`![[...]]`）は完全に維持され、Obsidianコピペ互換性を保証する。

### 2.2 結合画像ファイル (`〇〇_images.png` / `.jpg`)
1. **全図面の完全収録 & 1枚への縦連結 (Pillow / PIL & resvg-py)**:
   - 選択ドキュメント群に含まれる全図面（Excalidraw SVG、添付PNG/JPG等、HTMLに含まれる画像すべて）を上から順に1枚の画像へ縦連結。
   - Excalidraw等のベクター図面（SVG）は `resvg-py` により高解像度ラスタライズ（PNG変換）され、Pillow で確実に結合処理される。
2. **文字視認性を保護する超高解像度維持 (2800〜3200px基準)**:
   - 従来の幅1200px強制縮小を完全撤廃。
   - 画像群の最大幅に合わせて基準幅を動的決定（`max(2800, min(3200, max_img_w))`）。
   - 基準幅より大きい画像のみ縮小し、基準幅以下の画像は原寸の鮮明度をそのまま維持して中央揃え配置。
   - Excalidraw図面は一時プレビューキャッシュ（縮小PNG）ではなく、元ノートのデータから直接最高精度のベクターSVG（`prefer_vector=True`）を生成・ラスタライズし、図面内の細かいスケジュール表やプリントの文字潰れを完全に防止。
3. **図面ごとの説明ラベル描画（黒背景廃止・黒文字描画・文字化け完全防止）**:
   - 各画像の上部に、白背景＋**黒文字だけ**（`#000000`）で以下の情報を描画：
     `【図X】 所属: ノート名.md  |  リンク記法: ![[画像名.png]]`
   - 黒背景（濃紺の塗りつぶし帯）は完全撤廃し、すっきりとした読みやすいデザインとする。
   - OSの標準日本語フォント（macOS: ヒラギノ角ゴシック / Windows: ＭＳ ゴシック, Meiryo / Linux: Noto Sans CJK）を自動検出し、**日本語の文字化けを完全に防止**する。
4. **透過PNG・SVG透明領域の白背景アルファ合成（黒背景化防止）**:
   - 透過PNGやExcalidraw SVG等の透過部分（アルファチャンネル）を、白背景ベース画像（RGB: 255, 255, 255）と自然にアルファ合成（`flatten_to_rgb`）してから貼り付ける。
   - Pillowの直接 `convert("RGB")` による透明部の黒潰れ（黒背景化・黒い四角形の出現）を完全に防止する。
5. **大量・高解像度画像の安定結合（DecompressionBombError解除）**:
   - 40件〜100件以上のノート群を一括エクスポートする際、縦連結キャンバスのピクセル数がPillowのデフォルト上限（約89Mピクセル）を超過してもエラーで停止しないよう、`Image.MAX_IMAGE_PIXELS = None` を明示設定。
   - 幅・高さが0または異常な画像に対するゼロ除算防御を実装。
6. **社内チャット 4.5MB 制限の自動クリア**:
   - 出力ファイルサイズが **4.2MB**（安全マージン）を超える場合：
     - ① JPEG（品質85% → 75%）への自動切り替え
     - ② 解像度の段階的スケールダウン（0.85倍 → 0.7倍...）
     を行い、**必ず 4.5MB 未満の1枚のファイル** に収めて出力。
7. **画像なし時の挙動**:
   - 画像が0枚の場合は画像ファイルは生成せず、マークダウンファイルのみを出力。

### 2.3 メール解析・パス解決の例外防御・堅牢化
1. **破損メール耐性**:
   - 不正なバイナリデータや破損した `.msg` / `.eml` ファイルがノートからリンクされている場合でも、`try...except` により安全にスキップし、エクスポート全体を 500 エラーで停止させない。
2. **パス解決の安全性向上**:
   - `resolve_image_or_figure_data_url` における `current_dir` 解決のフォールバックを保護し、絶対パスや非実在ファイルが渡されても安全にカレントディレクトリを特定する。

1. **ステップ1見出し横のアクションUI**:

     - 現在設定されているフォルダパス（バッジ/ツールチップ表示）。
2. **サーバー永続化（次回起動時の自動復元）**:
   - バックエンドのデータディレクトリ内 `backend/data/ai_export_folder.txt` に設定されたフォルダパスを永続化。
   - `GET /api/export/config`: 保存されているフォルダパスを返却（未設定時は `~/Desktop/AI_Inputs`）。

   - `POST /api/export/open-folder` において `folder_path` が未指定（空）の場合、サーバー永続化された保存先フォルダを自動オープン。
   - プレビューモーダル内の「💾 2ファイルを保存」実行時にも、この設定済みフォルダへ `〇〇_context.md` と `〇〇_images.png`（または `.jpg`）が保存される。

1. **obsidianのtopタグのみを出す チェックボックス**:
   - 特大プレビューモーダル右ペインに「🏷️ obsidianのtopタグのみを出す」チェックボックスを配置。
   - チェックをONにすると、`has_obsidian_top_tag === true` のノートのみを抽出し、HTMLプレビューおよび保存対象を即座に絞り込み。
   - 各ノート行に「🏷️ TOP」バッジを表示して視認性を担保。
2. **ノートごとのリンク展開階層数設定 (Depth) & デフォルト値 (topタグあり: 5 / 他: 1)**:
   - モーダル内各ノート行に「階層: [ 数値 ]」の入力インプットを配置（0〜10階層）。
   - **デフォルト値**:
     - `top` タグが含まれているノート: **5**
     - それ以外のノート: **1**
   - ユーザーはノートごとに数値を自由に変更可能（0: リンク展開なし、1: 直リンク先まで、5: 5階層先まで）。
3. **ノート間リンク再帰展開エンジン (`LinkExpander`)**:
   - `extract_markdown_links`: WikiLink（`[[リンク先]]`、`[[リンク先|別名]]`、`[[リンク先#見出し]]`）および通常Markdownリンク（`[表示名](パス)`）からリンク先を自動抽出。画像（`![[...]]`）、メール（`.msg`/`.eml`）、非Markdownファイル、外部リンク、アンカーは除外。
   - `expand_linked_files`: 各ルートノートから幅優先探索（BFS）で指定階層まで探索。
   - **循環リンク・重複防御**: A -> B -> A の循環参照や多重参照を安全に検知・重複排除。
4. **HTMLプレビュー・2ファイル保存への完全連携**:
   - `export_documents_to_html`、`export_documents_to_markdown_and_image`、`/api/export/resolve-links` に `file_depths` を連携。
   - 展開された全ノートの本文・図面・メールが統合マークダウン、結合画像、自己完結HTMLプレビューに漏れなく取り込まれる。

## 5. プレビュー表示およびモーダルでの階層指定ツリー反映

ユーザーが「プレビューを見ながら、階層の指示（調整）もしていきたい」という要件に応え、階層指定（1〜5）の展開結果をHTMLプレビューおよびモーダル右側のファイル選択リストに視覚的ツリーとして即座に反映する。

### 1. HTMLプレビューへの階層反映
- **目次 (TOC)**: リンク展開された子ノートはインデント（`↳`）され、`<span class="badge depth-badge">階層 {depth}</span>` および `(リンク元: 親ノート名.md)` を付与。
- **ドキュメントヘッダー**: 記事タイトルに `↳` を付与し、パス欄に `<span class="badge depth-badge">🔗 リンク先 [階層 {depth}] (リンク元: 親ノート名.md)</span>` を表示。子ドキュメントカードには左側にアクセントボーダーを適用。

### 2. 統合マークダウン見出し境界への階層情報付与
- セクション見出しを `# ===== [ファイル {i}/{total}] ↳ [階層 {depth}] (リンク元: 親ノート名.md) ノート名.md =====` とし、AIモデルが前提資料の派生関係・階層構造を正確に文脈把握できるようにする。

### 3. モーダル右ペインでのインデントツリー表示 & リアルタイム連動
- モーダル内の各親ノート行の直下に、展開されたリンク先ノート一覧（`ai-child-nodes-container` / `ai-child-node-item`）を点線インデント付きのツリー形式で表示。
- `↳ [階層 {depth}] ファイル名 (リンク元: 〇〇)` により、どのファイルがどのノートから取り込まれたかを一目で把握。
- 右ペイン見出しの件数バッジに `〇件選択 (展開後: △件)` を表示。
- ユーザーが親ノートの「階層」入力欄を変更すると、リアルタイムで配下のツリーと左側のHTMLプレビューが即座に自動再生成・同期される。

## 6. Dataview内リンク網羅展開・子ノード個別除外・8001ハブ連携

### 1. Dataviewおよび図面リンクの網羅的抽出 (`LinkExpander`)
- **DataviewJS 内のJSON / オブジェクトパス**: `noteListRows = [{"path": "01_data/...", "name": "..."}]` のようなスクリプト内JSON定義から対象ファイルパスを自動抽出。
- **Dataview API 呼び出し**: `dv.page("...")` や `dv.pages("...")` 内のパス文字列を抽出。
- **Dataview クエリ**: `FROM "..."` 句で指定されたフォルダ・ファイルパスを抽出。
- **URLクエリパラメータ内のパス**: `http://localhost:3001/?filepath=...excalidraw.md` 等のURLからノートパス（URLデコード済み）を抽出。
- **Excalidraw 図面埋め込み**: `![[図_システム_top.excalidraw|1475]]` 等の図面ノート指定を検知し、`.excalidraw.md` または `.excalidraw` 実体ファイルを自動解決。
- **Vault相対パス解決**: `01_data/...` などのVault内相対パスをルートノートのディレクトリ階層を遡って自動で絶対パス解決。

### 2. 子ノードの個別除外チェックボックス
- モーダル右側ツリー内の各子ノードアイテム（`ai-child-node-item`）に独立したチェックボックスを設置。
- チェックを外した子ノートは、打ち消し線・半透明表示で視覚的に区別され、`excluded_file_paths` としてバックエンドへ送信。
- チェック切り替え時にデバウンスでHTMLプレビューを再生成し、マークダウン＆画像保存（`handleSaveBundle`）時にも除外設定がそのまま反映される。

### 3. カードクリックによる 8001 外部Openハブ連携
- 親ノートカード（`ai-file-selection-item`）および子ノードカード（`ai-child-node-item`）をクリックすると、`http://127.0.0.1:8001/api/fullpath?path={encodeURIComponent(fullPath)}` を別タブで開き、8001の外部アプリで対象ノートを即座に開く。
- カード右側に `↗` アイコンを表示し、リンク先であることを視覚的に案内。
- チェックボックス、ドラッグハンドル、順序変更ボタン（▲▼）、階層入力欄の操作時はイベント伝播（`e.stopPropagation()`）を抑止し、カードクリックの誤発火を防止。

## 7. spoon_feeder2風ツリー表示 & 折りたたみ・展開（開閉トグル）UI

参考リポジトリ（`spoon_feeder2`）のディレクトリツリー表示（TreeNode）に準拠し、展開されたリンク先ノート群を視覚的に美しい木構造として折りたたみ・展開可能にする。

### 1. 木構造への再帰的階層化 (`buildChildTree`)
- フラットな展開ノート一覧（`ExpandedNode[]`）を、各ノードの `parent_path` および `depth_level` を基に親・子・孫関係の木構造（`TreeChildNode[]`）へ自動変換。
- 階層2以上の孫ノードも直接の親ノードの真下にインデントしてネスト表示。

### 2. 開閉トグル（▼ / ▶）コンポーネント (`AiChildTreeNode`)
- **親ノート行**: 子ノードを持つ場合、ファイル名左側に開閉トグルボタン（▼ / ▶）を配置。ワンクリックで配下の全階層ツリーを折りたたみ・展開。
- **子ノード行**: 孫ノードを持つ場合、トグルボタン（▼ / ▶）を表示。持たない葉ノードは `↳` スペーサーを表示。
- **ガイド線**: 階層ごとに点線ガイド線（パープル系: `borderLeft: 1px dashed rgba(99, 102, 241, 0.35)`）と階層に応じたインデントを適用。
- **イベント分離**: トグルボタンのクリック時は `e.stopPropagation()` を実行し、親・子カードクリック（8001ハブ遷移）の誤発火を物理的に防止。

### 3. 「📂 すべて展開」「📁 すべて折りたたむ」一括操作
- モーダル右ペインの見出し直下に「📂 すべて展開」「📁 すべて折りたたむ」クイック操作ボタンを設置。
- ノート数が大量（数十件）の場合でも、ワンクリックですべてのツリーを一括で閉じて親ノート一覧に集約したり、一括で全階層を展開して全体像を俯瞰可能。

### 4. チェックボックス & 8001ハブ連携の完全互換
- ツリー構造化・折りたたみ機能が有効であっても、各ノードの個別除外チェックボックスおよび8001ハブでの即座の直接閲覧機能はそのまま完全動作。
