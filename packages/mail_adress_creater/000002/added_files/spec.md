# Outlook宛先作成アプリ 仕様書

## 1. 目的

Outlookの送信履歴から抽出した「送信先名 × 送信回数」のデータを利用し、宛先（To）とCCを効率よく作成してOutlookに貼り付けるための補助アプリを提供する。

加えて、Outlookの送信済みアイテムからのアドレス再取得と、職アド通知メールのキーワードチェックをバックエンドで実行できるようにする。

人間が最終確認・取捨選択を行う前提とし、完全自動送信は行わない。

## 2. 構成

### 2.1 フロントエンド

- React 18 + TypeScript
- Vite 6
- Tailwind CSS
- PWA対応
- `dist`にビルドされた静的ファイルをバックエンドが配信する

### 2.2 バックエンド

- Python 3.12（標準ライブラリのみ。Windowsでのみ pywin32）
- 標準ライブラリの`http.server`でAPIと`dist`を配信
- SQLiteでお気に入り、宛先、設定、キーワード一致、ジョブ実行結果を保存（`backend/data/app.sqlite3`）
- Windows + Outlook + pywin32 がある環境でOutlook COM連携を実行

モジュール構成:

| ファイル | 役割 |
| --- | --- |
| `backend/server.py` | HTTPハンドラ、ルーティング表、Origin/Host検証、エラーコード、キャッシュヘッダー、起動 |
| `backend/services.py` | アドレス再取得、キーワードチェック、予定解析・追加、ダミーデータ投入 |
| `backend/db.py` | SQLite（スキーマ作成・移行、設定、お気に入り、宛先、キーワード一致、ジョブ履歴）とCSV入出力 |
| `backend/outlook.py` | Outlook COM接続と復旧、送信済み取得、予定登録、職アド受信メール検索 |
| `backend/scheduler.py` | 自動実行の判定・再試行・多重起動防止 |
| `backend/event_parser.py` | 自然文の予定解析 |
| `backend/config.py` | パス、既定設定、ログ |

## 3. 入力データ仕様

### 3.1 CSVファイル

- ファイル名: `send_mail-ranking_tabulator.csv`
- 元データ配置: `public/send_mail-ranking_tabulator.csv`
- 配信データ配置: `dist/send_mail-ranking_tabulator.csv`
- 読み込み方法: フロントエンドから`fetch('/send_mail-ranking_tabulator.csv')`
- 更新方法: バックエンドの`POST /api/refresh-addresses`
- フロントエンドはCSVをキャッシュせず（`no-store`）取得し、HTTPエラー時は読み込みエラーとして扱う
- フロントエンドは読み込み後、同じ名前の行は回数を合計して1件にまとめ、回数の降順に並べる
- バックエンドはCSVを一時ファイル経由で置き換えるため、書き込みに失敗しても元のCSVは壊れない
- 再読み込み（アドレス再取得・DB削除後）でも、画面の検索語・チェック状態は維持する

### 3.2 CSVフォーマット

| 列名 | 型 | 説明 |
| --- | --- | --- |
| 名前 | string | Outlookに貼り付ける表示名 |
| 回数 | number | 送信回数。表示とソートに使用 |

```csv
名前,回数
山田 太郎,120
佐藤 一郎,200
```

- 名前にカンマを含む場合はダブルクォートで囲むCSV標準形式に対応する
- フロントエンドのCSV読み込みとバックエンドの既存CSVマージでは、回数が整数として読めない行は読み込み対象外にする

## 4. 画面構成

### 4.1 上部メニュー

- ハンバーガーメニュー（設定メニューの開閉）
- 「アドレス再取得」ボタン
- 「職アドキーワードチェック」ボタン
- 「DB表示」ボタン
- 「お気に入り」ボタン
- プロフィールのコピーボタン（メール・電話・住所・部署・家アド）。未設定の項目はコピーせず、設定を促すトーストを出す
- 実行中はボタンを無効化し、ラベルを実行中表示にする
- 実行エラーは画面上部に表示する
- 予定入力欄（自然文入力、「予定解析」「Outlook追加」、解析結果の編集欄）はヘッダーの下にある

### 4.2 ハンバーガーメニュー

以下を設定できる。

- 職アドキーワード（カンマ・読点・改行区切り。先頭に`-`を付けると除外キーワード）
- アドレス再取得の自動実行頻度（分）
- 職アドキーワードチェックの自動実行頻度（分）
- プロフィール（メールアドレス、電話番号、住所、部署、家アド）
- 「設定保存」ボタン
- 「ダミーデータ投入」ボタン。宛先一覧（DBとCSV）を上書きするため、確認ダイアログでOKした場合のみ実行する

既定値:

- キーワード: `棚卸`、`棚おろし`、`ユーザID`
- アドレス再取得: 43200分（約1ヶ月）
- キーワードチェック: 60分（1時間）

### 4.3 2ペイン

- 左ペイン: 宛先（To）
- 右ペイン: CC
- 宛先とCCは完全に独立した検索・チェック状態を持つ
- お気に入りは`★`付きで通常の宛先と同じ検索結果に表示する（宛先ペインにはTo側、CCペインにはCC側の宛先数を表示）
- お気に入りをコピーする場合は、登録された複数宛先へ展開してコピーする（お気に入りの中に別のお気に入り名があれば再帰的に展開し、循環参照は展開しない）
- 画面の右クリックメニュー: 「現在の宛先・CCをお気に入りに追加」「お気に入りを適用...」（宛先・CCペインへ一括反映）。適用中は検索窓の上に`★ お気に入り「名前」適用中`バッジを表示し、「解除」で通常表示に戻る
- 左右矢印キーでペインを切り替える（入力欄・本文エディタの編集中は無効）

## 5. ペイン共通仕様

### 5.1 検索機能

- 入力方式: 複数行テキストエリア
- 区切り文字: 半角スペース、全角スペース、その他空白、カンマ（`,`）、読点（`、`・`､`）
- 検索方式: OR検索
- 検索条件: 部分一致
- 大文字・小文字: 区別しない
- Enterキーで検索実行
- Shift+Enterで検索実行後に結果リストへフォーカス移動
- リスト内: 上下矢印で移動、Enterでコピー、Space / Ctrl+Enter / Shift+Enterでチェック切替

### 5.2 検索結果表示

- チェックボックス
- 名前
- 回数
- 並び順は回数の降順
- 検索を実行するまで一覧は表示しない。検索を実行すると、ヒットした宛先がチェックONになる（それまでのチェックは維持）
- マッチしなかったキーワードを表示する

### 5.3 コピー

- 左ペイン: 「宛先作成」
- 右ペイン: 「CC作成」
- チェックONの名前を`;`で連結してクリップボードにコピーする
- 名前部分をクリックすると、その名前だけをクリップボードにコピーする
- コピー成功時はトーストを表示する
- 右クリックメニューから宛先をお気に入りへ追加できる

### 5.4 フォントサイズ

- 各ペインで個別に8pxから20pxまで調整できる

## 6. バックエンドAPI仕様

### 6.1 アドレス再取得

`POST /api/refresh-addresses`

- Outlookの送信済みアイテムから宛先名を取得する
- 取得上限の既定値は150件
- 宛先名ごとに回数を集計する
- 既存のCSVとDB（`recipients`）の宛先名と、新規集計結果を名前でマージする
- 今回存在しなかった既存アドレスは回数0として残す
- `public/send_mail-ranking_tabulator.csv`と`dist/send_mail-ranking_tabulator.csv`へ保存する
- SQLiteの`recipients`にも保存する

### 6.2 職アドキーワードチェック

`POST /api/check-keywords`

- Outlookの受信トレイを確認する（新しい順に、既定500件）
- 件名に「職アドからのお知らせ」を含むメールを対象にする
- 本文行のうち、登録キーワードを含む行を抽出する（1行に複数のキーワードが含まれる場合は、最初に一致した1件だけを記録する）
- キーワードにマイナス記号 `-` を付与することで除外キーワードを設定でき、該当キーワードが件名または本文の該当行に含まれている場合は判定から除外される
- SQLiteの`keyword_matches`に保存する
- 保存済みレコードは `confirmed=0`（未確認）で保存され、ユーザーが確認するまで画面に表示され続ける
- 初めて保存された一致を`new_matches`として返す
- 新規一致は画面上部で目立つ形で表示する
- 保存済み履歴の取得では既存一致として扱う
- `GET /api/keyword-matches?new_only=1`は互換性のため空配列を返し、新規一致の判定はチェック実行時の`new_matches`で行う
- `GET /api/keyword-matches?unconfirmed=1`で未確認の一致のみを取得できる。アプリ起動時にこのフィルタを使い、未確認通知を復元する
- 画面は未確認の一致をバナーで表示し、「確認」ボタンで`POST /api/keyword-matches/confirm`を呼ぶまで消さない
- `POST /api/keyword-matches/confirm`: IDリスト（JSON: `{"ids": [...]}` ）を受け取り、該当レコードを確認済み（`confirmed=1`）に更新する

### 6.3 設定

- `GET /api/settings`
- `PUT /api/settings`

保存項目:

- `keywords`（文字列の配列。前後の空白と空要素は取り除く）
- `address_interval_minutes`（1以上の整数）
- `keyword_interval_minutes`（1以上の整数）
- `my_email`、`my_phone`、`my_address`、`my_dept`、`my_home_email`（文字列。前後の空白を取り除く）

不正な値は400で拒否する。未知のキーは無視する。

### 6.4 状態確認

`GET /api/health`

- バックエンドの起動状態
- 現在の設定
- ジョブ実行結果
- 自動実行はジョブ単位で多重起動を抑止する
- 自動実行の判定: 前回実行から設定した間隔が経過したら実行する。前回が失敗（`status=error`）だった場合は、間隔が長くても最大60分で再試行する
- 一時的なDBエラーなどで1回の判定が失敗しても、スケジューラは停止せず次回に再判定する

### 6.5 お気に入り

- `GET /api/favorites`
- `PUT /api/favorites`
- `POST /api/favorites/add`

- `PUT /api/favorites`のボディは`{"favorites": [{"name", "addresses", "cc_addresses"}, ...]}`で、全体を置き換える
- `POST /api/favorites/add`のボディは`{"name", "addresses", "cc_addresses"}`で、同名があれば置き換える。宛先とCCがどちらも空の場合は400

保存項目:

- お気に入り名
- 展開先の宛先（To）配列
- 展開先のCC配列
- 更新日時（内容が変わっていないお気に入りは、一括保存しても更新日時を維持する）

### 6.6 DB閲覧・削除

- `GET /api/database`
- `POST /api/database/delete`

対象テーブル:

- `settings`
- `recipients`
- `favorites`
- `keyword_matches`
- `job_runs`

`settings`は削除不可とする。`recipients`を削除した場合は、`public/send_mail-ranking_tabulator.csv`と`dist/send_mail-ranking_tabulator.csv`も同期更新する。

### 6.7 予定解析・Outlook予定追加

- `POST /api/parse-schedule`
- `POST /api/add-schedule`

自然文の予定入力から以下を抽出し、画面で編集できるようにする。

- 件名
- 開始日時
- 終了日時
- 場所
- 終日予定
- 本文（HTML/リッチテキスト対応）

`POST /api/add-schedule`はOutlook COMで予定表アイテムを作成する。日時だけでなく「明日」「今週の水曜日」などの相対表現を解析する。部屋番号など時刻ではない数字は時刻として扱わない。本文にHTMLタグ（`<br>`、`<b>`、`<p>`など、開始・終了タグの形をしたもの）が含まれる場合は、クラシックOutlookの制限（予定表にHTMLBodyプロパティがない問題）を回避するため、一時HTMLファイルを生成し、予定表アイテムの編集エンジン（`WordEditor`）のファイル挿入機能（`InsertFile`）を使って挿入する。これにより、HTMLタグがテキストとして露出することなく、リンクや表構造を再現して保存される。HTMLの取り込みに失敗した場合は、改行を保ったままタグを除いた平文を`Body`に設定する。タグを含まない本文は平文として設定し、`&amp;`などのHTMLエンティティは元の文字へ戻す（画面のエディタは常にHTMLとして値を持つため）。詳細は`docs/html_body_spec.md`。

### 6.8 ダミーデータ

`POST /api/seed-dummy-data`

Outlook COMを使えない検証環境向けに、宛先、キーワード一致、ジョブ履歴のサンプルをSQLiteとCSVへ投入する。**宛先（`recipients`とCSV）はダミーで置き換わり、元に戻せない。**画面は実行前に確認ダイアログを表示する。

### 6.9 APIのアクセス制限とエラーコード

- ブラウザからのAPIリクエストは同一Originのみ許可する。別OriginからのGET/POST/PUT/OPTIONSは403で拒否し、別Originに対する`Access-Control-Allow-Origin`は返さない
- ループバック（`127.0.0.1`など）で待ち受けている間は、Hostヘッダーが`localhost` / `127.0.0.1` / `[::1]`のいずれかでないリクエストを403で拒否する（DNSリバインディング対策）。ループバック以外を指定した場合は検証しない

| ステータス | 条件 |
| --- | --- |
| 400 | 入力不備（不正なJSON、JSONオブジェクトでないボディ、検証エラー、不正なContent-Length） |
| 403 | Origin / Hostの不一致 |
| 404 | 存在しないAPI |
| 413 | リクエストボディが1MBを超える |
| 500 | 上記以外の例外（Outlook接続失敗など。メッセージを画面に表示する） |

レスポンスは`{"error": "メッセージ"}`の形式。

### 6.9.1 キャッシュヘッダー

- `/api/*`: `Cache-Control: no-store`
- `/assets/*`（ファイル名にハッシュが付く）: `public, max-age=31536000, immutable`
- それ以外（`index.html`、`sw.js`、CSV、manifestなど）: `no-cache`（毎回再検証）

### 6.10 Outlook COM連携時のキャッシュ自動パージと復旧

`pywin32` の `EnsureDispatch` は、ディスク上（`%TEMP%/gen_py`）に型情報キャッシュを自動生成しますが、このキャッシュが破損するとエラーが繰り返されます。
この対策として、`EnsureDispatch` が失敗した際に以下の処理を自動実行します：
1. **ディスクキャッシュの削除**: `%TEMP%/gen_py/<Pythonのバージョン>`（例: `3.12`）配下の、Outlook型ライブラリ（`*000000000046*`）のキャッシュフォルダを削除する。
2. **メモリキャッシュの削除**: すでに Python プロセス（`sys.modules`）にインポートされている `win32com` 関連のキャッシュモジュールをパージする。
3. **モジュールの再ロード**: 完全にクリーンな状態で再度 `win32com.client` をインポートし直して `EnsureDispatch` をリトライする。
4. **Dispatchへのフォールバック**: それでも失敗したら `Dispatch` で接続する。これも失敗した場合は、クラシック版Outlookの確認を促すエラーを返す。

これにより、一度エラーが発生しても、バックエンドサーバーを再起動することなく安全に自動復旧します。

## 7. PWA仕様

- `public/manifest.webmanifest`を配信する
- `public/sw.js`をService Workerとして登録する
- アプリ本体はキャッシュする（画面遷移とmanifest等はネットワーク優先、ハッシュ付きの`/assets/*`はキャッシュ優先で、古いものは40件を超えた分から削除する）
- `/api`とCSVはキャッシュしない
- Chrome / Edgeからインストール可能にする

## 8. 対応環境

- 開発環境: macOS / Windows
- 利用環境: Windows推奨
- ブラウザ: Chrome / Edge
- Outlook連携: Windows + デスクトップ版Outlook + pywin32

Macではバックエンド配信とフロントエンド操作は可能だが、Outlook COM連携を使う機能はエラー表示になる。

## 9. 非対応事項

- メールの自動送信
- ユーザー認証・権限管理（同一Origin制限は行う）
- 複数ユーザー同時利用を前提とした権限制御
- Web版Outlook API / Microsoft Graph API連携

## 10. 補足

本アプリは「人間の判断を前提とした補助ツール」であり、確認しやすさと軽快さを優先する。
